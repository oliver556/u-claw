# OpenClaw 能力边界补充决策

日期：2026-08-21

状态：开发中补充决策。

本文件不替代已冻结的四项重构文档，不重排原开发阶段。它只补充一条能力边界红线：U-Claw 是 OpenClaw 的商业桌面壳、配置壳、权限桥、媒体展示和代理层，不重新实现 OpenClaw 已有 Agent 能力链。

## 1. 背景

四项重构已进入开发。开发过程中发现，部分实现可能从“界面重新展示”滑向“自然语言能力自研”。这会破坏“所有聊天统一经过 OpenClaw”的冻结方向，并让图片、视频、电脑操作、MCP、Skill、Plugin、渠道等能力出现第二套执行链。

本补充决策用于约束后续代码收口，不扩大原需求范围。

## 2. 总原则

所有用户自然语言输入只进入 OpenClaw `chat.send`。

U-Claw 不做自然语言意图识别分流，不自行判断是否生图、生视频、操作电脑、打开浏览器、调用 MCP、调用 Skill、调用 Plugin 或触发渠道动作。

图片、视频、电脑、浏览器、MCP、Skill、Plugin、渠道等能力，由 OpenClaw Agent tool chain 决策和执行。

U-Claw 只负责：

- UI 展示。
- 配置写入和读回。
- 商业授权代理。
- 本机权限桥。
- 媒体预览、复制、另存和历史展示。
- OpenClaw 状态、工具轨迹、任务状态、渠道状态读回。
- 明确产品按钮触发的本机动作。

## 3. 能力边界

### 3.1 对话

对话必须走 OpenClaw `chat.send`。

U-Claw 不直接组装大模型 prompt，不绕过 OpenClaw 调商业聊天模型生成最终回复。

商业 `/model-api/v1/chat/completions` 只作为 OpenClaw provider 的上游代理，不作为 U-Claw 前端直连聊天链。

### 3.2 图片

图片生成和图片编辑必须走 OpenClaw `image_generate`。

U-Claw 不判断用户是否要生图，不直接从对话框调用 `/model-api/v1/images/generations` 或 `/model-api/v1/images/edits`。

U-Claw 应补齐：

- `agents.defaults.imageGenerationModel` 配置。
- `/model-api/v1/images/generations` 代理。
- `/model-api/v1/images/edits` 代理。
- managed media 展示。
- 历史图片编辑回放和恢复。

### 3.3 视频

视频生成必须走 OpenClaw `video_generate`。

U-Claw 不判断用户是否要生视频，不从对话框直接调用 `/model-api/v1/videos`。

U-Claw 应补齐：

- `agents.defaults.videoGenerationModel` 配置。
- `/model-api/v1/videos` 创建、查询、内容读取代理。
- OpenClaw background task 状态展示。
- 视频媒体展示和历史恢复。

### 3.4 电脑、浏览器和本机操作

电脑操作、浏览器操作、命令执行、Node 能力必须走 OpenClaw `computer`、`browser`、`exec`、`node` 等工具链。

U-Claw 不用正则或前端逻辑识别“打开/启动/运行某应用”并直接执行。

已存在的 `local-actions` 自然语言分流应收口：

- 从默认 `chat.send` 链路移除。
- 如需保留，只能作为明确产品按钮动作。
- 结果不应伪装为 OpenClaw Agent 自然语言执行结果。

### 3.5 MCP

MCP 可保留配置 UI、风险确认、连接测试和状态展示。

Agent 实际可用工具必须以 OpenClaw `tools.effective` 为准。

U-Claw 不实现第二套 MCP 工具执行链，不让自然语言输入绕过 OpenClaw 直接调用 MCP server。

### 3.6 Skill 和 Plugin

Skill 和 Plugin 可保留安装、启停、更新、卸载、状态页和包校验。

运行时权威必须是 OpenClaw：

- Skill 状态以 `skills.status` 为准。
- Plugin 生命周期以 OpenClaw CLI 或 OpenClaw Gateway runtime 为准。
- Plugin/Skill 产生的工具能力以 OpenClaw `tools.catalog` 和 `tools.effective` 为准。

U-Claw 不新增 Skill/Plugin 能力执行链。

### 3.7 渠道

渠道配置、二维码、连接状态、凭据脱敏和诊断 UI 可以由 U-Claw 承担。

消息收发、session 映射、工具调用、Agent 回复必须回到 OpenClaw channel/runtime。

U-Claw 不为微信、QQ、Telegram、Discord 等渠道另写一套“消息进来后自行决策和回复”的链路。

### 3.8 语音、TTS、Talk 和通知

语音、TTS、Talk、voice wake 应走 OpenClaw `talk.*`、`tts.*`、`voicewake.*` 能力。

U-Claw 可承担麦克风、通知、音频播放、本机权限请求和播放桥接。

U-Claw 不自行实现独立语音 Agent。

## 4. 允许的 U-Claw 自写层

以下属于 U-Claw 职责，不视为越界：

- 商业授权、设备令牌、服务端 New API key 隔离。
- `/model-api/v1/*` 代理。
- OpenClaw 配置写入和读回。
- Electron 安全 IPC、权限桥和文件选择。
- 图片、视频、附件、历史消息和工具轨迹展示。
- 明确按钮动作，例如打开日志目录、打开配置目录、复制图片、另存图片。
- 启动器、更新器、Gateway 生命周期、诊断和商业打包。

判断标准：如果动作来自自然语言输入，应进 OpenClaw `chat.send`；如果动作来自明确 UI 控件，可由 U-Claw 处理。

## 5. 已识别收口项

### 5.1 `local-actions`

当前风险：普通聊天输入可被 U-Claw 正则识别并直接 `openPath`。

处理：

- 移除对默认聊天链的自然语言拦截。
- 保留时仅作为显式 UI 按钮动作。
- 增加验收：输入“打开计算器”必须观察到 OpenClaw `chat.send`，不能出现 `local_` runId 或 U-Claw 直接生成最终回复。

### 5.2 MCP 管理层

当前风险：配置、probe、start/stop 逻辑较深，容易演进为第二套 MCP runtime。

处理：

- 保留配置和状态管理。
- 自然语言触发 MCP 工具时，只认 OpenClaw `tools.effective` 和 tool event。
- 增加验收：U-Claw 不能直接把用户自然语言转换为 MCP 调用。

### 5.3 Skill、Plugin、渠道

当前风险：管理壳继续扩展时可能产生自研执行链。

处理：

- 保留安装、启停、状态、二维码、连接管理。
- 执行权威统一回 OpenClaw。
- 新增代码时必须说明它属于“管理壳”还是“执行链”。执行链默认不允许。

## 6. 验收规则

以下场景必须通过 OpenClaw 链路观测：

1. 普通文本对话：观察到 OpenClaw `chat.send`。
2. “生成一张图片”：观察到 `chat.send`、`image_generate` tool event、`/model-api/v1/images/generations`。
3. “修改上一张图片”：观察到 `chat.send`、`image_generate` edit、`/model-api/v1/images/edits`。
4. “生成一段视频”：观察到 `chat.send`、`video_generate` tool event、`/model-api/v1/videos`。
5. “打开浏览器 / 操作电脑”：观察到 OpenClaw computer/browser/exec/node 工具链，而非 U-Claw 自然语言正则执行。
6. MCP 工具调用：观察到 OpenClaw `tools.effective` 包含该工具，并产生 OpenClaw tool event。
7. 渠道消息：消息进入 OpenClaw session，回复和工具调用由 OpenClaw runtime 产生。

失败判定：

- U-Claw 前端或桌面层从自然语言直接判断能力类型。
- U-Claw 绕过 OpenClaw 直接调用图片、视频、电脑、浏览器、MCP、Skill、Plugin、渠道执行接口。
- U-Claw 自己生成最终 assistant 回复并伪装为 OpenClaw Agent 结果。

## 7. 执行方式

本补充决策作为原四项重构总纲的执行约束。

开发顺序不另开大线，插回原总纲当前批次执行：

1. 先收口 `local-actions` 自然语言分流。
2. 再补图片和视频的 OpenClaw 默认模型配置、代理和展示验收。
3. 再补电脑、浏览器、MCP、Skill、Plugin、渠道的边界测试。
4. 最后检查自然语言入口是否只剩 OpenClaw `chat.send`。

代码收口完成前，不新增任何自然语言意图分流能力。
