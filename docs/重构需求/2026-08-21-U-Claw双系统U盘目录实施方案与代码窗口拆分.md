```text
U-Claw/
├─ U-Claw.exe
├─ U-Claw.app/
├─ app/
│  ├─ usb-manifest.json
│  ├─ current/
│  │  ├─ win-x64.json
│  │  └─ macos-arm64.json
│  ├─ install-state/
│  │  ├─ win-x64.json
│  │  └─ macos-arm64.json
│  ├─ manifests/
│  │  ├─ win-x64.version.json
│  │  └─ macos-arm64.version.json
│  └─ packages/
│     ├─ win-x64/

│     └─ macos-arm64/
```

`support/` 可在制盘目录中预留，但不是首批代码门禁前置。

## 3. 平台独立与共享规则

平台独立：

- `app/packages/win-x64/runtime.pkg`
- `app/packages/macos-arm64/runtime.pkg`
- `app/manifests/win-x64.version.json`
- `app/manifests/macos-arm64.version.json`
- `app/current/win-x64.json`
- `app/current/macos-arm64.json`
- `app/install-state/win-x64.json`
- `app/install-state/macos-arm64.json`
- 宿主机 runtime cache：`%LOCALAPPDATA%/U-Claw/runtimes/win-x64/...`、`~/Library/Application Support/U-Claw/runtimes/macos-arm64/...`

平台共享：

- `data/`
- `data/.openclaw/`
- `data/outputs/`
- `data/logs/`
- `.uclaw/license/license.json`
- `.uclaw/license/.startup-credential.json`
- `.uclaw/license/.lifecycle-cache.json`

读写规则：

- Launcher 只按当前 OS target 读写本平台 package、manifest、current、install-state。
- 任一平台更新失败，不能覆盖另一平台 manifest、runtime.pkg、current、install-state。
- `data/` 是业务数据权威位置。Electron、Gateway、Adapter、OpenClaw 必须从启动 env 读取数据根，不能自行落到系统 home。
- 宿主机 cache 只存可重建 runtime/cache，不存完整会话、附件原件、用户产出、New API key、Provider key、长期明文令牌。
- `app/current/<target>.json` 只表示当前平台已完成安装的版本身份。它不是业务 rollback 指针。
- `app/install-state/<target>.json` 只记录事务中状态。事务完成后可留审计状态，但不能作为启动旧业务入口。

首版必须注入：

```text
UCLAW_USB_ROOT=<usb-root>
UCLAW_DATA_DIR=<usb-root>/data
UCLAW_OPENCLAW_HOME=<usb-root>/data/.openclaw
OPENCLAW_HOME=<usb-root>/data
OPENCLAW_STATE_DIR=<usb-root>/data/.openclaw
```

兼容策略：

- Windows 现有 `.uclaw/data` 先保留只读兼容探测。
- 若新 `data/` 不存在且旧 `.uclaw/data` 存在，首版做一次性迁移或显式阻断并提示迁移；不能静默分叉两份业务数据。
- 新写入一律进入根 `data/`。

## 4. USB Identity 与 License 跨系统映射

现状：

- Windows 生产实现使用 `DeviceIoControl` 读取 USB descriptor，失败后用 vendor/product/revision/serial/capacity fallback。
- 非 Windows 当前返回 `ErrLicenseUSBIdentityUnavailable`。

实施要求：

- 新增 macOS USB identity 采集，至少覆盖 removable/external disk、serial、vendor、product、capacity、volume UUID 的证据采集。
- macOS 采集不得把 Volume Name、挂载路径或盘符等易变字段作为唯一身份。
- `license.json` 仍绑定物理 U 盘，不绑定 OS 入口。
- `.startup-credential.json`、`license.json`、`.lifecycle-cache.json` 由两平台共享。
- 若 Windows 与 macOS 原始 descriptor 无法稳定同源，服务端必须引入版本化映射，例如 `fingerprint_version=2` 和 `device_aliases[]`，把同一物理 U 盘的 Windows 指纹与 macOS 指纹映射为同一授权设备。
- 客户端只能提交本平台 fingerprint 和证明材料；是否同盘由服务端判定。

最低验收：

- Windows 激活后，macOS 首启识别为同一授权设备。
- macOS 激活后，Windows 首启识别为同一授权设备。
- 换 USB 口、换盘符、换挂载点不改变授权结果。
- 换 U 盘必须被拒绝。

## 5. macOS `.app` 风险

macOS 首版不能只是把 runtime 包放进目录。还要解决：

- `U-Claw.app` bundle 结构、Info.plist、icon、bundle id、版本号。
- Developer ID signing。
- notarization。
- staple。
- 外置 U 盘启动下 Gatekeeper 验收。
- quarantine attribute 场景。
- arm64 Electron runtime entrypoint 与 manifest critical files。
- `macos-arm64` runtime.pkg 的 tar path 安全规则，不能继续只用 Windows path validator。
- macOS host cache 路径、文件锁、进程管理、USB disconnect 监控。

Gatekeeper 风险：

- 未签名或未 notarize 的 `.app` 在用户机器上会阻断。
- 从网页下载再拷贝到 U 盘可能带 quarantine，需实测首次打开。
- 外置盘文件系统 exFAT 对权限、xattr、symlink、case 行为与 APFS 不同，需单独矩阵。

## 6. 最小 schema 扩展点

### 6.1 `runtime-versions.json`

当前是单对象：

```json
{
  "runtimeId": "openclaw-2026.7.1-2-win-x64",
  "targetPlatform": "win32",
  "targetArch": "x64"
}
```

最小扩展建议：

```json
{
  "node": "24.15.0",
  "npm": "11.12.1",
  "electron": "40.10.6",
  "openclaw": "2026.7.1-2",
  "openclawNpmIntegrity": "...",
  "targets": {
    "win-x64": {
      "targetPlatform": "win32",
      "targetArch": "x64",
      "runtimeId": "openclaw-2026.7.1-2-win-x64",
      "entrypoint": "electron/electron.exe"
    },
    "macos-arm64": {
      "targetPlatform": "darwin",
      "targetArch": "arm64",
      "runtimeId": "openclaw-2026.7.1-2-macos-arm64",
      "entrypoint": "Electron.app/Contents/MacOS/Electron"
    }
  }
}
```

兼容要求：第一步保留旧字段或提供 adapter，保证 `win-x64` 测试不需要一次性全改。

### 6.2 runtime manifest schema

最小扩展：

- `targetPlatform`: enum `["win32", "darwin"]`
- `targetArch`: enum `["x64", "arm64"]`
- 新增 `target`: enum `["win-x64", "macos-arm64"]`，或由 platform/arch 推导。建议显式 `target`。
- `runtimeArchive` 首版允许 `runtime.pkg`，在平台目录内解析；不要签绝对路径。
- path validator 按 target 分流：Windows 禁止保留名/ADS；macOS 禁止 NUL、绝对路径、`..`、空段、Unicode/case 冲突和 unsafe symlink。
- signing payload 增加 `target` 时必须 bump payload domain，例如 `uclaw-runtime-manifest-v3`。

兼容要求：`win-x64` v2 manifest 继续可读，直到 Windows 双系统制盘完成后再切 v3。

### 6.3 release schema

当前 release compatibility 只接受 `platform: "win32"`、`arch: "x64"`。

最小扩展：

- `compatibility.target`
- `compatibility.platform`: `win32 | darwin`
- `compatibility.arch`: `x64 | arm64`
- `compatibility.runtimeId`
- release policy 指向当前 target 的 manifest URL 或一个 target map。

建议第一阶段不改生产 release policy。先加离线 contract 和 parser，再接 CDN。

### 6.4 `usb-manifest.json`

建议字段：

```json
{
  "schemaVersion": 1,
  "product": "U-Claw",
  "usbLayoutVersion": 1,
  "minimumBootstrapVersion": "0.1.0",
  "dataRoot": "data",
  "licenseRoot": ".uclaw/license",
  "targets": {
    "win-x64": {
      "entry": "U-Claw.exe",
      "package": "app/packages/win-x64/runtime.pkg",
      "manifest": "app/manifests/win-x64.version.json",
      "current": "app/current/win-x64.json",
      "installState": "app/install-state/win-x64.json"
    },
    "macos-arm64": {
      "entry": "U-Claw.app",
      "package": "app/packages/macos-arm64/runtime.pkg",
      "manifest": "app/manifests/macos-arm64.version.json",
      "current": "app/current/macos-arm64.json",
      "installState": "app/install-state/macos-arm64.json"
    }
  },
  "signature": { "algorithm": "ed25519", "keyId": "...", "value": "..." }
}
```

`usb-manifest.json` 不得成为未签名路径入口。Launcher 必须先验证签名，再使用其中相对路径。

## 7. Windows 兼容策略

原则：

- 不重建、不替换、不重新解释 Win PASS artifact `9443717301`。
- 不改 `final-windows-runtime.mjs` 和 `product.yml`。
- 双系统实施先用 fixture 和 contract 证明目录扩展，再由单独解冻窗口迁移真实 packaging。
- `win-x64` target 的 runtime manifest、treeSha256、fileCount、unpackedBytes 和 PE/app.asar 规则保持不变。

迁移方式：

1. 新增路径解析层，兼容旧 `.uclaw/runtime.pkg` 与新 `app/packages/win-x64/runtime.pkg`。
2. 新制盘只写新结构。
3. 旧结构只作为旧盘读取兼容，不作为双系统发行输出。
4. Windows physical gate 增加新结构 smoke 后，旧结构 gate 仍保留到正式切换完成。

## 8. 推荐实施顺序

1. `docs/contracts` 窗口：冻结双系统 layout、usb manifest、target manifest 合同和验收矩阵。只改 docs/test fixtures。
2. `schema` 窗口：扩展 runtime manifest validator、release schema、runtime versions adapter。先保持 `win-x64` 旧输入通过。
3. `launcher-paths` 窗口：新增 target-aware path resolver，把 package/data/license 分离；Windows 先支持新结构和旧结构兼容。
4. `packaging-layout` 窗口：新增双系统制盘 builder，用已有 Win runtime.pkg 作为输入，生成新目录；不碰 final Windows runtime 构建。
5. `macos-identity-launcher` 窗口：实现 macOS USB identity、host cache、env、process、disconnect monitor。
6. `macos-runtime-packaging` 窗口：构建 macos-arm64 runtime.pkg、manifest、`.app` launcher。
7. `macos-sign-notarize` 窗口：Developer ID signing、notarization、staple、Gatekeeper 真机门禁。
8. `cross-os-e2e` 窗口：同盘双系统 License 和 data 连续性门禁。
9. `release-cdn` 窗口：CDN readback、pointer switch、release policy target map。
10. `production-release` 窗口：审批后执行正式发布。

商业新链 E2E 应优先或并行独立推进；双系统窗口不得吞并商业 E2E。

## 11. 最低总验收

- Windows 双击 `U-Claw.exe`：未激活、激活、重启 gate、进入工作台 PASS。
- macOS 打开 `U-Claw.app`：同等流程 PASS。
- Windows -> macOS 授权连续 PASS。
- macOS -> Windows 授权连续 PASS。
- Windows 写会话、附件、产出，macOS 读回 PASS；反向 PASS。
- 换盘符、换挂载点、换 USB 口、换电脑，业务数据仍以 U 盘 `data/` 为权威。
- 删除宿主机 runtime 后可从 U 盘重新安装，不丢业务数据。
- 更新 `win-x64` 不覆盖 `macos-arm64` package/manifest/current/install-state。
- 更新 `macos-arm64` 不覆盖 `win-x64` package/manifest/current/install-state。
- 全包 secret scan PASS。
- Windows artifact `9443717301` 兼容证据未失效。

## 12. 主要风险

- path 迁移风险：`.uclaw/data` 到根 `data/` 若静默分叉，会丢会话连续性。
- signing payload 风险：改 manifest 字段不 bump domain，会造成跨语言验签歧义。
- platform path 风险：继续用 Windows path validator 处理 macOS runtime，会误杀合法路径或漏掉 macOS 风险。
- release policy 风险：单 manifest URL 无 target 概念，可能让 macOS 拉到 Windows runtime。
- license identity 风险：Windows/macOS descriptor 不同源，必须服务端映射。
- Gatekeeper 风险：`.app` 未 notarize 或 quarantine 未处理，用户机器无法打开。
- exFAT 风险：权限、xattr、case、Unicode normalization 与 APFS/NTFS 不同。
- artifact 风险：新 packaging 若顺手重建 Windows runtime，会破坏已 PASS artifact 冻结线。
