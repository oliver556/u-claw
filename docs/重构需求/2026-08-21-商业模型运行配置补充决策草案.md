## 3. 补充决策草案

### 3.1 New API key 边界

New API key 只属于服务端运行环境，不进入 U 盘，不进入桌面端配置，不进入 OpenClaw 配置，不进入日志。

U 盘侧只保存：

- `endpoint`
- `deviceToken`
- `deviceTokenId`
- 默认模型

服务端 key 替换后，通常不需要重新写 U 盘 key。只有默认模型、endpoint 或 deviceToken 轮换时，才需要更新 U 盘 credential。

### 3.2 默认模型

商业默认文本模型建议冻结为：

```text
gpt-5.5
```

原因：

- 已通过真实 chat 测试。
- 返回标准 `message.content`。
- 当前更适合作为客户默认模型。
- 避免 `gpt-5.6-sol` 在服务端 `/models` 不可见或未开放时导致默认模型不可用。

待确认项：

- U 盘 `builtin-model-credential.v1.json` 中默认 `model` 是否已最终写成 `gpt-5.5`。
- OpenClaw 配置中默认 `primary` 是否已最终指向 `uclaw-commercial/gpt-5.5` 或等价模型。

### 3.3 模型目录来源

客户端、U 盘黑盒测试、OpenClaw 动态模型选择不应写死商业模型清单。

运行时应以服务端返回为准：

```http
GET /model-api/v1/models
```

黑盒验收流程建议：

1. 先请求 `/model-api/v1/models`。
2. 按返回列表选择可测模型。
3. 文本模型走 `/model-api/v1/chat/completions`。
4. 图片模型走 `/model-api/v1/images/generations` 或 `/model-api/v1/images/edits`。
5. 若某模型不在 `/models` 返回中，客户端不应默认选择它。

### 3.4 `allowed_models` 策略

短期不建议直接注释或删除服务端 `allowed_models` 白名单。

短期策略：

- 继续保留服务端模型限制。
- 通过服务端配置或绑定数据，只开放计划给客户使用的模型。
- 即使 New API key 具备更大权限，U-Claw 服务端也只向客户暴露明确允许的模型。

中期可评估：

- 服务端模型目录跟随 New API `/models`。
- 但服务端仍保存一层“当前可见模型快照 / 允许集合”。
- 不建议无边界透传 New API key 能访问的全部模型。

不推荐：

- 完全取消模型限制。
- 使用 `all` 分组 key 后把所有上游模型直接暴露给客户。

风险：

- 成本不可控。
- 未验收模型可能格式不稳定。
- reasoning / thinking / image / video 等不同能力模型可能需要不同适配。

### 3.5 New API 分组关系

New API 的分组不应依赖客户端 header 切换。实际分组由 New API 后台的用户、令牌、渠道、可用分组规则决定。

U-Claw 服务端只使用：

```http
Authorization: Bearer <server-side-new-api-key>
```

不应设计成由 U-Claw 客户端或 U 盘传入 New API 分组。

推荐配置原则：

- `yiyong` 作为客户资源组。
- 上游来源用渠道名称、渠道标签、模型描述区分。
- 不把“阿里官方对接”“pro20x2”等上游来源当成客户访问父子分组。

## 4. 对四份文档的影响建议

### 4.1 模型目录与商业 API 凭据链路简化重构需求

建议后续正式并入。

应补充：

- New API key server-only。
- U 盘不保存 New API key。
- U 盘只保存 `endpoint/deviceToken/deviceTokenId/default model`。
- 模型目录以 `/model-api/v1/models` 为准。
- 默认文本模型为 `gpt-5.5`。
- `allowed_models` 短期保留，中期可演进为跟随 New API `/models` 的服务端快照/过滤机制。

### 4.2 OpenClaw 唯一聊天链与会话生命周期评估 v3

建议后续正式并入。

应补充：

- OpenClaw 商业默认模型使用 `gpt-5.5`。
- OpenClaw 动态模型列表来自服务端 `/models`。
- `gpt-image-2` 走图片链，不走 chat。
- DeepSeek 类模型可能触发 OpenClaw 顶层 `thinking`，需要配置兼容格式，避免 activation-server 严格 schema 返回 400。

### 4.3 U-Claw 启动打包与 Gateway 链路第三版重构需求

建议轻补。

应补充：

- 启动、预热、诊断不写死商业模型清单。
- 默认模型缺失时，应降级到服务端返回的可用文本模型，优先 `gpt-5.5`。
- 诊断报告输出模型 ID、HTTP 状态、能力类型，不输出 key、deviceToken、Bearer、b64。

### 4.4 启动强制更新与服务端单次回滚需求

可不改，或只加运维备注。

可选补充：

- 服务端 key 替换属于运行配置变更，不等同于版本发布。
- key 替换后需要重启双实例并验证 `/health/ready`、`/model-api/v1/models`、最小 chat/image 黑盒。
- 若 key 替换导致模型不可见，应优先回滚 key/config，不必回滚客户端版本。
