## 1. 调度权威来源

分发窗口按以下优先级读取文档：

1. [《第四阶段联调验收矩阵》](./第四阶段联调验收矩阵.md)：功能范围、权威后端和状态的唯一来源。
2. [《第四阶段任务对齐表》](./第四阶段任务对齐表.md)：阶段依赖和 Task 完成度的唯一来源。
3. [《第四阶段真实后端接线实施计划》](./superpowers/plans/2026-08-11-第四阶段真实后端接线实施计划.md)：目标文件、实现顺序和验证命令。
4. [《第四阶段后端能力全量审计》](./第四阶段后端能力全量审计.md)：原项目能力、现状和缺口证据。
5. 本文：窗口编号、滚动顺序、文件所有权、冲突组和集成规则。

发生冲突时，功能范围服从联调矩阵，调度方式服从本文。子窗口不得自行增加、删除或重新编号功能。

## 2. 固定编排参数

```text
主任务简称：Bavi-box P4
主窗口标题：Bavi-box P4 · 调度
最大活动窗口：3
开发窗口：最多 2
集成窗口：固定复用 90，占用 1 个槽位
单窗口 subagent：最多 3
执行模式：code + 原生 worktree
集成方式：本地临时 integration branch
push / PR：禁止，除非用户后续明确授权
```

- 完整清单预编号，但只创建依赖满足的窗口。
- `90` 窗口从第一批开始复用，不创建第二个集成窗口。
- 返工回到原编号、原窗口，不创建重复窗口。
- `completed` 只表示开发窗口完成；经交付验真并进入 `90` 后才算 `locally-integrated`。
- 主调度窗口不修改已分发的产品代码，不直接解决跨窗口冲突。
- 调度恢复后先读取登记表和现有窗口，不因断线重新创建任务。
- 模型和推理强度在创建窗口前读取当前账号能力；无法确认时继承用户当前配置，不猜模型名，不传 `fast`。

- 根工作区未提交中文 docs、`.playwright-cli/`、`.superpowers/`、`output/` 和 `outputs/` 不得 reset、stash、clean、覆盖或纳入提交。

## 6. 各窗口必须完成的开发点

### `01` 审计冻结与迁移决策

- 验证 99 个用户功能、4 个内部项、31 个 OpenClaw 核心域。
- 确认每项都有唯一窗口归属，不存在重复或缺号。
- 确认 `AUD-001`–`AUD-004` 为内部使用或不迁移，不计用户功能缺口。
- 更新 `P4-T00` 为已完成，第四阶段完成度变为 `1/9`。
- 只改第四阶段文档，不改产品代码。

### `02` Electron/OpenClaw 生产装配

- 实现仓内正式 `createDesktopMainOptions()`。
- 装配 Gateway process、端口、WebSocket v4、鉴权、能力协商、`OpenClawClient`、附件和领域服务。
- 正式 Electron 禁止回退 `MockUClawClient`；浏览器预览必须明确标识开发模式。
- 未配置、Gateway 失败、鉴权失败和协议错误分别展示可诊断状态。
- 为后续领域建立独立 Adapter/IPC/Service 注册点，减少公共文件并发修改。

### `03` 会话、消息、工具与上下文

- 会话列表、创建、切换、重命名、删除、历史分页和刷新恢复。
- 会话搜索、固定、分组和 U 盘元数据读回。
- 发送、流式、停止、附件、工具轨迹和单次审批。
- 上下文附件、引用、记忆、工具结果展示。
- `sessions.files.*` 与 reset/compact/branch/restore/steer 高级操作。

### `04` 工作区文件与 Markdown 记忆

- 工作区文件列表、搜索、读取、打开和显示位置。
- 重命名、移动、删除后从 U 盘权威目录读回。
- `MEMORY.md`、`memory/*.md` 列表、搜索、读取、编辑和删除。
- 刷新 renderer、重启 Electron 后文件和记忆仍一致。

### `05` Provider、Key、配置与本地模型

- Provider 增删改、启停、排序和凭据轮换。
- Provider Store 与 OpenClaw `config.get/schema/patch/apply` 一致。
- OpenAI-compatible、国产 Provider 和本地模型使用同一有效配置。
- Ollama/LM Studio 发现与真实连通测试。
- Proxy/`NO_PROXY` 同时作用于探测、Gateway 和 executor。
- API Key 不进入 renderer 持久状态、日志、导出或测试快照。

### `06` 三类模型路由、用量与成本

- `builtin/domestic/custom` 三类路由真实执行。
- 外部 Provider 失败不得静默回退 builtin。
- 会话选模写后通过 OpenClaw 读回。
- 接入 OpenClaw Usage/Cost/Session Usage 与 New API 额度时序。

### `07` Skill、SkillHub 与 curator

- 扫描原 `portable/skills-cn` 和 U 盘已安装 Skill。
- 接入 `skills.status`，展示 OpenClaw 实际可用状态。
- SkillHub.cn 免费 Skill 搜索、分类、详情、安装、更新和卸载。
- 启停、依赖、冲突后由 OpenClaw 读回。
- 接入 Skill curator/proposals 高级能力。

### `08` Plugin、MCP、工具与审批

- Plugin 列表、安装、更新、卸载、启停和 runtime 状态。
- Plugin UI descriptors 与 session actions。
- MCP 配置增删改启停、工具投影和实时 probe 分开展示。
- 工具 catalog/effective 管理视图。
- Exec/Plugin 审批策略、风险提示和实际权限一致。

### `09` 主流渠道与统一状态

- Telegram、QQ Bot、飞书、企业微信和 Discord 配置、启停、测试、重连、登出与收发。
- 凭据只进受控存储，UI 和日志只显示脱敏状态。
- 统一渠道健康、凭据和待操作状态来自各 runtime。
- 接入 `channels.status/logout/send/action/poll`。

### `10` 个人微信扫码与生命周期

- 复用已有微信 HTTP/Plugin 可执行流程。
- 扫码、刷新、超时、取消、登录、失效、重连和登出。
- 二维码与会话 Token 不写 `.env`、日志或 renderer 持久状态。
- macOS 可验证协议和错误；Windows 微信客户端场景转入 `P3-T08`。

### `11` Agent 与 Cron

- Agent 列表、身份、创建、编辑、删除。
- Agent 文件和 workspace 列表、读取、写入。
- Cron 列表、状态、详情、新增、更新、删除、立即运行和历史。
- 所有状态直接来自 `agents.*`、`agent.identity.*` 和 `cron.*`。

### `12` Task 活动中心与 Artifact

- 活动中心直接使用 `tasks.list/get/cancel` 和 `task` 事件。
- Artifact 使用 `artifacts.list/get/download`。
- 成果打开、下载和来源会话回溯。
- 禁止继续从 chat/session 派生权威 Task 或 Artifact 列表。

### `13` 日志、诊断、维护、配置与更新

- OpenClaw/Desktop/Launcher 真实日志，筛选、导出和清理。
- health、system info、stability、audit、Doctor 和受控修复。
- 备份、恢复、保留、回滚、空间统计、清理和恢复出厂。
- 原始配置脱敏读取与导出。
- 正式 release feed、签名验证、切换、回滚和本机缓存清理。

### `14` 设备、Node、Environment、Worktree 与 Terminal

- 设备配对列表、批准、拒绝、移除、Token 轮换和撤销。
- Node 列表、详情、重命名、配对、移除、受控 invoke 和事件。

### `15` Talk、TTS、Voice Wake 与 Push

- Talk session/client 生命周期。
- TTS 状态、Provider、Persona 和说话。

### `16` 授权、USB、制盘与 New API

- 建立并维护唯一 `codex/integration-phase4` 本地候选分支。

## 8. 子窗口统一验收要求

每个开发窗口必须：

1. 读取自身矩阵 ID 的每一行，不得只完成代表性主链。
2. 先完成代码和测试用例，再集中运行受影响包 typecheck、定向测试和一条真实 smoke。
3. 成功证据必须到达真实 OpenClaw、U 盘权威文件或正式领域服务。
4. 写操作必须销毁 UI 内存状态后重新读回。
5. Mock、fixture、typed contract、Store 和 localhost 假服务不能单独作为完成证据。
6. 缺外部账号、Windows、物理 U 盘或正式远程服务时，完成本地接线并标记 `待外部环境`。
7. 只收口 Critical/Important；Minor 写入风险，不阻断提交。
8. 提交后保持 worktree clean，并按固定报告格式交给主窗口。
