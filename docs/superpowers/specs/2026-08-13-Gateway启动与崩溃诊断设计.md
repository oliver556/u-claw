# Gateway 启动与崩溃诊断设计

## 目标

为 U-Claw 托管的 OpenClaw Gateway 建立完整诊断闭环。下一次启动失败或运行中退出时，日志必须回答：哪个进程、哪个端口、处于哪个启动阶段、退出码与信号是什么、是否由 U-Claw 主动停止、运行了多久、退出前 stderr 报了什么。

本设计只增加可观测性，不引入自动重启，不放宽 readiness 条件，不改变 Gateway 业务行为。

## 已确认问题

当前 Gateway 以 `stdio: "ignore"` 启动，stdout 和 stderr 被永久丢弃。现有日志只记录 `gateway-started` 和 `gateway-stopped`，没有退出码、signal、端口、PID、停止原因和错误输出。

现有 `gateway-started` 在子进程 spawn 后立即记录，早于 HTTP 健康检查和 RPC 能力检查，因此不能代表 Gateway 真正可用。主动关闭和异常退出也使用同一个 `gateway-stopped` 事件，历史数据无法判断是否发生崩溃。

## 事件模型

新增结构化 Gateway 生命周期事件：

- `gateway-spawned`：子进程获得 PID。
- `gateway-health-ready`：HTTP 健康检查通过。
- `gateway-capability-ready`：RPC 能力检查通过，Gateway 可服务。
- `gateway-startup-failed`：readiness 前失败或超时。
- `gateway-stop-requested`：U-Claw 主动请求停止，记录原因。
- `gateway-exited`：子进程退出，记录退出分类和证据。

`gateway-started` 仅在完整 readiness 通过后记录，保留该事件用于兼容现有诊断消费者。

每条 Gateway 事件包含：

```text
timestamp, event, pid, instanceId, port, phase,
exitCode, signal, stopRequested, stopReason,
startedAt, uptimeMs, stderrTail
```

可选字段仅在有值时写入。`gateway-exited` 的分类规则：

- `requested-stop`：U-Claw 已调用停止。
- `startup-failure`：readiness 完成前退出。
- `unexpected-exit`：readiness 完成后、未请求停止时退出。

## 输出捕获

Gateway 子进程改用 `stdout: ignore, stderr: pipe`。诊断根因主要来自 stderr，不保存 stdout，避免高频协议输出制造日志压力。

stderr 使用有界内存环形尾缓冲：

- 最多保留最后 64 KiB。
- 按 UTF-8 文本处理。
- 每行写入前执行敏感信息脱敏。
- 不实时把完整 stderr 重复写入 JSONL，只在失败或退出事件附带尾部。

脱敏至少覆盖：Bearer token、常见 API key 赋值、Gateway `--token` 参数、Authorization header。无法可靠识别的超长行截断。

## 日志存储

日志写入现有诊断目录下的独立文件：

```text
<dataRoot>/diagnostics/desktop-logs/uclaw-gateway.jsonl
```

采用有界轮转：当前文件达到 2 MiB 时轮转为 `.1`，仅保留当前文件和一个历史文件。日志写入失败不得阻断启动或关闭流程。

## 生命周期归属

`GatewayProcessManager` 负责进程事实：PID、instanceId、spawn 时间、stderr 尾部、exit/close、exitCode、signal、是否收到 stop 请求。

启动协调层负责业务阶段：选端口、HTTP health、RPC capability、window ready。它通过显式方法把阶段和端口回写进程管理器，不能从日志文本反推状态。

主动停止必须携带原因：

- `application-quit`
- `startup-rollback`
- `consistency-restart`
- `manual-restart`

未提供原因时使用 `unspecified`，但不能把它归类为异常崩溃。

## 启动失败与空壳

诊断改造不改变现有原子启动约束：Gateway readiness 未通过时不创建主窗口。若启动失败，清理 Gateway 后报告启动错误并退出 Electron。

运行中 Gateway 意外退出时，本阶段只记录 `unexpected-exit`。不自动重启，避免隐藏根因。空壳体验优化在取得真实失败样本后另行设计。

## 测试

单元测试覆盖：

- spawn 后只产生 `gateway-spawned`，不产生真成功事件。
- readiness 通过后产生 `gateway-health-ready`、`gateway-capability-ready` 和兼容事件 `gateway-started`。
- readiness 前退出被标为 `startup-failure`。
- readiness 后未请求停止退出被标为 `unexpected-exit`。
- 主动停止记录原因并标为 `requested-stop`。
- stderr 尾部有界、UTF-8 可读、敏感信息已脱敏。
- exit 和 close 双事件只生成一次最终退出记录。
- 日志达到阈值后轮转，写入失败不影响 Gateway 生命周期。

集成验证使用可控子进程分别模拟：正常 ready、启动即退出、ready 后退出、主动停止。验收时真实启动 U-Claw，确认 `uclaw-gateway.jsonl` 中存在完整阶段事件且 `/health` 返回 200。

## 非目标

- Gateway 自动重启。
- 修改 OpenClaw 本身。
- 修改模型、API key 或聊天协议。
- 在没有真实诊断证据前推测并修复 Gateway 崩溃根因。
