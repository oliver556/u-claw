# P2-T14 更新文件系统 TOCTOU 加固设计

## 范围

本设计只闭合第二阶段 P2-T14 的两个剩余缺口：

- REL-003：Launcher 完成 runtime tree hash 验证后，到 Windows `CreateProcess` 按路径启动前，runtime 被替换。
- SEC-004：Desktop 更新暂存、原子切换和卸载缓存清理在 `lstat` 后按路径操作，root、junction 或 reparse point 被替换。

更新检查、Ed25519 签名链、反重放、原子切换、失败回滚、REL-006 不迁移和卸载范围保持现有契约。真实 feed、正式证书、断电测试和 Windows 真机证据属于 P3-T08。

## 威胁模型

攻击者能在当前用户可写目录中并发创建、重命名或替换文件、目录、junction、symlink 和其他 name-surrogate reparse point。攻击者不能注入 Launcher/Desktop 进程、取得管理员权限、修改已签名 manifest，或绕过 Windows 内核对打开句柄的 share mode 和对象身份保证。

目标是确保安全检查针对的对象就是后续启动、rename 或 delete 使用的对象；所有受控路径都必须保持在已打开的 root 句柄内，并拒绝 reparse traversal。拥有管理员权限、进程注入能力或内核级访问的攻击者不在本阶段边界内。

## 方案

### Launcher runtime 启动绑定

新增 runtime launch lease。Windows 实现从已打开的 runtime root 句柄遍历目录树，使用不共享 write/delete 的文件句柄读取并计算签名 tree hash，拒绝 reparse point、非普通文件、多硬链接和遍历期间身份变化。所有验证过的文件句柄保持打开，交给 `ManagedProcess` 持有，直到进程退出或停止。

入口路径必须位于同一 lease root。`CreateProcess` 前后读取入口文件 identity；原验证句柄仍禁止 write/delete sharing，因此路径对象无法被替换或改写。Go/Win32 不支持直接从现有文件句柄调用 `CreateProcess`，所以“独占句柄锁 + 入口 identity 重验 + 同一 root 约束”构成绑定保证。

非 Windows 实现保留原 tree hash 行为并提供相同 lease 生命周期接口，不声称具有 Windows share-mode 保证。

### Desktop 安全文件操作 helper

Launcher 增加内部、非用户可见的 release filesystem helper。Desktop 通过明确参数调用同一受信 Launcher binary。helper 打开受控 root 后，只接受固定操作与固定叶名称；使用 Go `os.Root` 执行创建、rename、隔离和递归删除。

Windows Go `os.Root` 基于目录句柄和 `NtCreateFile`，路径解析使用 `O_NOFOLLOW_ANY`，rename/delete 使用 handle-relative Win32 操作。helper 在操作前拒绝 root 自身的 reparse point，并拒绝目标树内 junction/reparse point。Desktop 不再对这些操作执行 `lstat` 后的路径 use；网络下载仍只能写入 helper 创建的唯一 staging 目录。

helper 支持的最小操作：

- 创建唯一 update staging 目录。
- 在 package root 内固定文件名之间 rename。
- 删除已创建 staging 目录。
- 将 `runtime`、`cache`、`updates` 隔离到唯一 quarantine 名后，递归删除隔离树。

参数不允许绝对子路径、`..`、任意 child 名或跨 root 操作。helper 失败时 Desktop 沿用现有更新恢复和 partial failure 状态。

## 测试

- Go：先加入替换攻击测试钩子。验证 runtime 文件在 hash 后、启动前无法被替换；入口 identity 不一致时拒绝启动；lease 在进程结束后释放。
- Go Windows helper：测试 root/child reparse 拒绝、rename/remove 不越界、替换攻击失败。macOS 只运行通用单测和 `GOOS=windows GOARCH=amd64` 交叉编译；不标记真机通过。
- TypeScript：通过注入 helper adapter 验证 staging、switch、cleanup 只走安全操作接口；helper 拒绝时保留 active runtime 或报告 partial failure；既有签名、回滚、卸载测试继续通过。
- 完整验证：Launcher `go test`、`go test -race`、`go vet`、Windows amd64 交叉编译；Desktop 定向测试、完整 tests、typecheck、build；适用 packaging tests。

## 残余风险

- Windows share-mode、junction/reparse 拒绝和 `os.Root` handle-relative 行为仍需 P3-T08 真机攻击测试确认。
- 真正断电中的文件系统持久化语义需 P3-T08 实机断电测试。
- 正式证书、真实 feed 和生产签名资产不在本设计中验证。
