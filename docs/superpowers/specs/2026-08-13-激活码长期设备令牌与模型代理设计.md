# Bavi-box 激活码、长期设备令牌与模型代理设计

> 状态：已确认  
> 确认日期：2026-08-13  
> 适用版本：第一版启动激活授权的下一次实现与 VPS 部署  
> 替代范围：[真实模型对话与消息布局设计](./2026-08-13-真实模型对话与消息布局设计.md) 中“短期客户端 Token、有效期、刷新”部分

## 1. 目标与边界

用户收到的产品盘根目录包含 `Bavi-box.exe` 和激活码 TXT。首次启动只要求用户输入激活码，不要求用户名。激活成功前不进入正常工作区，内嵌模型不可用；激活成功后，客户端获得绑定当前产品盘的长期设备访问令牌，并通过 Bavi-box 模型代理访问独立部署的 New API。

本设计保留已有启动许可证、U 盘指纹、撤销、换发和离线启动边界。取消的只有模型访问令牌的固定有效期和客户端自动刷新，不取消服务端逐请求状态检查。

第一版接受“防君子”边界：完整复制产品盘可能复制长期设备令牌，复制者与原用户共享同一 New API 账户、余额、额度、限速和封禁状态。不承诺抵抗完整磁盘镜像、逆向、内存提取或硬件级复制。

## 2. 凭证分工

| 凭证 | 唯一用途 | 保存位置 | 生命周期 |
| --- | --- | --- | --- |
| 激活码 | 首次绑定产品盘 | 用户激活码 TXT；服务端仅保存带 pepper 的摘要 | 成功绑定一次后不可再次绑定其他盘 |
| 启动密钥与签名许可证 | Launcher 启动授权 | U 盘隐藏目录；服务端保存必要校验材料 | 沿用许可证撤销、禁用、换发规则 |
| 长期设备访问令牌 | 调用 Bavi-box 模型代理 | U 盘 mode `0600` 文件；服务端仅保存摘要 | 不设 `expiresAt`；可禁用、撤销、重新发放 |
| New API Key | 代理访问对应 New API 账户 | 仅当前 VPS 加密保存 | 由管理员录入、替换或禁用 |
| 上游供应商 Key | New API 调用模型上游 | 仅独立 New API 服务器 | 不进入当前 VPS、客户端或 U 盘 |

激活码不是日常 API 密码。New API Key 永远不返回客户端。启动密钥、设备访问令牌、New API Key 和上游供应商 Key不得复用、互相派生或共享撤销材料。

## 3. 发货前准备

第一版采用人工预配置：

```text
生成随机激活码
-> 在验证服务器创建库存记录，只保存激活码摘要
-> 录入对应 New API 用户 ID、用户名、API Key、默认模型和上游地址
-> 加密保存 New API Key，库存状态设为 prepared/configured
-> 将激活码明文写入该产品盘的激活码 TXT
-> 激活码明文不再进入数据库、日志或普通管理查询
```

New API 账号可以由运营人员预先创建。未来自动开户属于独立升级，不改变客户端激活协议。

## 4. 首次激活流程

```text
Launcher 检测未激活
-> 启动唯一 Electron 的 activation-only 界面
-> 用户只输入激活码
-> 客户端提交 activationCode、usbFingerprint、clientVersion、idempotencyKey
-> 验证服务器用摘要定位唯一库存
-> 检查库存未绑定、New API 映射已配置
-> 原子绑定 U 盘指纹并签发启动许可证
-> 生成随机长期设备访问令牌，服务端只保存摘要
-> 返回启动许可证、启动凭据和内嵌模型凭据
-> 客户端原子写盘、本地验签、提交 activation commit
-> Launcher 重新执行完整启动检查并进入正常工作区
```

激活响应中的内嵌模型凭据采用一个正式契约，不再并存 `activation-builtin-credential.v1.json` 与无法直接消费的另一套模型凭据：

```json
{
  "schemaVersion": 1,
  "deviceId": "...",
  "licenseId": "...",
  "endpoint": "https://121.41.89.103/model-api/",
  "model": "gpt-5.6-sol",
  "deviceToken": "随机高熵长期令牌"
}
```

正式域名生效后，`endpoint` 改为 `https://license.yiyong.me/model-api/`。客户端不得硬编码 New API 地址或 New API Key。

## 5. 日常模型请求

```text
OpenClaw / Desktop 内嵌模型路径
-> 从 U 盘安全读取 endpoint、model、deviceToken
-> Authorization: Bearer <deviceToken>
-> 当前 VPS 的 /model-api/*
-> 设备令牌摘要查询
-> 检查 inventory、device、license、binding 均为 active
-> 检查 New API 映射 configured，模型在允许范围
-> 解密该映射的 New API Key
-> 替换上游 Authorization 并转发到独立 New API
-> 将兼容响应返回客户端
```

第一版至少代理：

- `GET /model-api/v1/models`
- `POST /model-api/v1/chat/completions`

模型代理由 Go 服务实现鉴权、映射、密钥解密、请求转发、超时、限流和审计。Caddy 只负责 TLS、路由和负载均衡，不保存或注入每用户 New API Key。

## 6. 数据与管理面

现有库存、设备、许可证和 New API binding 继续复用。新增或调整的数据必须表达：

```text
inventory_id
device_id
license_id
device_token_id
device_token_digest
device_token_status
new_api_user_id
new_api_username
encrypted_new_api_key
new_api_key_version
new_api_base_url
default_model
allowed_models
binding_status
created_at
updated_at
```

管理 CLI 负责：

- 为 prepared 库存录入或替换 New API 映射与密钥。
- 查看脱敏映射状态，不显示 Key 或设备令牌。
- 禁用、启用或撤销设备访问令牌。
- 为同一有效设备重新发放设备令牌；旧令牌立即失效。

数据库 migration 角色和应用角色保持分离。New API Key 使用现有 envelope/KMS 边界加密；正式环境必须替换测试用 `local-kek-v1`。

## 7. 错误处理

| 场景 | 结果 |
| --- | --- |
| 激活码不存在或格式错误 | 统一返回 `ACTIVATION_INVALID`，不泄露库存存在性 |
| 激活码已绑定其他产品盘 | 返回 `ACTIVATION_CODE_ALREADY_BOUND` |
| New API 映射未配置 | 返回 `BUILTIN_BALANCE_PENDING`，不得绑定库存 |
| 激活响应不明或写盘中断 | 沿用同盘事务 journal 和幂等恢复 |
| 设备令牌无效或已撤销 | 模型代理返回固定 `401`，不泄露具体状态 |
| License、设备或 binding 非 active | 模型代理拒绝，固定分类错误，不请求 New API |
| New API 余额不足、限流、模型不可用 | 保留兼容状态和脱敏错误，不切换到其他 Provider |
| New API 网络或超时 | 返回可重试服务错误，不暴露上游地址、Key 或请求头 |

长期设备令牌没有到期检查，也没有 `/v1/device-tokens` 刷新流程。服务器仍在每次模型请求时检查授权状态，因此管理员禁用或撤销可立即阻止后续请求。

## 8. 部署拓扑

```text
客户端
  -> HTTPS 121.41.89.103（域名审核后改 license.yiyong.me）
      -> Caddy
          -> Go 激活/模型代理实例 127.0.0.1:18081
          -> Go 激活/模型代理实例 127.0.0.1:18082
              -> PostgreSQL（本机，仅内部访问）
              -> mTLS/安全组白名单
                  -> 独立高配置 New API 服务器
```

独立 New API 未部署前，可以完成激活协议、凭据写盘和代理拒绝路径，但不得宣称真实首次模型对话通过。New API 接入后，安全组只允许当前 VPS 访问其数据面，服务间优先使用 mTLS。

## 9. 验收门禁

实现完成后必须重新部署到 `121.41.89.103`，并验证：

1. 激活界面没有用户名字段，只提交激活码。
2. 错误激活码不绑定库存；正确激活码只绑定一次。
3. 激活响应不含 `expiresAt`，客户端不调用刷新接口。
4. 长期设备令牌写入 mode `0600` 文件，New API Key 不进入客户端、日志或响应。
5. 正常模型路径可直接读取激活产物，不再需要第二套 provisioning credential。
6. 模型代理每次校验 License、设备、binding 和设备令牌状态。
7. 两个 Go 实例任停一个，激活和模型代理入口仍可用。
8. `/internal/*`、`/metrics` 和管理面继续拒绝公网访问。
9. 真实 New API 可用后，完成一次 `gpt-5.6-sol` 对话；余额不足、限流和禁用均按预期失败。
10. Go test/race/vet、Node build/typecheck/contract/integration/E2E、secret scan 和 Linux amd64 构建全部通过。

Windows 10/11、普通用户、Defender 和物理 U 盘仍是最终发行门禁，不能用 macOS 临时目录或 API smoke 替代。
