# 激活码长期设备令牌与模型代理实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户只输入激活码完成产品盘绑定，客户端获得无到期时间的长期设备令牌，并由当前 VPS 逐请求鉴权后代理独立 New API。

**Architecture:** 保留现有启动许可证、USB 指纹、激活 journal、幂等恢复和双实例部署。激活码仅用于首次绑定；长期设备令牌只在客户端和激活加密产物中出现，数据库仅存 pepper 摘要。Go 服务新增 OpenAI 兼容模型代理，按令牌加载加密 New API Key、执行授权与分布式限流、替换上游 Authorization；Caddy 只做 TLS 和双实例负载均衡。

**Tech Stack:** Go 1.24、PostgreSQL 15、pgx/v5、Node.js 24.15、TypeScript 5.9、React 19、Zod 4、Vitest、Playwright、Electron 40、Caddy、systemd。

**Authoritative spec:** [激活码长期设备令牌与模型代理设计](../specs/2026-08-13-激活码长期设备令牌与模型代理设计.md)

## 固定决策

- 数据库可保留 `username_*` 作为旧内部标识，但它不再是用户凭证，也不出现在激活 API/UI/TXT。
- `token_grants` 旧表保留用于历史兼容和回滚；新请求不再读写它，不执行破坏性 drop。
- 长期设备令牌格式为 `uclaw_dt_` 加 32-byte random 的 43 字符 base64url 编码；数据库保存 `HMAC-SHA256(activation pepper, raw token)`，不保存明文。
- New API Key 只允许从 mode `0600` 文件录入。CLI 参数、stdout、JSON 状态、HTTP 响应和审计均不得出现明文。
- v1 模型代理只接受非流式 OpenAI chat completions；Desktop 收到完整响应后继续转换成现有 `MessageEvent` 流。流式代理另立版本。
- 代理上游禁止 redirect，剥离 hop-by-hop 和客户端 Authorization，固定写入数据库映射对应的 New API Key。
- 两实例共享 PostgreSQL admission lease，限流不能靠单实例内存计数。
- 独立 New API 未提供前，只能验收代理拒绝、脱敏和网络错误路径，不能宣称真实模型对话通过。

```sql
CREATE TABLE IF NOT EXISTS device_access_tokens (
    device_token_id UUID PRIMARY KEY,
    inventory_id UUID NOT NULL REFERENCES activation_inventory(id),
    device_id UUID NOT NULL REFERENCES devices(device_id),
    license_id UUID NOT NULL REFERENCES licenses(license_id),
    token_digest BYTEA UNIQUE NOT NULL CHECK (octet_length(token_digest) = 32),
    status TEXT NOT NULL CHECK (status IN ('active', 'disabled', 'revoked')),
    issued_at TIMESTAMPTZ NOT NULL,
    revoked_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL,
    updated_at TIMESTAMPTZ NOT NULL,
    FOREIGN KEY (license_id, device_id) REFERENCES licenses(license_id, device_id),
    CHECK ((status = 'revoked') = (revoked_at IS NOT NULL))
);
CREATE UNIQUE INDEX device_access_tokens_one_active_per_device
ON device_access_tokens(device_id) WHERE status = 'active';

ALTER TABLE new_api_bindings
    ADD COLUMN IF NOT EXISTS api_key_envelope BYTEA,
    ADD COLUMN IF NOT EXISTS api_key_version TEXT,
    ADD COLUMN IF NOT EXISTS base_url TEXT,
    ADD COLUMN IF NOT EXISTS default_model TEXT,
    ADD COLUMN IF NOT EXISTS allowed_models TEXT[] NOT NULL DEFAULT '{}',
    ADD COLUMN IF NOT EXISTS requests_per_minute INTEGER NOT NULL DEFAULT 60 CHECK (requests_per_minute BETWEEN 1 AND 6000),
    ADD COLUMN IF NOT EXISTS concurrent_requests INTEGER NOT NULL DEFAULT 2 CHECK (concurrent_requests BETWEEN 1 AND 100);

CREATE TABLE IF NOT EXISTS model_proxy_admissions (
    request_id UUID PRIMARY KEY,

CREATE INDEX model_proxy_admissions_token_started_idx
```

- [ ] **Step 3: 实现 repository 授权与分布式 admission**

```sql
SELECT pg_advisory_xact_lock(hashtextextended($1::text, 0));
DELETE FROM model_proxy_admissions
WHERE device_token_id=$1 AND lease_expires_at < clock_timestamp();
SELECT count(*) FILTER (WHERE completed_at IS NULL),
       count(*) FILTER (WHERE started_at >= clock_timestamp() - interval '1 minute')
FROM model_proxy_admissions WHERE device_token_id=$1;
```
