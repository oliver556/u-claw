# P2-T14 TOCTOU 加固实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 Launcher 验证的 Windows runtime 对象绑定到启动，并把 Desktop 生产更新和缓存清理移入 handle-relative Launcher helper。

**Architecture:** Launcher 增加 runtime lease；Windows lease 对已哈希文件持有禁止 write/delete sharing 的句柄，并在 `CreateProcess` 前重验入口 identity。Launcher 还提供固定协议的内部 release-fs helper；Desktop 生产服务把包流交给 helper，由同一 root handle 完成 staging、校验、transaction 和切换，缓存清理也由 helper 完成。

**Tech Stack:** Go 1.25+ `os.Root`、Win32 `CreateFileW`/file identity、Node.js 24 streams/child process、TypeScript、Vitest。

**Files:**
- Create: `product/launcher/release_fs_helper.go`

- [ ] **Step 2: 验证 RED**

Run: `go test ./... -run 'TestReleaseFSHelper'`

Expected: FAIL，因为 helper 入口不存在。

- [ ] **Step 3: 最小实现**

`runReleaseFSHelper(args, stdin, stdout)` 只接受：

```text
--release-fs-helper secure-install --root <packageRoot>
--release-fs-helper cleanup-cache --root <cacheRoot> --child runtime|cache|updates
```

`secure-install` 在一个 `os.Root` 生命周期内创建随机 staging、流式写 `runtime.pkg`、核对 signed bytes/SHA-256、写 signed `version.json`、写 transaction、使用 `Root.Rename` 切换并 fsync root。`cleanup-cache` 先用 root 内 marker 证明归属，递归扫描拒绝 reparse/非目录，再隔离和 `Root.RemoveAll`。所有动态名称只由 helper 生成并通过 basename allowlist。

- [ ] **Step 4: 验证 GREEN**

Run: `go test ./... -run 'TestReleaseFSHelper'`

Expected: PASS，外部 sentinel 未变化。
