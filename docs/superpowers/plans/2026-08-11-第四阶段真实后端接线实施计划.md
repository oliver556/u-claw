# Bavi-box 第四阶段真实后端接线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将新 React UI 的 99 个用户功能接到真实 OpenClaw、U 盘权威文件、Desktop 服务及第三阶段服务，清除生产 Mock、固定空数据和仅更新 Store 的伪完成。

**Architecture:** 生产调用固定走 `React -> preload -> 受控 IPC -> Desktop/Adapter -> OpenClaw 或权威服务`。OpenClaw 会话、任务、Agent、Cron、Artifact 和配置不在 Bavi-box 中复制数据库；Bavi-box 仅为固定/分组等客户端元数据及便携文件维护 U 盘存储。实施基线为 `codex/integration-p2-t10-local@9bcd854`，执行前先将本计划和第四阶段文档合入该分支。

**Tech Stack:** TypeScript 5、React 19、Electron、Ant Design 5、Zod、OpenClaw Gateway WebSocket v4、Vitest、Testing Library、Playwright、Node.js `24.15.0`、Go Launcher。

---

## 文件结构

- `product/shared/src/`：只放领域 schema、错误和 `UClawClient`/IPC 契约。
- `product/adapter/src/`：只放 OpenClaw v4 RPC、事件映射和连接恢复。
- `product/desktop/src/wiring/`：生产对象图与环境读取；正式 Electron 唯一装配入口。
- `product/desktop/src/` 现有领域目录：文件、Provider、Skill、Plugin、MCP、渠道、诊断、更新和产品化服务。
- `product/frontend/src/features/`：真实状态、用户操作和可诊断错误；不解析 OpenClaw 原始 payload。
- `product/tests/integration/`：真实本地 Gateway/文件/服务证据；scripted fixture 只能作契约回归。
- `product/tests/e2e/`：通过 preload 驱动真实 Electron；Mock E2E 不计第四阶段完成。
- `docs/第四阶段联调验收矩阵.md`：99 个用户功能和 4 个内部决策的唯一状态表。

## 全阶段规则

- 每个 Task 先写失败测试，集中完成实现，再跑该 Task 的 typecheck、定向测试和一条真实 smoke。
- 写操作必须重新读取 OpenClaw RPC 或权威文件验证；不得仅断言 React Store。
- `UClawError.code` 区分 `UNCONFIGURED`、`UNSUPPORTED`、`OFFLINE`、`AUTH_FAILED`、`PROTOCOL_ERROR` 和领域错误。
- API Key、Token、二维码、会话正文和签名私钥不得进入 renderer 持久状态、日志、fixture 或快照。
- 外部账号、Windows 或物理 U 盘缺失时，矩阵只能标记 `待外部环境`；本地可验证部分仍须先通过。
- 每个 Task 提交前同步《第四阶段需求》《第四阶段任务对齐表》《第四阶段联调验收矩阵》。
