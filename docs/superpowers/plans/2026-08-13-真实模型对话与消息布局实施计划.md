# U-Claw 真实模型对话与消息布局实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让 U-Claw Electron 客户端通过现有 OpenClaw 主链使用 `gpt-5.6-sol` 完成真实对话，并把消息改成无头像、无名称的左右双气泡布局。

**Architecture:** 开发期 Provider 配置只由 Electron 主进程读取，通过现有 `ProviderStore` 幂等同步到 OpenClaw；renderer 不读取 Base URL 或 API Key。对话继续走 `React -> IPC -> model router -> OpenClawClient -> Gateway -> Provider`，第一版产品模型目录只公开 `GPT-5.6 Sol`。

**Tech Stack:** TypeScript 5.9、React 19、Electron、OpenClaw Gateway、Ant Design 5、Vitest、Testing Library、Playwright。

function MessageFrame({ message }: { message: Message }) {

export const DEFAULT_PRODUCT_MODEL = { productId: "gpt", modelId: "gpt-5.6-sol", label: "GPT-5.6 Sol" } as const;

export function toProductModels(items: Array<{ id: string; available: boolean }>) {
  return items
    .filter((item) => item.id === DEFAULT_PRODUCT_MODEL.modelId || item.id.endsWith(`/${DEFAULT_PRODUCT_MODEL.modelId}`))

- [ ] **Step 3: 实现解析与幂等同步**

导出：

```ts
export const DEVELOPMENT_PROVIDER_ID = "uclaw-development-gpt";
export function readDevelopmentProvider(env: NodeJS.ProcessEnv): DevelopmentProvider | null;
export async function bootstrapDevelopmentProvider(store: ProviderStore, config: DevelopmentProvider | null): Promise<void>;
```

同步规则：

1. `null` 时不改现有 Provider。
2. ID 不存在时 `create()`；存在时只有字段变化才 `update()`。
3. API Key 每次通过 `setApiKey()` 写入凭据存储，不写普通 JSON。
4. 最后 `select()` 固定 Provider。
5. 重复执行后 Provider 仍只有一条，选择不变。

- [ ] **Step 4: 接入 Gateway 协商后的生产 wiring**

`createDesktopMainOptions(env)` 启动时只解析配置；在 `probeCapabilities()` 完成 Gateway 协商且确认必需方法后调用一次 bootstrap。原因：`ProviderStore` 的 `openClawConfig.synchronize()` 需要可用 Gateway，不能在 transport 连接前执行。

```ts
const developmentProvider = readDevelopmentProvider(env);
let developmentProviderReady = false;

// probeCapabilities 成功分支
if (!developmentProviderReady) {
  await bootstrapDevelopmentProvider(providers, developmentProvider);
  developmentProviderReady = true;
}
```

若配置完整但同步失败，启动 fail-closed，不能继续 mock 或 builtin。错误响应不得包含 Base URL、API Key 或 Authorization。
