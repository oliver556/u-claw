## 2. 不需要服务器的验收

以下项目主要需要 Windows 真机，不要求先提供服务器：

- Windows 10/11 x64 普通用户启动、关闭、重开和进程回收。
- NTFS junction/reparse point、ACL、文件锁和路径边界。
- Launcher runtime 缓存、更新切换、回滚和异常恢复。
- 安装器、卸载器和本机缓存清理。
- Windows 100%、125%、150% 缩放。

以下项目还必须使用物理 U 盘：

- 插拔、异常拔出、盘符变化和只读状态。
- U 盘写入中断、换机连续性和本机缓存隔离。
- 同一物理 U 盘在两台 Windows 机器上的数据连续性。
- 长时间运行、拔盘后的进程和宿主机残留审计。

## 3. 需要真实服务或账号的验收

不要求一开始就提供生产服务器，可以先使用隔离测试环境：

- 更新：HTTPS 测试 feed、公开签名公钥、测试签名包和撤销列表。
- Provider：测试 API Key、自定义 OpenAI-compatible 服务、本地 Ollama/LM Studio。
- Skill：SkillHub.cn 真实免费 Skill 数据和下载包。
- Plugin/MCP：真实插件包、MCP 服务和工具调用。
- 渠道：Telegram、QQ Bot、飞书、企业微信测试应用及回调；个人微信真实账号和 Windows 微信客户端。
- OpenClaw：真实锁定版本 runtime、会话、记忆、任务、配置和 Doctor 输出。

正式发布前再接入 production feed、正式公钥/证书和生产账号。私钥、API Key、Bot Secret 不写入文档或聊天，应放 GitHub Actions Secrets、本机环境文件或专用密钥系统；文档只记录变量名和配置位置。

production Launcher 构建前必须配置三个公开变量：

- `UCLAW_RUNTIME_TRUSTED_PUBLIC_KEYS`
- `UCLAW_RUNTIME_REVOKED_KEY_IDS`
- `UCLAW_RELEASE_BASE_URL`

## 5. 验收顺序

1. 先闭合第 4 节的实现缺口。
2. 使用 Windows 真机完成不依赖服务器的系统验收。
3. 使用物理 U 盘完成插拔、换机、写入中断和残留审计。
4. 接入隔离测试 feed、测试 Provider 和渠道账号。
5. 全部稳定后再配置 production feed、正式证书和生产账号。
