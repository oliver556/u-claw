# U-Claw 第四阶段需求

> 文档状态：第四阶段本地会合完成；正式环境验收移交 `P3-T08`
> 记录日期：2026-08-12
> 代码基线：`codex/integration-phase4@8d8e69a`
> 审计入口：[《第四阶段后端能力全量审计》](./第四阶段后端能力全量审计.md)

## 1. 阶段目标

第四阶段把前三阶段已有 UI、shared 契约、IPC、Adapter、Desktop Service 和 Launcher 接到真实 OpenClaw 与已有后端。

交付主链：

```text
原项目用户能力
-> U-Claw shared/Adapter
-> Electron 受控 IPC
-> React UI
-> 用户操作真实生效
-> 后端权威状态回读
```

本阶段不接受以下完成证据：

- 页面已可见。
- Mock/fixture E2E 通过。
- typed contract 存在。
- Store 能存储数据。
- localhost 假服务返回成功。

## 2. 核心完成标准

每个用户功能必须同时满足：

1. 生产 Electron 不使用 `MockUClawClient`。
2. UI 请求经 preload、IPC 和 Adapter/领域服务到达真实后端。
3. 写操作可从后端或权威文件读回，不仅更新 UI Store。
4. 空数据、未配置、不支持、离线、鉴权失败和协议错误均有不同状态。
5. 至少完成一条非 Mock 成功证据和一条真实失败证据。
6. 缺少外部账号或 Windows/U 盘时，状态只能是“待外部环境”，不能是“已完成”。

## 3. 功能包

### 3.1 生产装配

- 实现仓内受控 `createDesktopMainOptions()`。
- 组装 Gateway 进程、WebSocket v4、`OpenClawClient`、附件、健康探测、Provider executor 和各领域服务。
- 浏览器开发预览必须显式标识 Mock；正式 Electron 禁止回退 Mock。

### 3.2 工作、会话、文件与记忆

- Gateway 会话列表、新建、切换、重命名、删除、历史分页和刷新恢复。
- 发送、流式、停止、附件、工具事件和单次审批。
- 会话固定、分组与 U 盘元数据落盘。
- OpenClaw Session 文件、工作区文件、Markdown 记忆和上下文读回。
- 会话 reset、compact、branch、restore 和 steer 进入受控高级操作。

### 3.3 模型、Provider、配置与用量

- Provider Store 与 OpenClaw `config.get/schema/patch` 统一。
- 国产 Provider、OpenAI-compatible、Ollama/LM Studio 连通测试和实际对话使用同一配置。
- `builtin/domestic/custom` 三类路由真实执行，外部错误不静默回退。
- API Key 不进入 renderer 持久状态、日志或导出。
- 接入 OpenClaw Usage/Cost/Session Usage 和时序数据。

### 3.4 Skill、Plugin、MCP、工具与审批策略

- 原 `portable/skills-cn` 内置 Skill、U 盘安装 Skill 和 OpenClaw 可用状态统一。
- SkillHub.cn 免费 Skill 搜索、详情、安装、更新和卸载后可被 OpenClaw 读回。
- Plugin 生命周期、UI descriptors 和 session actions 进入真实 runtime。
- MCP 区分已配置、已投影工具和实时 probe，不虚报连接。
- 工具 catalog/effective 和 Exec/Plugin 审批策略可管理。
- Skill curator/proposals 作为高级能力接入。

### 3.5 渠道

- Telegram、QQ Bot、飞书、企业微信、个人微信和 Discord 进入真实 OpenClaw/Plugin runtime。
- 每个渠道支持配置、连通测试、启停、重连、登出、状态和消息收发验证。
- 个人微信优先复用已有可执行扫码流程，再通过受控 Adapter 输出。
- 统一状态来自各 runtime，不来自 UI Store 推测。

### 3.6 Agent、Cron、Task 与成果

- Agent 列表、身份、创建、编辑、删除、文件和 workspace。
- Cron 列表、状态、新增、更新、删除、立即运行和运行历史。
- 活动中心直接使用 `tasks.list/get/cancel` 和 `task` 事件。
- 成果页使用 `artifacts.list/get/download`，保留来源会话。

### 3.7 高级系统能力

- 真实 logs、diagnostics.stability、audit、Doctor 和受控修复。
- 设备配对、Token 轮换/撤销和 Node 列表/配对/调用。
- Environment/worktree 列表、状态、创建、删除、恢复和清理。
- 原生 Terminal 通过严格 IPC 和 Gateway terminal RPC 提供，不暴露任意本机 shell。
- Talk/TTS、Voice Wake 和 Push 进入高级设置。
- 备份、恢复、空间、恢复出厂、更新、回滚和本机缓存清理使用真实服务。

### 3.8 第三阶段产品化链路

- 隐藏内置模型、授权、USB 指纹、许可证生命周期、制盘、New API 开户和失败补偿进入真实配置。
- 额度、限速、并发、模型权限、用户/设备禁用和用量统计从真实 New API 读回。
- 本地 fixture 只作自动化，不作为正式服务通过证据。

- `secrets.reload/resolve`：保留在 Electron/服务端，不返回明文。
- `controlUi.githubPreview`：Dashboard 内部预览，不迁移。
- `crestodian.*`：无已批准用户需求，不直接暴露。

## 7. 联调配置

- 根目录 `.env.example` 是字段说明与模板。
- 根目录 `.env` 是本机联调值，由 `.gitignore` 忽略。

- License/Release 签名私钥、企业上游 Key 和 New API 服务端秘密禁止进入客户端 `.env`。
