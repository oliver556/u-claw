# 技能库模块迁移复盘与实现指南

> 用途：把本项目技能库模块迁移到新项目时使用。本文基于 ZUXO 原始实现文档、U-Claw 实际开发过程、问题日志、修复提交和测试结果整理。
>
> 原始需求基线：`/Users/biancheng/Documents/ZUXO/docs/技能库功能开发实现逻辑.md`
>
> 结论：技能库不能只迁 UI。必须同时迁移本地 API 代理、SkillHub 安全客户端、安装事务、OpenClaw runtime 读回、缓存/限流策略、权限确认、错误分类和前端 loading/轮询状态。

## 1. 目标体验

技能库页面需要提供两个主入口：

- 技能商城：展示 SkillHub 在线目录，支持搜索、分类、排序、分页、详情抽屉和安装。
- 我的技能：展示本地已安装 Skill，支持查看详情、导入 ZIP、启用、禁用、卸载或后续更新。

核心体验要求：

- 前端只请求本地 API/IPC，不直接暴露 SkillHub API Key 或远程下载细节。
- 商城默认 40 条/页，默认推荐排序。
- 搜索 300ms debounce，分类/排序变化重置分页。
- 列表项显示图标、名称、版本、描述、分类、下载量、收藏量、安装状态。
- 点击列表项打开右侧详情抽屉，抽屉展示 README/Markdown。
- 安装为异步任务，前端展示 `queued/running/succeeded/failed` 状态，并支持重启恢复。
- 安装完成后刷新本地技能列表与 OpenClaw runtime 状态。
- 高风险 Skill 安装和重新启用都必须显式确认权限。

## 2. 推荐架构

```text
Frontend UI
  │
  │ IPC / localhost API only
  ▼
Desktop Skill Service
  ├─ SkillHub Client: search/detail/readme/download/cache
  ├─ Bundle Validator: ZIP/path/hash/identity/security
  ├─ Install Coordinator: transaction journal + recovery
  └─ OpenClaw Runtime: skills.status / skills.update readback
       │
       └─ data/.openclaw/workspace/skills
```

迁移时建议拆成四层：

- `frontend/features/skills`：商城、我的技能、详情抽屉、确认弹窗、loading、operation polling。
- `shared/capabilities`：`SkillCatalogItem`、`SkillDetail`、`SkillOperation`、权限、风险等级、logo allowlist 等契约。
- `desktop/src/skills/skillhub-*`：SkillHub 搜索、详情、README、下载、缓存、错误分类。
- `desktop/src/skills/skill-service.ts` 与 `openclaw-skill-runtime.ts`：安装事务、本地状态、runtime 读回、启停恢复。

## 3. 原始需求到本项目的实现映射

| 原始需求 | U-Claw 实现要点 |
| --- | --- |
| 本地代理 SkillHub | 前端通过 `window.uclaw.skills.invoke` 调本地服务；远程请求只在 desktop 层。 |
| 40 条/页、搜索、分类、排序 | `skills.search` 支持 `query/category/sort/cursor/pageSize`；前端 300ms debounce。 |
| 详情抽屉读取 README | `skills.detail` 返回详情与 markdown；前端用 `SafeMarkdown` 渲染。 |
| 安装异步任务 | 后端返回 `SkillOperation`；前端轮询 `skills.operation`。 |
| 安装后刷新本地 skills | 成功后同时刷新 `skills.installed` 与 `skills.runtime-status`。 |
| 启用/禁用 | `skills.set-enabled` 调 OpenClaw `skills.update`，再读回验证。 |
| 缓存与 stale fallback | `skillhub-cache.ts` 管理 live/cache；只对明确 transient upstream failure 回退。 |
| 安全校验 | `bundle-validator.ts`、`skillhub-client.ts` 校验 ZIP、路径、hash、identity、trusted hosts。 |

## 4. 已遇到问题、根因、修复

### 4.1 列表不能滚动、空态顶部空洞、Logo 缺失

现象：

- 技能商城列表无法正常滚动。
- 没数据时空态距离顶部过大。
- 图标经常显示不出来。

根因：

- 列表没有独立 scroll owner，页面 grid 高度被上层吃掉。
- 空态落在隐式 grid 行里，被结果区高度撑出大空洞。
- SkillHub 前 200 条约 48.5% 返回 `iconUrl: null`，并非本地图片加载链路全坏。

修复：

- `.skill-results` 做独立滚动区，顶部 tabs/header/filter 常驻。
- 空态紧跟 toolbar，取消隐式大行撑高。
- `SkillLogo` 增加首字母 fallback，只接受可信 host 的远程图标。

涉及文件：

- `product/frontend/src/features/skills/SkillManager.tsx`
- `product/frontend/src/features/skills/SkillLogo.tsx`
- `product/frontend/src/theme/global.css`
- `product/frontend/tests/SkillManager.test.tsx`

### 4.2 分类中文、名称中文、分类/排序切换后加载异常

现象：

- 分类显示英文，不符合中文产品体验。
- 切换分类和排序后，列表可能不刷新或加载错数据。

根因：

- 分类 key 未映射中文 label。
- 前端传 `sort`，而 SkillHub 期望 `sortBy + order=desc`。
- 并发请求乱序返回，旧响应覆盖新结果。
- cache/live 分页混用会污染 identity proof。

修复：

- 固化 13 个一级分类中文映射，保留原始 category key 做筛选。
- 排序映射为官方参数：`score/downloads/stars/updatedAt` -> `sortBy=...&order=desc`。
- 前端使用 request sequence，后端使用 catalog epoch 丢弃旧会话响应。
- 禁止 cached/live 混合分页，detail cache 校验 identity fingerprint。

涉及文件：

- `product/desktop/src/skills/skillhub-client.ts`
- `product/desktop/src/skills/skillhub-cache.ts`
- `product/frontend/src/features/skills/SkillManager.tsx`

### 4.3 打开 Find Skills 失败

现象：

- 打开 `find-skills` 详情失败，但真实 HTTP search/detail/file/COS 链路可通。

根因：

- SkillHub API identity 与 README frontmatter 陈旧不一致。
- 旧逻辑把详情展示和安装校验绑定太死。
- 错误被误分类，UI 只看到泛化失败。

修复：

- 详情展示以 API identity 为权威。
- 安装前仍由 `validateSkillBundle()` 严格校验 ZIP 内 slug/version/identity，不降低安全边界。
- 引入 typed SkillHub failure，区分 not found、identity conflict、transient upstream。
- 只有明确 transient upstream failure 才允许 stale cache fallback。

提交：

- `48d4d30 fix SkillHub detail identity handling`

### 4.4 `ima-skills` 详情打不开

现象：

- `ima-skills` 打开详情失败。

根因：

- 合法 YAML `description: |` block scalar 被受限 parser 拒绝。
- 精确搜索同页存在 `namespace:null` 的坏 sibling，旧 schema 让整页失败。

修复：

- `bundle-validator.ts` 支持受限 YAML block scalar / folded scalar。
- search item 逐条校验，坏记录隔离丢弃。
- 若整页没有任何有效记录，仍 fail closed。

提交：

- `422aeeb fix SkillHub YAML detail parsing`

### 4.5 安装到 90% 后失败

现象：

- `ima-skills` 安装进度到约 90% 后失败。

根因：

- 商城 slug 为 `ima-skills`，但 `SKILL.md name` 为 `ima-skill`。
- OpenClaw runtime 用 `name` 作为 runtime id，安装后回读时按 slug 查找，导致误判失败。

修复：

- 安装读回使用本地 scanner 的 `slug/runtimeName/directoryKey` 建唯一 alias。
- 只接受 workspace 来源，不接受 bundled/managed namesake。
- 保持正反向唯一，避免同名或内置 Skill 混淆。

涉及文件：

- `product/desktop/src/skills/skill-service.ts`
- `product/desktop/tests/skill-service.test.ts`

提交：

- `68e635b fix skill runtime alias verification`

### 4.6 同 slug 多 namespace 安装失败

现象：

- 已确认具体 Skill 后，安装仍被拒绝。

根因：

- cached detail 与 live catalog proof 漂移。
- 同 slug 在多个 namespace 复用，旧逻辑无法安全重建 exact proof。
- Renderer 把 `CONFIRMATION_REQUIRED` 映射成泛化文案，遮蔽具体原因。

修复：

- exact tuple refresh：在 slug + namespace + version 唯一匹配时重建 proof。
- cache 强刷复用已确认 identity。
- 不放宽付费校验，不放宽身份绑定。

提交：

- `45a8c2a fix exact SkillHub identity refresh`

### 4.7 `_meta.json` 漂移导致安装失败

现象：

- `cnfinancialscraper` ZIP 真实下载成功，但安装校验失败。

根因：

- 根目录 `_meta.json` 是上游 transport metadata，清单 size/hash 可漂移。
- 普通安装文件仍应严格 hash/size 校验。

修复：

- 仅忽略根目录 `_meta.json` transport metadata。
- 其他文件继续执行 size/hash/path 校验。

涉及文件：

- `product/desktop/src/skills/skillhub-client.ts`
- `product/desktop/tests/skillhub-client.test.ts`

### 4.8 点击安装/启停/卸载无 loading，可重复提交

现象：

- 用户点击“开始安装”“确认安装”“启用”等按钮后，等待接口期间没有反馈。
- 快速重复点击可能产生重复请求。

根因：

- 只展示 operation 返回后的进度，没有覆盖 IPC start 返回前的等待态。
- React render 前存在同步重复提交窗口。

- Ant `Button loading` 与 `aria-busy`。
- `mutationPendingRef` / `importPendingRef` 同步防重复提交。
- 保留 operation polling 作为后续阶段反馈。

涉及文件：

- `product/frontend/src/features/skills/SkillManager.tsx`
- `product/frontend/src/features/skills/InstalledSkillWorkbench.tsx`
- `product/frontend/tests/SkillManager.test.tsx`

### 4.9 关闭 Skill 后重新启用失败，Switch 样式异常

现象：

- Skill 关闭后再启用失败。
- 启用按钮/Switch 显示成怪异方块。

根因：

- Workbench 重构后，重新启用固定传 `confirmation:null`，高风险 Skill 被后端拒绝。
- 全局 `.skill-table-row > button` CSS 误命中 `.ant-switch`。
- OpenClaw `skills.update` 后 `skills.status` 可能短暂 stale，立即读回会误判失败。

修复：

- 启用高风险已安装 Skill 前弹权限确认。
- 提交 `permissionFingerprint` 与 `acceptedRisk`。
- CSS selector 收窄到 `.ant-btn`。
- runtime readback 改为约 2 秒 bounded polling。
- domain error 仅经 schema 验证后透传，未知错误脱敏。

涉及文件：

- `product/desktop/src/skills/openclaw-skill-runtime.ts`
- `product/desktop/src/skills/skill-service.ts`
- `product/frontend/src/features/skills/InstalledSkillWorkbench.tsx`

## 5. 安全边界

迁移时不能放松这些边界：

- 前端不得保存或暴露 SkillHub API Key。
- SkillHub API 详情可用于展示，但安装包必须重新校验。
- 安装确认必须绑定 `permissionFingerprint`，不能只靠 checkbox。
- 同 slug 多 namespace 时必须保留 `namespace + slug + version + identityFingerprint`。
- ZIP 下载只允许可信 HTTPS host 和可信 redirect。
- ZIP 必须校验路径穿越、Windows 保留名、重复路径、symlink、文件数量、单文件大小、总大小、sha256。
- 上游 `_meta.json` 可特殊处理，但普通文件不能跳过 hash。
- cache fallback 只能用于明确 transient failure；identity conflict、paid drift、invalid payload 必须 fail closed。
- OpenClaw runtime 读回必须只接受 workspace 来源，不能被 bundled namesake 冒充。
- 高风险 Skill 重新启用必须再次确认权限。

## 6. 缓存与上游容错策略

建议保留或实现：

- Marketplace cache：按 query/category/sort/pageSize/cursor 或 page key 隔离。
- README cache：按 `namespace/slug/version` 隔离。
- Detail cache：保存 identity fingerprint，不允许跨 identity 复用。
- Stale fallback：仅限 timeout、429、5xx、网络错误等 transient。
- 429：读取 `Retry-After`，做指数退避，限制最大重试。
- Request dedupe：同一 URL/参数同时只允许一个 upstream promise。
- 前端先显示旧缓存，并以 `stale: true` 提示用户。
- cache schema 升级时禁止混入旧 identity 数据。

## 7. 前端交互规则

- 搜索输入 debounce 300ms。
- 分类/排序变化要显示 replacement loading，不能留旧结果假装新结果。
- 分页只能 append 当前 catalog session 的结果。
- 打开详情时，同一时间只允许一个详情请求，重复点击 disabled/loading。
- 安装、更新、导入 ZIP、启用、禁用、卸载都必须有 start loading。
- 操作进入 running 后显示 operation progress。
- 操作失败要显示后端精确 domain error，不要统一吞成“安装失败”。
- 空态不应占满过大顶部间距。
- 列表结果区必须独立滚动。
- Switch、Input、Select、Button 建议统一用 UI 库控件，CSS selector 不得误伤第三方组件内部结构。

## 8. 后端任务与恢复规则

安装、更新、卸载、启停建议统一为 `SkillOperation`：

```ts
type SkillOperation = {
  id: string;
  slug: string;
  action: "install" | "update" | "uninstall" | "enable" | "disable";
  state: "queued" | "running" | "succeeded" | "failed";
  phase: string;
  progress: number;
  error?: string;
};
```

关键要求：

- 每个 replace/remove/toggle 都写 transaction journal。
- 启动时先 recover 未完成事务。
- 文件写入使用 staging -> backup -> replace -> verify。
- state 写入使用 atomic JSON。
- OpenClaw readback 不一致必须 rollback 或标记失败。
- update 要保留原 enabled 状态。
- uninstall 遇到 bundled namesake 时，只删除 workspace 内容。

## 12. 迁移原则

新项目实现时，优先按这些原则决策：

- 展示可以宽容，安装必须严格。
- 前端可以缓存 UI 状态，身份和权限必须以后端为准。
- SkillHub 是不完全可信上游，所有 payload 都要 schema 校验。
- OpenClaw runtime 是最终可用性权威，安装完成必须读回确认。
- 所有异步操作必须给用户即时反馈。
- 所有会改变本地技能目录的操作必须可恢复。
- UI 统一用设计系统控件，业务 CSS 不碰第三方组件内部选择器。
