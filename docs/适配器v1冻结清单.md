# Bavi-box Adapter v1 冻结清单

> 状态：语义契约可开发，线上协议映射条件冻结
>
> 基线：`openclaw@2026.7.1-2`
>
> 协议：Gateway WebSocket JSON v4
>
> 详细定义：《Adapter 契约草案》

## 1. 冻结结论

Adapter v1 的前端语义边界已经足够稳定，可启动 `product/shared`、Mock Adapter、Electron IPC 和 React UI 开发。

不得将当前状态误称为“全量协议已冻结”。会话 patch 的置顶、分组和归档等字段、部分配置 schema、受控 CLI 和 Windows device identity 仍需真实 fixture 或实机证据。

冻结原则：

1. React 只依赖 Bavi-box 领域类型。
2. OpenClaw 原始 payload 只存在于 Adapter transport 和 mapper。
3. 新协议字段先进 fixture 和 mapper，不直接进组件。
4. 无真实证据的功能使用 Capability 关闭，不伪造可用状态。

## 3. 允许立即开发的契约

### 3.1 Gateway

- [x] 连接状态：`idle/connecting/authenticating/ready/reconnecting/degraded/failed/closed`。
- [x] token、password、device token 由 Electron 主进程持有。
- [x] `hello-ok` 映射为 Gateway 信息和 CapabilitySet。
- [x] 断线指数退避，启动中尊重 `retryAfterMs`。
- [x] 重连后重拉状态、会话、当前历史和待审批项。
- [x] 无通用 `seq replay`；检测到 gap 后执行重拉。

### 3.2 Session 和 Chat

- [x] `sessions.list/create/get/delete/resolve`。
- [x] `chat.history/message.get/send/abort`。
- [x] 发送使用 idempotency key。
- [x] 流式事件统一为 `started/delta/tool/approval/final/aborted/error`。
- [x] `delta` 区分 `append` 和 `replace`。
- [x] `final/error/aborted` 都是流的终态。
- [x] 草稿是 UI 本地状态，不属于 OpenClaw 协议。

### 3.3 Tool 和 Approval

- [x] `session.tool` 映射为统一 ToolCall。
- [x] ToolCall 状态：`pending/running/succeeded/failed/cancelled`。
- [x] Exec 审批使用 `exec.approval.*`。
- [x] Plugin 审批使用 `plugin.approval.*`。
- [x] 重连后分别调用 list/get 恢复待审批项。
- [x] renderer 不能直接发送任意 RPC 或任意命令。

### 3.4 Model、Skill、Channel 和系统状态

- [x] `models.list/authStatus/authLogout`。
- [x] `skills.status/search/detail/install/update/...` 形成管理领域边界。
- [x] `channels.status/start/stop/logout` 和 `web.login.start/wait`。
- [x] `logs.tail`、`health/status/system.info/diagnostics/audit`。
- [x] `update.status/run` 属于 Adapter 能力，但发行更新还需 Bavi-box 签名与回滚层。

### 3.5 File、Memory、MCP 和 Plugin

- [x] workspace/session/artifact 的只读列表和获取。
- [x] MCP 状态分为 `configured/projected/probed`。
- [x] MCP probe/reload 为 Electron 受控 CLI 边界。
- [x] Plugin 完整安装生命周期为 Electron 受控 CLI 边界。
- [x] 文件写入和记忆编辑在真实协议完成前保持 Capability 关闭。

## 4. 开发前必须落地的共享类型

`product/shared` 至少导出：

```ts
export interface UClawClient {
  gateway: GatewayService;
  sessions: SessionService;
  chat: ChatService;
  tools: ToolService;
  approvals: ApprovalService;
  models: ModelService;
  skills: SkillService;
  channels: ChannelService;
  files: FileService;
  diagnostics: DiagnosticsService;
}

export interface CapabilitySet {
  protocolVersion: 4;
  methods: ReadonlySet<string>;
  events: ReadonlySet<string>;
  features: Readonly<Record<string, boolean>>;
}

export type MessageEvent =
  | { type: "started"; runId: string; sessionId: string }
  | { type: "delta"; runId: string; mode: "append" | "replace"; text: string }
  | { type: "tool"; runId: string; tool: ToolCall }
  | { type: "approval"; runId: string; approval: ApprovalRequest }
  | { type: "final"; runId: string; message: Message }
  | { type: "aborted"; runId: string; reason?: string }
  | { type: "error"; runId: string; error: UClawError };
```

类型定义需搭配运行时 schema。所有进出 Adapter 的原始数据必须验证。

## 7. 契约变更规则

允许的 v1 兼容变更：

- 新增可选字段。
- 新增 Capability。
- 新增错误码，保留 `unknown` 回退。
- 新增不破坏已有语义的服务方法。

需要 v2 或迁移层的变更：

- 删除或重命名已冻结字段。
- 改变 `append/replace` 或终态语义。
- 将 Exec 和 Plugin 审批合并。
- 把本机缓存当成 U 盘用户数据唯一副本。
- 将 OpenClaw 原始字段暴露给 React。
