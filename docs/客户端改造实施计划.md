# U-Claw 客户端改造实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` (recommended) or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以当前 `portable/` 和锁定 OpenClaw 为能力基线，交付无浏览器感的 Windows Electron 客户端，完成第一至第四阶段开发，并在全部真实后端接线完成后统一执行真实 Windows 与物理 U 盘验收。

**Architecture:** 正式代码位于 `product/`。React 只依赖 `shared` 领域契约，Adapter 吸收 OpenClaw WebSocket/RPC 差异，Electron 负责窗口、IPC、Gateway 和受控 CLI。轻量 Launcher 与 runtime 打包是独立工作流，最终通过 Windows E2E 会合。

**Tech Stack:** TypeScript 5、React 19、Vite 7、Electron、Ant Design 5、TanStack Query、Zod、Vitest、Testing Library、Playwright、Node.js `24.15.0`、OpenClaw `2026.7.1-2`。

## 2. 目录与责任

```text
product/
├── package.json                 npm workspace 与统一脚本
├── package-lock.json            锁定产品依赖
├── tsconfig.base.json           TypeScript 共享配置
├── shared/                      领域类型、schema、错误和 IPC 契约
├── adapter/                     OpenClaw transport、mapper、重连和 Mock
├── desktop/                     Electron main、preload、窗口和子进程
├── frontend/                    React 页面、组件、状态和主题
├── launcher/                    Windows 轻量启动器
├── packaging/                   runtime.pkg、version.json 和发行目录
└── tests/                       跨包集成、契约和 Windows E2E
```

文件边界：

- `shared` 不依赖 Electron、React 或 OpenClaw 实现。
- `adapter` 不导入 React 组件。
- `frontend` 不导入 OpenClaw 原始类型。
- `preload` 只暴露已验证的白名单方法。
- `launcher` 不持有业务 UI 或 OpenClaw 协议逻辑。
