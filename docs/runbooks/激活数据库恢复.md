# 激活数据库备份与恢复

## 目标与边界

- RPO：生产 PostgreSQL 启用连续 WAL 归档，PITR 目标不超过 15 分钟数据损失。
- RTO：从确认恢复时间点起，60 分钟内完成新实例恢复、校验和受控切流。
- 恢复只写入新数据库或隔离实例。禁止覆盖仍在服务的生产库。
- 备份包含激活状态、许可 revision、加密 artifact envelope 与审计事件；不得包含明文激活码、startup secret 或 token secret。

## 备份与 PITR 前提

1. PostgreSQL 基础备份与 WAL 归档由基础设施层管理；归档存储启用版本化、加密和独立保留策略。
2. 每日逻辑备份用于可移植恢复演练：

```sh
umask 077
pg_dump --format=custom --no-owner --no-acl \
  --file activation-"$(date -u +%Y%m%dT%H%M%SZ)".dump \
  "$ACTIVATION_DATABASE_URL"
```

3. 记录 dump 的 SHA-256、PostgreSQL 主版本、开始/结束时间、源实例和 WAL 归档健康状态。备份文件与校验值不得写入仓库。

## 恢复命令

逻辑恢复必须使用新库：

```sh
createdb --maintenance-db="$ACTIVATION_ADMIN_DATABASE_URL" \
  "$ACTIVATION_RESTORE_DATABASE"
pg_restore --exit-on-error --no-owner --no-acl \
  --dbname "$ACTIVATION_RESTORE_DATABASE_URL" \
  activation-YYYYmmddTHHMMSSZ.dump

# Re-establish migration ownership, application DML grants, default privileges,
# and verify the application role still has no DDL privilege.
ACTIVATION_DATABASE_URL="$ACTIVATION_RESTORE_DATABASE_URL" \
  product/activation-server/deploy/migrate.sh
```

PITR 使用最新完整基础备份创建新实例，并将目标时间设为事故前已确认 UTC 时间：

```conf
restore_command = 'restore-wal %f %p'
recovery_target_time = '2026-08-13 02:14:00+00'
recovery_target_action = 'promote'
```

`restore-wal` 由生产基础设施提供，必须从不可变 WAL 归档按文件名取回并校验。禁止在原实例上直接执行 PITR。恢复达到目标时间并暂停/提升后，先封锁应用流量，再执行验证。

## 恢复验证与切流

部署顺序固定为：使用独立 migration 管理连接运行 `deploy/migrate.sh`；成功后，application role 启动 server/admin。server/admin 只读校验 `schema_migrations` version/checksum，不执行 DDL。示例 compose 的 `migrate` one-shot job 承担该步骤，两个 activation 实例等待其成功退出。

1. 对比 `schema_migrations` 版本与 checksum；任何不一致立即停止。
2. 对比源备份清单中的表行数，重点检查 `activation_inventory`、`licenses`、`activation_attempts`、`audit_events`。
3. 抽查 `prepared`、`binding`、`active`、`reissued`；核对 `entitlement_revision`、license `revision`、replacement 关系、artifact envelope 字节与 key version、审计顺序。
4. 对 username、activation code digest、USB fingerprint、license `(device_id, revision)` 和 activation idempotency key 执行唯一约束负向验证；均预期 SQLSTATE `23505`。不得删除或放宽约束完成恢复。
5. 对解包后的逻辑 SQL 或受控查询输出扫描已知演练秘密 marker；命中数必须为 `0`。扫描证据不得包含真实秘密值。
6. 使用应用角色连接，确认 DML 可用，同时 `CREATE TABLE` 与 `CREATE SCHEMA` 均被拒绝。
7. 记录验证人、时间、目标点、checksum、查询结果摘要和回滚点。双人批准后切换连接串；旧实例保持只读，直至观察期结束。

## 季度演练证据

每季度至少执行一次隔离恢复与 PITR 演练。证据路径：

```text
evidence/activation-db-recovery/YYYY-QN/
  manifest.md
  backup.sha256
  restore.log
  verification.log
  plaintext-secret-scan.txt
  approvals.md
```

`manifest.md` 必须记录 RPO/RTO 实测值、目标 UTC 时间、PostgreSQL 版本、备份/WAL 对象 ID、临时恢复实例 ID、异常与处置。日志先脱敏再归档；证据按安全审计保留策略保存，不提交到源码仓库。
