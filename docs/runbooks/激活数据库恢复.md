# 激活数据库备份与恢复

## 目标与边界

- RPO：生产 PostgreSQL 启用连续 WAL 归档，PITR 目标不超过 15 分钟数据损失。
- RTO：从确认恢复时间点起，60 分钟内完成新实例恢复、校验和受控切流。
- 恢复只写入新数据库或隔离实例。禁止覆盖仍在服务的生产库。
- 备份包含激活状态、许可 revision、长期设备 token digest、New API Key 加密 envelope、model proxy admission 与审计事件；不得包含明文激活码、startup secret、device token 或 New API Key。
- 部署前的 DB/env/Caddyfile/systemd/compose reference/binary 一致备份和 checksum 步骤见 [激活与模型代理部署](./激活与模型代理部署.md)。本文的数据库恢复不代替发布前完整备份。

## 备份与 PITR 前提

本文的 `bash` 块必须整块由 root 的 Bash 执行，不得使用 `sh` 或逐行复制，以保留 fail-fast 和 secret cleanup trap。

1. PostgreSQL 基础备份与 WAL 归档由基础设施层管理；归档存储启用版本化、加密和独立保留策略。
2. 每日逻辑备份用于可移植恢复演练：

```bash
set -Eeuo pipefail
trap 'exit_code=$?; printf "database backup failed at line %s with status %s\\n" "$LINENO" "$exit_code" >&2; exit "$exit_code"' ERR
trap 'unset PGSERVICEFILE PGPASSFILE' EXIT
export PGSERVICEFILE=/run/secrets/uclaw-activation/pg_service.conf
export PGPASSFILE=/run/secrets/uclaw-activation/pgpass
for secret_file in "$PGSERVICEFILE" "$PGPASSFILE"; do
  test -f "$secret_file"
  test ! -L "$secret_file"
  test "$(stat -c '%u:%a' "$secret_file")" = '0:600'
done
umask 077
BACKUP_FILE="activation-$(date -u +%Y%m%dT%H%M%SZ).dump"
pg_dump --dbname='service=uclaw_migration' --format=custom --no-owner --no-acl --file "$BACKUP_FILE"
```

3. 记录 dump 的 SHA-256、PostgreSQL 主版本、开始/结束时间、源实例和 WAL 归档健康状态。备份文件与校验值不得写入仓库。

## 恢复命令

逻辑恢复必须使用新库：

```bash
set -Eeuo pipefail
set +x
on_restore_error() {
  local exit_code=$?
  printf 'database restore failed at line %s with status %s\n' "$LINENO" "$exit_code" >&2
  exit "$exit_code"
}
cleanup_restore_environment() {
  unset ACTIVATION_DATABASE_URL ACTIVATION_MIGRATION_ROLE ACTIVATION_MIGRATION_PASSWORD
  unset ACTIVATION_APP_ROLE ACTIVATION_APP_PASSWORD PGSERVICEFILE PGPASSFILE PGOPTIONS
}
trap on_restore_error ERR
trap cleanup_restore_environment EXIT

: "${ACTIVATION_RESTORE_DATABASE:?ACTIVATION_RESTORE_DATABASE is required}"
: "${ACTIVATION_PRODUCTION_DATABASE:?ACTIVATION_PRODUCTION_DATABASE is required}"
: "${ACTIVATION_PRODUCTION_SYSTEM_IDENTIFIER:?ACTIVATION_PRODUCTION_SYSTEM_IDENTIFIER is required}"
: "${RESTORE_DUMP_FILE:?RESTORE_DUMP_FILE is required}"
: "${RESTORE_RELEASE_DIR:?RESTORE_RELEASE_DIR is required}"
: "${EXPECTED_BACKUP_MANIFEST_SHA256:?EXPECTED_BACKUP_MANIFEST_SHA256 is required}"
: "${EXPECTED_DUMP_SHA256:?EXPECTED_DUMP_SHA256 is required}"
[[ "$ACTIVATION_PRODUCTION_SYSTEM_IDENTIFIER" =~ ^[0-9]+$ ]]
[[ "$EXPECTED_BACKUP_MANIFEST_SHA256" =~ ^[0-9a-f]{64}$ ]]
[[ "$EXPECTED_DUMP_SHA256" =~ ^[0-9a-f]{64}$ ]]
test "$ACTIVATION_RESTORE_DATABASE" != "$ACTIVATION_PRODUCTION_DATABASE"
RESTORE_BACKUP_DIR="$(dirname -- "$RESTORE_DUMP_FILE")"
RESTORE_MANIFEST_FILE="$RESTORE_BACKUP_DIR/SHA256SUMS"
test "$(basename -- "$RESTORE_DUMP_FILE")" = 'activation.dump'
test -d "$RESTORE_BACKUP_DIR"
test ! -L "$RESTORE_BACKUP_DIR"
export PGSERVICEFILE=/run/secrets/uclaw-activation/restore-pg_service.conf
export PGPASSFILE=/run/secrets/uclaw-activation/restore-pgpass
MIGRATION_ROLE_FILE=/run/secrets/uclaw-activation/migration-role
MIGRATION_PASSWORD_FILE=/run/secrets/uclaw-activation/migration-password
APP_ROLE_FILE=/run/secrets/uclaw-activation/app-role
APP_PASSWORD_FILE=/run/secrets/uclaw-activation/app-password
for secret_file in "$PGSERVICEFILE" "$PGPASSFILE" "$MIGRATION_ROLE_FILE" "$MIGRATION_PASSWORD_FILE" "$APP_ROLE_FILE" "$APP_PASSWORD_FILE"; do
  test -f "$secret_file"
  test ! -L "$secret_file"
  test "$(stat -c '%u:%a' "$secret_file")" = '0:600'
done

for backup_file in "$RESTORE_DUMP_FILE" "$RESTORE_MANIFEST_FILE"; do
  test -f "$backup_file"
  test ! -L "$backup_file"
done
actual_manifest_digest="$(sha256sum "$RESTORE_MANIFEST_FILE" | awk '{print $1}')"
test "$actual_manifest_digest" = "$EXPECTED_BACKUP_MANIFEST_SHA256"
(
  cd "$RESTORE_BACKUP_DIR"
  sha256sum --check --strict SHA256SUMS
)
actual_dump_digest="$(sha256sum "$RESTORE_DUMP_FILE" | awk '{print $1}')"
test "$actual_dump_digest" = "$EXPECTED_DUMP_SHA256"

maintenance_control_access="$(psql --dbname='service=uclaw_restore_maintenance' -X -At --set=ON_ERROR_STOP=1 \
  --command "SELECT has_function_privilege(current_user, 'pg_catalog.pg_control_system()', 'EXECUTE')")"
test "$maintenance_control_access" = 't'
maintenance_system_identifier="$(psql --dbname='service=uclaw_restore_maintenance' -X -At --set=ON_ERROR_STOP=1 \
  --command 'SELECT system_identifier::text FROM pg_catalog.pg_control_system()')"
[[ "$maintenance_system_identifier" =~ ^[0-9]+$ ]]
test "$maintenance_system_identifier" != "$ACTIVATION_PRODUCTION_SYSTEM_IDENTIFIER"

createdb --maintenance-db='service=uclaw_restore_maintenance' "$ACTIVATION_RESTORE_DATABASE"

target_control_access="$(psql --dbname='service=uclaw_restore' -X -At --set=ON_ERROR_STOP=1 \
  --command "SELECT has_function_privilege(current_user, 'pg_catalog.pg_control_system()', 'EXECUTE')")"
test "$target_control_access" = 't'
target_system_identifier="$(psql --dbname='service=uclaw_restore' -X -At --set=ON_ERROR_STOP=1 \
  --command 'SELECT system_identifier::text FROM pg_catalog.pg_control_system()')"
target_database="$(psql --dbname='service=uclaw_restore' -X -At --set=ON_ERROR_STOP=1 \
  --command 'SELECT current_database()')"
test "$target_system_identifier" = "$maintenance_system_identifier"
test "$target_database" = "$ACTIVATION_RESTORE_DATABASE"
test "$target_database" != "$ACTIVATION_PRODUCTION_DATABASE"

pg_restore --exit-on-error --no-owner --no-acl --dbname='service=uclaw_restore' "$RESTORE_DUMP_FILE"

# Re-establish migration ownership, application DML grants, default privileges,
# and verify the application role still has no DDL privilege.
export ACTIVATION_DATABASE_URL='service=uclaw_restore'
export PGOPTIONS='-c log_statement=none -c log_min_error_statement=panic -c log_parameter_max_length=0'
export ACTIVATION_MIGRATION_ROLE="$(<"$MIGRATION_ROLE_FILE")"
export ACTIVATION_MIGRATION_PASSWORD="$(<"$MIGRATION_PASSWORD_FILE")"
export ACTIVATION_APP_ROLE="$(<"$APP_ROLE_FILE")"
export ACTIVATION_APP_PASSWORD="$(<"$APP_PASSWORD_FILE")"
"$RESTORE_RELEASE_DIR/deploy/migrate.sh"
```

`EXPECTED_BACKUP_MANIFEST_SHA256` 和 `EXPECTED_DUMP_SHA256` 必须来自外部 root-only append-only backup ledger 与已审批恢复单，不能从待恢复目录或其副本读取。脚本先验证 manifest 自身 digest，再在备份目录执行严格 `sha256sum -c`，最后独立验证 dump digest；三步都成功后才连接数据库，任何 mismatch 都在 `createdb`/`pg_restore` 前停止。

`restore-pg_service.conf` 定义不含密码的 `[uclaw_restore_maintenance]` 和 `[uclaw_restore]`：前者连接隔离恢复 cluster 的 `postgres` maintenance DB，只用于创建 `$ACTIVATION_RESTORE_DATABASE`；后者连接新建目标库，供 `pg_restore` 和 `migrate.sh` 使用。密码只在 `restore-pgpass`。两文件均为 root 所有、mode `0600`。两个 service 使用专用 restore/bootstrap administrator；该角色需要 `CREATEDB`、`CREATEROLE`、目标库/schema 所有权、角色管理权限，以及由 DBA 显式授予的 `EXECUTE ON FUNCTION pg_catalog.pg_control_system()`，但不授予 `SUPERUSER`、`REPLICATION` 或业务流量权限，也不得复用 application/migration role。生产 `system_identifier` 必须从受控资产记录加载，不能在本次恢复命令中临时查询生产库。脚本在创建目标库前拒绝生产库名和生产 cluster，创建后机械确认 maintenance/target service 的 `system_identifier` 相同、目标 `current_database()` 精确匹配且不是生产库；任一检查失败都在 `pg_restore` 前停止。`migrate.sh` 连接 bootstrap administrator 后内部 `SET ROLE` 到 `NOCREATEROLE` migration role 执行 migration；application role 同样保持 `NOCREATEROLE`。四个 role/password 环境值全部从独立 `0600` 文件加载，不出现在 argv 或 stdout。`PGOPTIONS` 将该 session 的 statement/parameter 日志关闭；必须事先确认托管平台/`pgaudit` 没有独立记录 password DDL，否则停止恢复 migration。EXIT trap 在成功和失败路径都清除环境中的 role password。

只允许使用当前 release 的 `deploy/migrate.sh` 和 migration 1-4。恢复旧 binary 时不运行旧 migrator；旧 binary 可以在保留 additive migration 4 schema 的前提下运行。migration 4 不做 down migration，不删除新 table/column/index/constraint，不删 `schema_migrations` version 4，不删除恢复库中的新数据。

PITR 使用最新完整基础备份创建新实例，并将目标时间设为事故前已确认 UTC 时间：

```conf
restore_command = 'restore-wal %f %p'
recovery_target_time = '2026-08-13 02:14:00+00'
recovery_target_action = 'promote'
```

`restore-wal` 由生产基础设施提供，必须从不可变 WAL 归档按文件名取回并校验。禁止在原实例上直接执行 PITR。恢复达到目标时间并暂停/提升后，先封锁应用流量，再执行验证。

## 恢复验证与切流

部署顺序固定为：使用独立 migration 管理连接运行 `deploy/migrate.sh`；成功后，application role 启动 server/admin。server/admin 只读校验 `schema_migrations` version/checksum，不执行 DDL。示例 compose 的 `migrate` one-shot job 承担该步骤，两个 activation 实例等待其成功退出。

1. 对比 `schema_migrations` 版本与 checksum；任何不一致立即停止。
2. 验证 ledger 为 1-4，`device_access_tokens` 和 `model_proxy_admissions` relation 存在，migration 4 checksum 与当前 release 一致。
3. 对比源备份清单中的表行数，重点检查 `activation_inventory`、`licenses`、`activation_attempts`、`device_access_tokens`、`new_api_bindings`、`model_proxy_admissions`、`audit_events`。不导出 `token_digest` 或 `api_key_envelope` 原值作为证据。
4. 抽查 `prepared`、`binding`、`active`、`reissued`；核对 `entitlement_revision`、license `revision`、replacement 关系、device token 状态与每设备唯一 active 约束、New API envelope/key version 成对性、admission lease/completion 时间和审计顺序。
5. 对 username、activation code digest、USB fingerprint、license `(device_id, revision)`、device token digest、每设备 active token 和 activation idempotency key 执行唯一约束负向验证；均预期 SQLSTATE `23505`。不得删除或放宽约束完成恢复。
6. 对解包后的逻辑 SQL 或受控查询输出扫描已知演练 secret marker；命中数必须为 `0`。扫描证据不得包含真实 secret 值。再扫描日志，确认无 activation code、device token、New API Key 或完整 prompt。
7. 使用应用角色连接，确认可读 `schema_migrations`且业务 DML 可用，同时 ledger 写入、`CREATE TABLE` 与 `CREATE SCHEMA` 均被拒绝。
8. 在恢复库的隔离应用实例上验证一个逾期 model proxy admission lease 会被下一次同 token admission 自动清理，不使用手工 SQL 修改 lease。
9. 记录验证人、时间、目标点、checksum、查询结果摘要和回滚点。双人批准后切换连接串；旧实例保持只读，直至观察期结束。

## 季度演练证据

每季度至少执行一次隔离恢复与 PITR 演练。证据路径：

```text
evidence/activation-db-recovery/YYYY-QN/
  manifest.md
  backup.sha256
  restore.log
  verification.log
  plaintext-secret-scan.txt
  approvals.md
```

`manifest.md` 必须记录 RPO/RTO 实测值、目标 UTC 时间、PostgreSQL 版本、备份/WAL 对象 ID、临时恢复实例 ID、异常与处置。日志先脱敏再归档；证据按安全审计保留策略保存，不提交到源码仓库。
