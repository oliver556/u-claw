# 激活与模型代理部署

## 目标与生产基线

本手册覆盖 `121.41.89.103` 上激活服务、长期设备令牌和模型代理的部署、域名切换、New API 接入、验收和回滚。本手册不记录真实 activation code、device token、New API Key、签名私钥、KEK、数据库密码或 operator credential。

2026-08-14 只读盘点确认当前生产主路径为：

```text
public HTTPS :443
  -> caddy.service
  -> 127.0.0.1:18081 / 127.0.0.1:18082
  -> uclaw-activation@18081.service / uclaw-activation@18082.service
  -> postgresql.service
```

两个 Go 实例只监听 loopback，Caddy 监听 `80/443`，四个 systemd 服务均为 active。当前 VPS 使用宿主机 systemd + Caddy + PostgreSQL，这是本手册唯一主部署路径。`product/activation-server/deploy/compose.production.example.yaml` 是新环境的容器化参考拓扑；它增加 OpenResty、edge mTLS 和 loopback management gateway，不得在当前 VPS 发布中混用 `docker compose` 命令、容器服务名或容器端口。若未来经审批整体迁移到 compose，必须另写迁移和回退计划。

## 发布前门禁

以下标记为 `bash` 的关键块必须作为完整块由 root 的 Bash 执行，不得逐行复制，不得使用 `sh`。执行前以 `test -n "$BASH_VERSION"` 确认解释器；`set -Eeuo pipefail`、ERR trap 和 EXIT secret cleanup trap 必须在同一进程内生效。

在 VPS 上定义本次发布变量，变量值必须来自已审批的制品和 UTC 时间：

```bash
set -Eeuo pipefail
trap 'exit_code=$?; printf "release path initialization failed at line %s with status %s\\n" "$LINENO" "$exit_code" >&2; exit "$exit_code"' ERR

export RELEASE_GIT_SHA
export BACKUP_UTC
[[ "$RELEASE_GIT_SHA" =~ ^[0-9a-f]{40}$ ]]
[[ "$BACKUP_UTC" =~ ^[0-9]{8}T[0-9]{6}Z$ ]]
export RELEASE_DIR="/opt/uclaw-activation/releases/$RELEASE_GIT_SHA"
export BACKUP_DIR="/opt/uclaw-activation/backups/$BACKUP_UTC"
test "$(basename -- "$RELEASE_DIR")" = "$RELEASE_GIT_SHA"
test "$(basename -- "$BACKUP_DIR")" = "$BACKUP_UTC"
test -d /opt/uclaw-activation/releases
test -d /opt/uclaw-activation/backups
test ! -e "$RELEASE_DIR"
test ! -e "$BACKUP_DIR"
umask 077
mkdir -m 0700 -- "$RELEASE_DIR"
mkdir -m 0700 -- "$BACKUP_DIR"
mkdir -m 0700 -- "$RELEASE_DIR/staging"
```

SHA 必须是 40 位小写十六进制 commit，UTC 必须是 `YYYYMMDDTHHMMSSZ`。先校验再拼路径，`basename` 再确认没有 path traversal。三个 `mkdir` 依赖底层 `O_EXCL` 语义；目录已存在或竞态创建时立即失败，禁止复用旧 release、backup 或 staging。失败后由发布人隔离残留目录并重新生成新的 `BACKUP_UTC`，不得删除后沿用同一标识。

必须先满足以下条件：

1. 本地 Task 10 质量门禁通过；Linux amd64 server/admin、migration 1-4 和 SHA-256 manifest 来自同一 `RELEASE_GIT_SHA`。
2. `systemctl is-active postgresql caddy uclaw-activation@18081 uclaw-activation@18082` 全部返回 `active`；`ss -lntp` 确认 `18081/18082` 仅绑定 `127.0.0.1`。
3. `/opt`、`/var/lib/postgresql` 空间可同时容纳 custom-format dump、两版 binary、配置备份和发布制品。
4. 发布人、回滚人、观察时间窗、上一版 SHA/checksum 已记录。没有可回滚备份时停止。
5. 禁止 shell tracing：会话中先执行 `set +x`；禁止将 secret 放在 CLI 参数、命令历史、stdout、工单或验收记录。

任一步失败必须停止发布：

```bash

  unset PGSERVICEFILE PGPASSFILE
}
trap on_backup_error ERR
trap cleanup_backup_environment EXIT

for secret_file in "$PGSERVICEFILE" "$PGPASSFILE"; do

  test ! -L "$secret_file"

done
test -f "$BACKUP_LEDGER"
test ! -L "$BACKUP_LEDGER"
test "$(stat -c '%u:%a' "$BACKUP_LEDGER")" = '0:600'
lsattr -d "$BACKUP_LEDGER" | awk '{print $1}' | rg -q 'a'

test "$(stat -c '%u:%a' "$BACKUP_DIR")" = '0:700'
test -z "$(find "$BACKUP_DIR" -mindepth 1 -print -quit)"
install -m 0600 /etc/uclaw-activation.env "$BACKUP_DIR/uclaw-activation.env"
install -m 0600 /etc/caddy/Caddyfile "$BACKUP_DIR/Caddyfile"
install -m 0600 /etc/systemd/system/uclaw-activation@.service "$BACKUP_DIR/uclaw-activation@.service"
install -m 0600 /usr/local/bin/uclaw-activation-server "$BACKUP_DIR/uclaw-activation-server"
install -m 0600 /usr/local/sbin/uclaw-activation-admin "$BACKUP_DIR/uclaw-activation-admin"
test ! -e /opt/uclaw-activation/compose.yml || install -m 0600 /opt/uclaw-activation/compose.yml "$BACKUP_DIR/compose.yml.reference-only"
pg_dump --dbname='service=uclaw_migration' -Fc --no-owner --no-acl --file "$BACKUP_DIR/activation.dump"
pg_restore --list "$BACKUP_DIR/activation.dump" > "$BACKUP_DIR/activation.dump.list"
systemctl cat caddy.service > "$BACKUP_DIR/caddy.service"
psql --dbname='service=uclaw_migration' -X -Atc \
  "SELECT version || ':' || encode(checksum,'hex') FROM schema_migrations ORDER BY version" \
  > "$BACKUP_DIR/schema-migrations.txt"
(
  cd "$BACKUP_DIR"
  find . -maxdepth 1 -type f ! -name SHA256SUMS -print0 | sort -z | xargs -0 sha256sum > SHA256SUMS
  sha256sum -c SHA256SUMS
)
backup_manifest_digest="$(sha256sum "$BACKUP_DIR/SHA256SUMS" | awk '{print $1}')"
backup_dump_digest="$(sha256sum "$BACKUP_DIR/activation.dump" | awk '{print $1}')"
[[ "$backup_manifest_digest" =~ ^[0-9a-f]{64}$ ]]
[[ "$backup_dump_digest" =~ ^[0-9a-f]{64}$ ]]

```

`pg_service.conf` 的 `[uclaw_migration]` 只写 host、port、dbname、user 和 TLS 参数；密码只写入 `pgpass`。两文件均必须 root 所有且 mode `0600`。`pg_dump`/`psql` argv 只出现无密码的 service name。如生产使用 peer auth，可以等价的专用 OS/migration role 命令取代。`backup-manifests.log` 必须由安全管理员预创建为 root `0600`、非 symlink，并用文件系统 append-only 标志（Linux `chattr +a`）保护；发布流程只能追加 UTC、manifest digest 和 dump digest。其副本进入独立备份目录无效，恢复时只信任外部已审批 ledger/变更单中的 digest。备份中的 env、dump 和 binary 均按 secret 保管。

## migration 4

migration 只能向前。使用独立 migration role，不得使用 application role 执行 DDL。首次部署和既有 role 重跑都必须先由 cluster admin 执行以下准备；不得依赖 `migrate.sh` 自动产生 bootstrap 到 migration role 的 membership：

```bash
set -Eeuo pipefail
set +x
export PGSERVICEFILE=/run/secrets/uclaw-activation/pg_service.conf
export PGPASSFILE=/run/secrets/uclaw-activation/pgpass
BOOTSTRAP_ROLE_FILE=/run/secrets/uclaw-activation/bootstrap-role
MIGRATION_ROLE_FILE=/run/secrets/uclaw-activation/migration-role
APP_ROLE_FILE=/run/secrets/uclaw-activation/app-role
for secret_file in "$PGSERVICEFILE" "$PGPASSFILE" "$BOOTSTRAP_ROLE_FILE" "$MIGRATION_ROLE_FILE" "$APP_ROLE_FILE"; do
  test -f "$secret_file"
  test ! -L "$secret_file"
  test "$(stat -c '%u:%a' "$secret_file")" = '0:600'
done
export ACTIVATION_BOOTSTRAP_ROLE="$(<"$BOOTSTRAP_ROLE_FILE")"
export ACTIVATION_MIGRATION_ROLE="$(<"$MIGRATION_ROLE_FILE")"
export ACTIVATION_APP_ROLE="$(<"$APP_ROLE_FILE")"

psql --dbname='service=uclaw_cluster_admin' -X --set=ON_ERROR_STOP=1 <<'SQL'
\getenv bootstrap_role ACTIVATION_BOOTSTRAP_ROLE
\getenv migration_role ACTIVATION_MIGRATION_ROLE
\getenv app_role ACTIVATION_APP_ROLE
BEGIN;
SELECT format('CREATE ROLE %I LOGIN NOSUPERUSER NOCREATEDB CREATEROLE NOINHERIT NOREPLICATION', :'bootstrap_role')
WHERE NOT EXISTS (SELECT FROM pg_roles WHERE rolname = :'bootstrap_role') \gexec
SELECT format('ALTER ROLE %I LOGIN NOSUPERUSER NOCREATEDB CREATEROLE NOINHERIT NOREPLICATION', :'bootstrap_role') \gexec
SELECT format('CREATE ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION', :'migration_role')
WHERE NOT EXISTS (SELECT FROM pg_roles WHERE rolname = :'migration_role') \gexec
SELECT format('ALTER ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION', :'migration_role') \gexec
SELECT format('CREATE ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION', :'app_role')
WHERE NOT EXISTS (SELECT FROM pg_roles WHERE rolname = :'app_role') \gexec
SELECT format('ALTER ROLE %I LOGIN NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT NOREPLICATION', :'app_role') \gexec
SELECT format('GRANT %I TO %I WITH ADMIN OPTION', :'migration_role', :'bootstrap_role') \gexec
SELECT format('REVOKE %I FROM %I', :'migration_role', :'app_role') \gexec
SELECT format('ALTER DATABASE %I OWNER TO %I', current_database(), :'bootstrap_role') \gexec
SELECT format('ALTER SCHEMA public OWNER TO %I', :'bootstrap_role') \gexec
SELECT format(
  CASE c.relkind
    WHEN 'r' THEN 'ALTER TABLE %I.%I OWNER TO %I'
    WHEN 'p' THEN 'ALTER TABLE %I.%I OWNER TO %I'
    WHEN 'S' THEN 'ALTER SEQUENCE %I.%I OWNER TO %I'
    WHEN 'v' THEN 'ALTER VIEW %I.%I OWNER TO %I'
    WHEN 'm' THEN 'ALTER MATERIALIZED VIEW %I.%I OWNER TO %I'
    WHEN 'f' THEN 'ALTER FOREIGN TABLE %I.%I OWNER TO %I'
  END,
  n.nspname, c.relname, :'bootstrap_role'
)
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'public' AND c.relkind IN ('r', 'p', 'S', 'v', 'm', 'f')
\gexec
COMMIT;
SQL
```

`uclaw_cluster_admin` 只用于该预处理。它必须有权创建/修改三个 role，并把目标 database、`public` schema 和现有 relation ownership 转给 bootstrap；运行后立即撤销会话。PostgreSQL 16+ 将 role membership 的 `SET`、`INHERIT`、`ADMIN` 拆成独立 membership option，旧版本语义不同；DBA 必须按生产 `server_version_num` 确认上述 grant 保留 `SET TRUE`，且仅 bootstrap 对 migration role 持有必要的 `ADMIN OPTION`。bootstrap 固定 `CREATEROLE`，但不是 superuser/database creator/replication role；migration 和 app 均固定 `NOCREATEROLE`，app 不得成为 migration member。

然后从 root-only 文件读取凭据。正式执行前用 bootstrap connection 核对 database/schema/现有 relation ownership、membership/Admin 边界，并在事务内实际成功执行 `SET LOCAL ROLE` 后回滚 preflight：

```bash
set -Eeuo pipefail
set +x
on_migration_error() {
  local exit_code=$?
  printf 'migration failed at line %s with status %s\n' "$LINENO" "$exit_code" >&2
  exit "$exit_code"
}
cleanup_migration_environment() {
  unset ACTIVATION_DATABASE_URL ACTIVATION_MIGRATION_ROLE ACTIVATION_MIGRATION_PASSWORD
  unset ACTIVATION_APP_ROLE ACTIVATION_APP_PASSWORD PGSERVICEFILE PGPASSFILE PGOPTIONS
}
trap on_migration_error ERR
trap cleanup_migration_environment EXIT

export PGSERVICEFILE=/run/secrets/uclaw-activation/pg_service.conf
export PGPASSFILE=/run/secrets/uclaw-activation/pgpass
MIGRATION_ROLE_FILE=/run/secrets/uclaw-activation/migration-role
MIGRATION_PASSWORD_FILE=/run/secrets/uclaw-activation/migration-password
APP_ROLE_FILE=/run/secrets/uclaw-activation/app-role
APP_PASSWORD_FILE=/run/secrets/uclaw-activation/app-password
BOOTSTRAP_ROLE_FILE=/run/secrets/uclaw-activation/bootstrap-role
for secret_file in "$PGSERVICEFILE" "$PGPASSFILE" "$BOOTSTRAP_ROLE_FILE" "$MIGRATION_ROLE_FILE" "$MIGRATION_PASSWORD_FILE" "$APP_ROLE_FILE" "$APP_PASSWORD_FILE"; do
  test -f "$secret_file"
  test ! -L "$secret_file"
  test "$(stat -c '%u:%a' "$secret_file")" = '0:600'
done

export ACTIVATION_DATABASE_URL='service=uclaw_bootstrap_admin'
export PGOPTIONS='-c log_statement=none -c log_min_error_statement=panic -c log_parameter_max_length=0'
export ACTIVATION_MIGRATION_ROLE="$(<"$MIGRATION_ROLE_FILE")"
export ACTIVATION_MIGRATION_PASSWORD="$(<"$MIGRATION_PASSWORD_FILE")"
export ACTIVATION_APP_ROLE="$(<"$APP_ROLE_FILE")"
export ACTIVATION_APP_PASSWORD="$(<"$APP_PASSWORD_FILE")"
test "$(psql --dbname='service=uclaw_bootstrap_admin' -X -Atc 'SELECT current_user')" = "$(<"$BOOTSTRAP_ROLE_FILE")"
psql --dbname='service=uclaw_bootstrap_admin' -X --set=ON_ERROR_STOP=1 \
  --set=migration_role="$ACTIVATION_MIGRATION_ROLE" \
  --set=app_role="$ACTIVATION_APP_ROLE" <<'SQL'
SELECT current_setting('server_version_num')::integer AS server_version_num \gset
SELECT (
  (SELECT NOT rolsuper AND NOT rolcreatedb AND rolcreaterole AND NOT rolreplication
   FROM pg_roles WHERE rolname = current_user)
  AND (SELECT count(*) = 2 AND bool_and(NOT rolcreaterole AND NOT rolsuper AND NOT rolcreatedb AND NOT rolreplication)
       FROM pg_roles WHERE rolname IN (:'migration_role', :'app_role'))
  AND pg_has_role(current_user, :'migration_role', 'MEMBER')
  AND EXISTS (
    SELECT 1 FROM pg_auth_members
    WHERE roleid = :'migration_role'::regrole AND member = current_user::regrole AND admin_option
  )
  AND (SELECT pg_get_userbyid(datdba) = current_user FROM pg_database WHERE datname = current_database())
  AND (SELECT pg_get_userbyid(nspowner) = current_user FROM pg_namespace WHERE nspname = 'public')
  AND NOT EXISTS (
    SELECT 1 FROM pg_class c JOIN pg_namespace n ON n.oid = c.relnamespace
    WHERE n.nspname = 'public' AND c.relkind IN ('r', 'p', 'S', 'v', 'm', 'f')
      AND pg_get_userbyid(c.relowner) <> current_user
  )
  AND NOT pg_has_role(:'app_role', :'migration_role', 'MEMBER')
) AS bootstrap_preflight_ok \gset
\if :bootstrap_preflight_ok
\else
  \echo 'bootstrap role, membership, ADMIN boundary, or ownership preflight failed'
  \quit 2
\endif
\echo 'validated PostgreSQL server_version_num=' :server_version_num
BEGIN;
SELECT format('SET LOCAL ROLE %I', :'migration_role') \gexec
SELECT current_user = :'migration_role' AS set_local_role_ok \gset
\if :set_local_role_ok
\else
  \echo 'SET LOCAL ROLE preflight failed'
  \quit 2
\endif
ROLLBACK;
SQL
"$RELEASE_DIR/deploy/migrate.sh"
```

`pg_service.conf` 的 `[uclaw_bootstrap_admin]` 是专用 bootstrap 管理连接，不是 migration/application runtime role。preflight 中任一布尔值不是 `t`、role 行数不完整、`SET LOCAL ROLE` 失败、当前 database/schema/relation owner 不正确，或生产 PG 版本下 membership 不允许 `SET ROLE` 时，禁止运行 migrator。`migrate.sh` 可以创建缺失 role 作为防御，但授权闭环不能依赖该行为；cluster admin 必须预先覆盖既有 role、显式 membership/ADMIN 边界和 ownership 转移。脚本随后以 bootstrap 修正两个 runtime role，在内部 `SET ROLE` 到 migration role 执行 migration，最后 `RESET ROLE` 完成 grants/验证。`PGOPTIONS` 在该 session 关闭 statement/parameter 日志，避免脚本中 role password DDL 进入 PostgreSQL 标准日志。部署前必须在隔离环境确认托管平台或 `pgaudit` 不会另行记录密码 DDL；无法保证时停止，不得以“先迁移后删日志”代替预防。

验证 ledger、relation 和权限：

```sql
SELECT version, encode(checksum, 'hex') FROM schema_migrations ORDER BY version;
SELECT to_regclass('public.device_access_tokens');
SELECT to_regclass('public.model_proxy_admissions');
```

预期 ledger 为 1-4，两个 relation 存在。再用 application role 读 ledger，并确认它无法更改 ledger 或创建 table/schema。migration 4 只增加 table、column、constraint 和 index，不破坏旧 binary；回滚 binary 时保留 schema 和新数据。不得删除 migration 4 对象，不得从 ledger 删除 version 4，不得运行旧 binary 携带的旧 migrator。旧 binary 回滚只复用当前新 migrator 做读取验证，或显式跳过 migration。

### DNS 和 registry 门禁

必须先由 registry/RDAP 确认域状态中不再有 `clientHold`，再验证权威 DNS。运行：

```sh
curl -fsSL https://rdap.org/domain/yiyong.me | jq -r '.status[]'
dig +short license.yiyong.me A

```

预期：RDAP 输出不包含 `client hold`、`clientHold` 或等价 hold 状态；A 记录只包含 `121.41.89.103`；AAAA 为空，除非 VPS 已审批并验证 IPv6 入口。当前 2026-08-14 盘点的 A/AAAA 均为空，因此域名切换仍是未满足门禁。

### Caddy 路由与自动证书

先备份 Caddyfile。新配置必须将公网路由做 allowlist：只有 `/v1/*`、`/model-api/*`、`/health/ready` 反向代理到 `127.0.0.1:18081` 和 `127.0.0.1:18082`；`/internal/*`、`/metrics`、管理 API 和所有其他路径返回 404。不得对公网监听管理端口。

`license.yiyong.me` 站点不写 `tls` 证书文件，由 Caddy ACME 自动签发和续期。`https://121.41.89.103` 站点保留现有已验证的 IP TLS 配置，不得用域名证书代替 IP compatibility certificate。当前 systemd 拓扑使用以下 allowlist 结构：

```caddyfile
{

(public_routes) {
	@public path /v1/* /model-api/* /health/ready
	handle @public {
```

`TXN_ID` 由变更系统生成且本次唯一；临时 tag 固定为 `uclaw-activation-endpoint-$TXN_ID`。本事务创建带随机 nonce 的唯一 annotated tag，并在 push 前保存本地 tag object OID。push 使用 `--force-with-lease=refs/tags/$TXN_TAG:` 的 absent lease，只允许创建不存在的 ref，不允许覆盖预存或竞态 tag。即使 push 响应丢失，cleanup 也只在远端 ref 的 tag object OID 精确等于本事务记录的 annotated object OID 时，使用该 OID 的 lease 删除；预存 tag、不同 object OID 或 ownership 不确定时固定报错、fail closed、转人工，绝不删除。peeled commit SHA 只验证执行目标，不作为 ownership 证明。

当前 `.github/workflows/portable-launcher.yml` 可在 tag ref 运行：它包含无 branch 限制的 `workflow_dispatch`，job 不按 branch/ref 过滤，`actions/checkout` 使用事件 ref。审批人必须先审计该性质，并把目标 SHA 上 workflow 文件的 SHA-256 写入变更单；脚本在改全局 variable 前下载该文件并核对 `EXPECTED_PORTABLE_WORKFLOW_SHA256`。workflow 不满足 tag 运行条件、digest 不匹配、tag 已存在或无法证明 annotated tag object 由本事务拥有且 peeled commit 精确为 `RELEASE_GIT_SHA` 时立即阻断，不得修改全局 variable。

事务只按唯一 `headBranch=$TXN_TAG` 和已审批 `headSha` 捕获 run，不再用同 SHA 或 dispatch 时间窗猜测。多个候选、超时、artifact 缺失、tag 删除失败或任何命令失败时均 fail closed：EXIT trap 恢复旧 variable，并删除远端和本地临时 tag；任一恢复/删除失败也返回非零并升级人工处置。只有指定 `databaseId` 的 `watch`、tag、`headSha`、workflow name、完成状态、结论和唯一未过期 `portable-launcher-diagnostics` artifact 全部通过，且远端/本地临时 tag 均已确认删除，才把新 variable 标为 committed。当前 workflow 只上传脱敏 diagnostics，不上传正式 Launcher binary，因此不得把该 artifact 误当成可发布制品。新正式 binary 仍必须从同一 SHA 进入签名/公证流水线，并重做 SHA-256、Win10/11 普通用户、Defender、物理 U 盘、正常激活和首次模型请求验收后才可发布。事务失败时继续服务上一已签名、已验收的旧 endpoint 发行物，禁止就地修改已签名 binary。

旧 IP HTTPS endpoint 自域名切换日起至少保留一个完整发行周期。移除前必须证明受支持客户端全部已迁移，且回滚不再依赖 IP。

```bash
journalctl -u uclaw-activation@18081 -u uclaw-activation@18082 --since '30 minutes ago' --no-pager > "$JOURNAL_SCAN_FILE"
history -a "$HISTFILE"
scan_without_echoing_secret "$HISTFILE"
scan_without_echoing_secret /root /var/log
scan_without_echoing_secret --glob '!new-api-key.import' "$NEW_API_IMPORT_DIR"
scan_without_echoing_secret --glob '!new-api-import-*/new-api-key.import' "$NEW_API_IMPORT_ROOT"
cleanup_mapping_secrets
trap - EXIT
if compgen -G '/run/secrets/uclaw-activation/new-api-import-*' >/dev/null; then
  printf 'New API import directory residue found\n' >&2
  exit 2
fi
test ! -e /run/secrets/uclaw-activation/new-api-key.import
test ! -e /run/secrets/uclaw-activation/new-api-key.journal-scan

closure_record="$(jq -cn --arg rotation "$ROTATION_ID" --arg inventory "$INVENTORY_ID" \
  --arg identity "$EXPECTED_KEY_IDENTITY" --arg operation "$CLOSURE_OPERATION_ID" \
  --arg key_version "$EXPECTED_API_KEY_VERSION" \
  '{state:"committed",rotationId:$rotation,inventoryId:$inventory,keyIdentity:$identity,operationId:$operation,apiKeyVersion:$key_version}')"
exec {rotation_ledger_fd}>>"$ROTATION_LEDGER"
flock -x "$rotation_ledger_fd"
existing_closure_count="$(jq -s --arg rotation "$ROTATION_ID" --arg inventory "$INVENTORY_ID" \
  '[.[] | select(.rotationId == $rotation and .inventoryId == $inventory and .state == "committed")] | length' \
  "$ROTATION_LEDGER")"
case "$existing_closure_count" in
  0) printf '%s\n' "$closure_record" >&"$rotation_ledger_fd" ;;
  1) jq -es --argjson record "$closure_record" '
       [.[] | select(.rotationId == $record.rotationId and .inventoryId == $record.inventoryId and .state == "committed")] == [$record]
     ' "$ROTATION_LEDGER" >/dev/null ;;
  *) printf 'duplicate committed rotation closure records found\n' >&2; exit 2 ;;
esac
flock -u "$rotation_ledger_fd"
exec {rotation_ledger_fd}>&-
```

批准 identity manifest 是 root `0600` JSON，至少包含唯一的 `rotationId/inventoryId/identityScheme/expectedIdentity/operationId/apiKeyVersion`。优先使用 New API 官方提供、能从输入 key 离线导出且经过审批的 upstream key ID；当前没有这类已验证工具时固定使用 `hmac-sha256-v1`。HMAC key 与 New API Key 独立，至少 32 bytes，只存在 root `0600` 文件；Python argv 只有文件路径，key/HMAC key 不进入 argv、environment、stdout 或日志。批准 manifest 必须在安全工作站用同一规范化规则（仅去掉一个结尾 LF）预计算，运行时从实际输入 key 重算并精确比较。无法建立 identity、manifest 不唯一或 identity 不匹配时，`mapping set` 不会执行。

`mapping show` 真实输出包含 inventory/user 标识、base URL host、model/policy、KMS key version、status 和 updated time；它不输出 New API Key identity。脚本只用它确认批准的 `apiKeyVersion`。只有 history、journal、`/root`、`/var/log`、import/runtime 目录的不回显 secret scan 全部成功，Bash memory history 已清空，key 输入文件和受控目录已成功删除且无残留后，才向外部 root `0600`、filesystem append-only rotation ledger 追加 `state="committed"` closure。失败路径不得产生 committed closure；若另行写 provisional 记录，最终撤旧验证也必须忽略它。`rg` 的 `0/1/其他` 分别代表命中/无命中/扫描失败；任一清理/扫描失败均 fail closed。

## 验收矩阵

所有证据只记录时间、git SHA、binary checksum、request/support ID、HTTP status 和脱敏摘要。

1. 公网路由：`/v1/*`、`/model-api/*`、`/health/ready` 按契约响应；`/internal/*`、`/metrics`、管理 API 和未知路径必须为 404。用 `ss -lntp` 确认无公网 admin/management 端口。
2. 代理负向：无 bearer、随机 bearer、revoked bearer 均为一致的 401；不允许模型为 403；超限为 429；上游不可用为脱敏 502/503。response 不得包含 New API hostname 之外的内部地址、key、token 或完整 prompt。
3. 激活：错误激活码为 `ACTIVATION_INVALID`；正确测试库存绑定后无 username/expiry；二次同幂等恢复返回同一 device/license/token。客户端 `builtin-model-credential.v1.json` mode 为 `0600`，endpoint 为预期公共代理地址。
4. revoke/reissue：测试 device token revoke 后立即 401；reissue 只产生一个 active token，旧 token 永久失效，新 token 只写 root-only output 文件。细节见 [激活服务故障处理](./激活服务故障处理.md)。
5. admission：两实例共用 PostgreSQL lease。一个请求逾期后，下次同 token admission 自动清理 expired lease，无需人工 SQL；十分钟以前的记录也由请求路径限量清理。
6. kill-one：先保持持续 health 和代理鉴权流量，再依次 `systemctl stop uclaw-activation@18081`、验证 18082 接管、恢复 18081；然后对 18082 重复。禁止同时 stop 两个实例。
7. New API Key rotation canary：先 set 新 envelope，通过单个专用测试库存/设备做 models 和最小 chat canary，再扩大。只有 canary 和观察通过后才可在 New API 撤销旧 key。见 [激活服务密钥轮换](./激活服务密钥轮换.md)。

## binary/config 回滚

回滚触发条件：激活回归、敏感信息泄漏、migration ledger/checksum 不一致、双实例无法 ready、公网私有路由可访问或域名证书故障无法在观察窗内恢复。

配置、unit、Caddy 和 release 切换必须作为完整 root Bash 块执行：

```bash
set -Eeuo pipefail
trap 'exit_code=$?; printf "rollback preparation failed at line %s with status %s\\n" "$LINENO" "$exit_code" >&2; exit "$exit_code"' ERR
: "${BACKUP_UTC:?BACKUP_UTC is required}"
: "${PREVIOUS_RELEASE_GIT_SHA:?PREVIOUS_RELEASE_GIT_SHA is required}"
[[ "$BACKUP_UTC" =~ ^[0-9]{8}T[0-9]{6}Z$ ]]
[[ "$PREVIOUS_RELEASE_GIT_SHA" =~ ^[0-9a-f]{40}$ ]]

PREVIOUS_RELEASE_DIR="/opt/uclaw-activation/releases/$PREVIOUS_RELEASE_GIT_SHA"

test "$(basename -- "$BACKUP_DIR")" = "$BACKUP_UTC"
test "$(basename -- "$PREVIOUS_RELEASE_DIR")" = "$PREVIOUS_RELEASE_GIT_SHA"
test -d "$BACKUP_DIR"
test -f "$BACKUP_LEDGER"
test ! -L "$BACKUP_LEDGER"
test "$(stat -c '%u:%a' "$BACKUP_LEDGER")" = '0:600'

  $1 == backup_utc { count++; record=$0 }
```

1. 停止新发布和管理写操作，保留 request ID 和脱敏日志。
2. 从外部 root `0600`、非 symlink、filesystem append-only 的 `backup-manifests.log` 读取该 `$BACKUP_UTC` 唯一审批记录。先用其中 `manifest=` 校验 `SHA256SUMS` 自身 digest，再执行 `sha256sum --check --strict`，并额外核对 `dump=` 与上一 release binary。全部通过后才允许安装 env、unit、Caddy 配置并切换 binary。禁止信任备份目录内另存的 digest、临时计算值或同目录审批副本来自证。

7. 重做 public allowlist、负向代理、health、kill-one 和 secret scan。

## 域名、证书和 DNS 回滚

- 证书签发失败：保持 IP HTTPS 服务和旧发行配置，不切 `PUBLIC_MODEL_ENDPOINT`；恢复 A/AAAA、80/443 入站、Caddy 存储权限、ACME 限额或系统时钟后重试。不关闭 TLS 校验。
- DNS 错指或不稳定：将 A 恢复为上一已验证值，删除未验证 AAAA，保持 Caddy 两个站点。使用权威和多个公共 resolver 监测 TTL 收敛。
- 域名已切但必须恢复 IP endpoint：将 GitHub Actions `vars.UCLAW_ACTIVATION_ENDPOINT` 改回 `https://121.41.89.103/`，回退上一已签名、已验收的 IP endpoint 发行物；将 `/etc/uclaw-activation.env` 的 `PUBLIC_MODEL_ENDPOINT` 改回 `https://121.41.89.103/model-api/`，滚动重启后用全新测试库存确认新 `builtinCredential.endpoint` 为 IP 值。不就地修改已签名 binary。

已签发的 builtin credential 内含当时 endpoint，修改服务 env 不会追溯改写客户端文件。因此域名 DNS 回滚后仍要尽量保持域名站点可用；无法保持时，必须通过已审批的客户端凭据恢复/重发流程更新 endpoint，不得只轮换 device token 并假定 endpoint 已改变。
