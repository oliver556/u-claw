# Bavi-box 客户端色彩规范

> 文档状态：已确认
>
> 确认日期：2026-08-07
>
> 适用范围：Bavi-box Windows Electron 客户端
>
> 色彩基线：Ant Design 5 默认蓝色体系

## 1. 设计结论

Bavi-box 使用 Ant Design 默认蓝色作为品牌基线，建立适合长期使用桌面工具的亮色和暗色语义色。

- 品牌主色保持 `#1677FF`。
- 企业产品用色保持克制，蓝色只承担操作、选中、焦点、链接和信息状态。
- 窗口、侧栏、工作画布和浮层主要使用中性色建立层级。
- U 盘、Gateway、工具调用和更新状态使用明确功能色，不能全部使用品牌蓝色。
- 亮色与暗色共享同一套语义 token，业务组件禁止直接写 Hex、RGB 或固定透明色。
- 当前开发先实现亮色主题。全部产品功能完成后，再按本规范实现和验收暗色主题。

## 2. 官方基线

Ant Design 将颜色分为系统级色彩和产品级色彩。Bavi-box 采用其默认 Seed Token：

| Token | 值 | 用途 |
| --- | --- | --- |
| `colorPrimary` | `#1677FF` | 品牌、主操作、选中、焦点 |
| `colorInfo` | `#1677FF` | 启动、同步、处理中 |
| `colorSuccess` | `#52C41A` | 成功、在线、已完成 |
| `colorWarning` | `#FAAD14` | 警告、降级、需要注意 |
| `colorError` | `#FF4D4F` | 错误、断开、危险操作 |
| `colorBgBase` | `#FFFFFF` | 亮色背景派生基础 |
| `colorTextBase` | `#000000` | 亮色文本派生基础 |

官方参考：<https://ant.design/docs/spec/colors-cn>

## 5. 产品状态映射

同一状态在所有页面必须使用相同语义，不能由组件自行选择颜色。

| 产品状态 | 颜色语义 | 示例 |
| --- | --- | --- |
| 正常、在线、已落盘、工具成功 | Success | U 盘在线、Gateway 正常、数据已写入 |
| 启动、同步、连接、工具运行中 | Info | Gateway 启动中、模型连接中 |
| 降级、等待授权、空间不足 | Warning | U 盘空间偏低、渠道需要重新登录 |
| 断开、写入失败、工具失败 | Error | U 盘失联、Gateway 崩溃 |
| 未启用、未配置、空闲 | Neutral | 未配置渠道、未启用技能 |

状态不能只依赖颜色表达。必须同时提供图标、文字或形状，满足色觉障碍用户使用。

## 6. 界面区域应用

### 6.1 自定义标题栏

- 标题栏和侧栏使用同一背景，形成完整桌面外壳。
- 标题栏不得使用大面积品牌蓝色。
- Windows 最小化、最大化和关闭按钮保持原生语义；关闭按钮悬停遵循 Windows 危险色表现。
- U 盘、Gateway 和当前模型使用文字加状态图标，不使用大色块。

### 6.2 导航和会话列表

- 默认透明背景，悬停使用 `--uclaw-bg-hover`。
- 当前项使用 `--uclaw-bg-selected`，图标和关键文字使用 `--uclaw-primary-text`。
- 不使用左侧蓝色粗竖线与蓝底同时强调。

### 6.3 工作画布和输入区

- 工作画布保持中性，长时间阅读区域不染蓝。
- 用户消息、Agent 消息和工具结果主要通过布局、间距和边界区分。
- 输入区使用清晰边框；聚焦后显示品牌色边框和焦点环。
- 代码块使用独立中性表面，不跟随品牌蓝色。

### 6.4 工具、附件和任务产物

- 运行阶段使用信息色，成功或失败后切换为对应功能色。
- 状态色只用于图标、短标签、进度和关键边界。
- 参数、日志和结果正文仍使用中性色，防止高饱和信息干扰阅读。

## 7. 使用限制

禁止以下做法：

- 在业务组件中直接写 `#1677FF` 或其他固定颜色。
- 使用蓝色渐变、蓝色发光和大面积深蓝背景。
- 用品牌蓝同时表达成功、警告和失败。
- 用颜色作为状态的唯一表达方式。
- 为不同功能页面发明新的灰色或状态色。
- 暗色主题直接使用 CSS `filter`、颜色反转或亮色值整体降低亮度。
- 在暗色功能尚未实现时展示无效主题切换按钮。

## 8. 技术落地约束

主题实现分为两层：

1. Ant Design `ConfigProvider` 提供组件级 Seed Token 和主题算法。
2. Bavi-box CSS variables 提供产品级语义 token，覆盖 Electron 外壳和非 Ant Design 组件。

亮色使用：

```ts
theme.defaultAlgorithm
```

暗色使用：

```ts
theme.darkAlgorithm
```

组件只能通过 Ant Design `useToken()` 或 `--uclaw-*` 变量消费颜色。主题模式最终由统一 Theme Provider 管理，禁止页面局部维护自己的亮暗状态。

## 9. 实施顺序

### 9.1 当前实施

1. 建立亮色和暗色 token 文件。
2. 在主题模块内完成 Ant Design Token 到 Bavi-box 语义 token 的映射。
3. 客户端第一阶段和第二阶段功能全部使用语义 token。
4. 当前只启用和验收亮色主题。

### 9.2 全部功能完成后

1. 启用 `theme.darkAlgorithm`。
2. 接入已冻结的暗色语义 token。
3. 逐页检查工作区、设置、弹窗、菜单、工具状态、图表、Markdown 和代码块。
4. 完成键盘焦点、Windows 窗口控件和系统通知的暗色验证。
5. 全部通过后才向用户开放主题切换。

该顺序保证当前开发不会因暂缓暗色实现而产生固定色值债务。

## 10. 验收标准

- 代码扫描不存在主题文件以外的固定业务色值。
- 亮色和暗色正文对比度满足 WCAG AA，普通文本不低于 `4.5:1`。
- 焦点环在两种主题下清晰可见。
- 状态均包含颜色以外的文字或图标表达。
- Windows 100%、125%、150% 缩放下颜色边界和焦点状态清晰。
- 亮暗切换后没有白闪、透明叠层错误或不可读代码块。
- Electron 标题栏、Ant Design 组件和自建组件使用同一主题语义。
