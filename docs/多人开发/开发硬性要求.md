# U-Claw 多人开发硬性要求

更新时间：2026-08-22

本文档用于冻结当前 P0 验证成果，并约束多人并行开发边界。所有开发者开始改代码前必须先读完本文档。

## 0. 目录定义

`<repo>` 指本项目仓库根目录，不是某个子目录。

小李总当前机器示例：

```txt
/Users/jamison/Document/300_学习/320_code/390_ai_agent/u-claw
```

当前仓库根目录下有两个旧目录必须只读：

```txt
<repo>/u-claw-app
<repo>/product
```

目录含义：

1. `<repo>/u-claw-app`：已归档原版 OpenClaw Electron 桌面壳，禁止直接修改。
2. `<repo>/product`：之前版本的 U-Claw 产品工程，当前不作为本轮开发对象，禁止直接修改。
3. `<repo>/u-claw-app-dev`：本轮正式开发目录。该目录需要从 `<repo>/u-claw-app` 复制创建，目前如果不存在，属于正常状态。

本轮开发结论：

```txt
不改 <repo>/u-claw-app。
不改 <repo>/product。
从 <repo>/u-claw-app 复制出 <repo>/u-claw-app-dev。
后续 UI、模型链路、打包，都在 <repo>/u-claw-app-dev 内完成。
```

## 1. 项目总原则

1. 第一目标：复用 OpenClaw 原版能力，不重写智能体能力。
2. U-Claw 只做 UI、配置、包装、入口、便携化。
3. 没有 OpenClaw 原版 `method/event/CLI/config` 支撑的能力，一律不开发。
4. 不允许写“看起来能用”的残血版功能。
5. 不允许为了 UI 效果绕过 OpenClaw 原能力链路。
6. 能用配置解决，不改源码。
7. 能用中转站或模型/API adapter 解决，不改 OpenClaw。
8. 必须改 OpenClaw 前端时，只做最小补丁，并记录原因、文件、验证方式。

## 2. 当前 P0 Baseline

当前 P0 已验证：

1. Mac U 盘启动 OK。
2. Windows U 盘启动 OK。
3. 文本对话 OK。
4. 图片生成基本 OK。
5. 视频问题已定位：New API/xAI 协议适配 + 上游并发限制。

以上作为 `P0 baseline`。任何改动不得破坏这些结果。

如果改动后出现下列问题，必须先停下，不继续叠功能：

1. App 打不开。
2. Gateway 起不来。
3. 文本对话失效。
4. U 盘数据路径失效。
5. Mac/Win 任一平台启动失效。
6. 打包产物依赖宿主机 Node/Python/npm。

## 5. 原版能力矩阵先行

每个功能必须先进入矩阵，再开发。

矩阵字段：

```txt
OpenClaw 原能力
U-Claw UI 入口
权威调用方式
配置来源
当前状态
验证命令/截图
风险
备注
```

状态只能是：

```txt
OK
Blocked
Unknown
Do Not Build
```

状态规则：

1. `OK`：已验证，可进入 UI。
2. `Blocked`：有明确卡点，不进 UI。
3. `Unknown`：未确认权威调用方式，不开发。
4. `Do Not Build`：不投入时间。

硬规则：

1. 没有 OpenClaw 原版 `method/event/CLI/config`，不开发。
2. 不知道权威调用方式，不开发。
3. `Unknown` 不开发。
4. `Blocked` 不进 UI。
5. 不允许先做假 UI 再补能力。

## 8. 禁止把运行目录当源码

禁止把 U 盘运行目录、用户缓存目录、Windows 本地缓存目录当源码。

当前 U 盘便携运行采用宿主机缓存策略：

```txt
U 盘保存打包产物和 data 源。
启动时复制/解压到宿主机缓存。
App 从宿主机缓存运行。
运行期高频读写发生在宿主机缓存。
退出后再把 data 同步回 U 盘。
```

目的：

```txt
减少 U 盘高频读写。
提高启动和运行速度。
降低 ExFAT 文件锁、权限、随机读写性能问题。
```

这些目录只用于验证/临时排查，不能作为源码修改位置：

```txt
Mac U 盘运行目录：
<U盘挂载点>/U-Claw

Mac 本机运行缓存：
~/Library/Caches/U-Claw/u-claw-app-mac-arm64

Windows 本机运行缓存：
%LOCALAPPDATA%\U-Claw\usb-portable
```

小李总当前机器示例：

```txt
Mac U 盘运行目录：
/Volumes/UCLAW_10/U-Claw

Mac 本机运行缓存：
/Users/jamison/Library/Caches/U-Claw/u-claw-app-mac-arm64
```

规则：

1. 禁止把 `<U盘挂载点>/U-Claw` 当源码目录。
2. 禁止只改缓存目录后说“修好了”。
3. 禁止不重打包就交付。
4. 缓存目录改动只能用于验证，不算正式修复。
5. 正式修复必须回写到 `<repo>/u-claw-app-dev`，再打包。
6. 不得让 OpenClaw 直接长期高频读写 U 盘。
7. 运行读写优先宿主机缓存，U 盘作为便携源和最终同步目标。

## 14. 视频链路当前冻结结论

当前视频链路问题不在 U 盘打包。

已确认：

```txt
OpenClaw xAI provider 请求：
POST /v1/videos/generations
GET  /v1/videos/{request_id}

New API 原生视频接口：
POST /v1/video/generations
GET  /v1/video/generations/{task_id}
```

当前处理方向：

```txt
OpenClaw 不改。
New API 前面加 New API/xAI 视频协议适配服务。
New API/xAI 视频协议适配服务负责路径转换、字段清洗、返回格式转换。
```

New API/xAI 视频协议适配服务当前职责：

```txt
/v1/videos/generations -> /v1/video/generations
task_id/id -> request_id
删除上游不接受的 duration 字段
/v1/videos/{id} -> /v1/video/generations/{id}
New API 状态 -> xAI 状态
视频 URL -> video.url
```

当前已定位额外问题：

```txt
上游视频账号存在并发上限。
New API 可能会自动失败重试或轮询任务。
验证阶段需要降低/关闭视频渠道重试，避免连续消耗。
```

UI 开发硬边界：

2. 能力入口必须绑定矩阵里的 OpenClaw 原能力或已确认权威调用方式。

6. 不允许为短期演示写假能力。
7. 原版已有交互，优先 1:1 承接，再做 U-Claw 样式。
8. UI 样式、布局、组件可以由 UI 负责人单独推进，不需要等模型链路负责人。
9. UI 负责人不得修改模型链路底座文件。
10. 模型链路负责人不得修改 UI 文件，除非先和 UI 负责人确认。

聊天页 Skill 下拉原则：

1. 聊天页可以增加 Skill 下拉作为快捷配置入口，但不能自造 chat-level skill 系统。
2. Skill 下拉应放在输入框工具栏，优先放在模型选择附近。
3. Skill 与模型都属于本次对话运行配置，视觉上应放在同一组。
4. 下拉展示的是用户可理解的 skill 名称，不要求用户记 skill ID。

## 17. Skill / SkillHub 原则

Skill 产品目标：

1. U-Claw 用户侧 skill 来源以 SkillHub 为准。
2. 原版 OpenClaw bundled skills 不面向用户展示。
3. 原版 OpenClaw bundled skills 可保留在底层，避免破坏运行时依赖。
4. 不允许为了“不展示原版 skill”而直接删除底层 bundled skills。
5. UI 层只展示 U-Claw 筛选后的 SkillHub skill。
6. 用户不需要记 skill ID 或 skill 文件名。
7. 用户应通过中文名称、分类、用途说明选择 skill。

Skill 技术边界：

1. 不允许自造 skill 执行器。
2. 不允许绕过 OpenClaw 原版 skill runtime。
3. 不允许因为聊天页要 Skill 下拉，就重写一套独立 chat-level skill 系统。
4. SkillHub skill 最终必须进入 OpenClaw 可识别的 skill 安装/绑定链路。
5. 如果 SkillHub skill 格式可被 OpenClaw 原版 runtime 读取，则直接安装到 OpenClaw skill 目录。
6. 如果 SkillHub skill 格式不同，只允许做格式转换/安装 adapter，不允许自造 runtime。
7. 无法被 OpenClaw 原版 runtime 识别的 SkillHub skill，状态标为 `Blocked`，不进入正式可用入口。

当前 OpenClaw 原版事实：

1. OpenClaw 原版聊天页没有“本次聊天选择 skill”的入口。
2. OpenClaw 原版 Skill 管理入口在独立 `Skills` 页和 `Agents -> Skills` 面板。
3. OpenClaw 原版 skill 更接近 Agent-level configuration，不是每条消息临时选择。

U-Claw Skill 下拉要求：

1. U-Claw 可以在聊天输入框增加 Skill 下拉。
2. Skill 下拉是快捷配置入口，不是新 runtime。
3. Skill 下拉底层必须修改/复用 Agent skills 配置。
4. Skill 下拉应放在输入框工具栏，优先放在模型选择附近。
5. Skill 与模型都属于本次对话运行配置，视觉上应放在同一组。
6. 下拉展示 SkillHub skill 的用户可读名称、分类、用途。
7. 原版 OpenClaw bundled skills 不出现在用户侧下拉中。
8. 原版 OpenClaw bundled skills 如为底层依赖，可保留在运行时目录。

Skill 下拉第一版建议语义：

```txt
选择 Skill
-> 修改当前会话对应 Agent 的 skills 配置
-> 或创建/切换到带该 skill 的 Agent/session
```

需要验证的问题：

```txt
SkillHub skill 包结构是什么。
SkillHub skill 能否直接被 OpenClaw 读取。
SkillHub skill 应安装到哪个目录。
Agent skills 引用 SkillHub skill 的 key 是什么。
修改 Agent skills 后，当前 session 是否立即生效。
是否需要刷新 session tools。
是否需要新开 session 才稳定生效。
```

第一版可接受策略：

```txt
Skill 选择后自动新建/切换一个带该 skill 的会话。
或提示用户该 Skill 从新会话开始生效。
```

权威调用方式优先参考原版 Agents 页面已有逻辑：

```txt
runtimeConfig.patchForm([`agents`, `list`, i, `skills`], ...)
runtimeConfig.save()
```

SkillHub 接入必须先完成格式审计：

```txt
SkillHub skill 包结构
OpenClaw skill 包结构
SKILL.md / metadata / install steps / env key / tool requirements
安装目录
Agent skills 引用方式
启停方式
```

## 18. 微信能力原则

1. 先确认 OpenClaw 原版微信能力是否存在。
2. 先确认入口、权限、登录态、消息收发、文件收发、异常处理。
3. 没有原版能力链路，不写替代版。
4. 微信能力不得影响文本/图片/视频主链路。

## 19. 协作纪律

1. 两个人不能同时改同一底座文件。
2. 每天先同步矩阵状态。
3. 遇到 gateway、打包、权限、portable data 问题，先停，不继续叠功能。
4. 所有临时绕路必须写进问题记录。
5. 不允许“先这样吧”但不记录。

建议问题记录文件：

```txt
<repo>/docs/多人开发/问题记录.md
```

建议验收记录文件：

```txt
<repo>/docs/多人开发/验收记录.md
```
