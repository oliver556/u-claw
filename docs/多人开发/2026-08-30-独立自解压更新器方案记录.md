# U-Claw 独立自解压更新器方案记录

日期：2026-08-30

## 背景

当前 `codex/hard-update-prep` 已有一套启动强制硬更新代码：

- 启动脚本在启动 Electron 前执行 `hard-update-client.js startup-update`。
- 有更新时写入 `app/update-transaction.json` 和 `app/.update-staging/`。
- 通过 `app/.runtime/update-shutdown-request.json` 请求正在运行的 U-Claw 退出。
- 再执行 `apply-startup-update` 替换程序层。

实测后决定：不再把大包硬更新放进启动链路。启动链路只负责启动、缓存解压、数据同步。更新链路改为独立自解压更新器。

## 总原则

1. 启动链路不做硬更新下载和替换。
2. 更新器是独立 exe，不依赖正在被替换的 `U-Claw/app`。
3. 更新只替换程序层，不覆盖用户数据。
4. `U-Claw/data` 永远保留。
5. Windows 文件锁优先处理：更新前必须让 U-Claw、gateway、node 子进程退出。
6. 本次发货先不在页面内提示更新。
7. 本次发货后，如需给客户更新，先人工发独立更新器包，让客户复制到 U 盘后运行。

## 本次发货策略

本次版本只保留：

- 启动修复。
- 默认关闭启动硬更新。
- 盘内数据路径污染修复。
- 必要的稳定性修复。

本次版本不做：

- 页面内版本检查提示。
- 点击后自动下载更新器。
- 点击后自动退出并拉起更新器。
- 后台静默更新。
- 强制更新阻断。

客户更新方式：

1. 给客户发送 `U-Claw-Updater-vX.Y.Z.exe` 或压缩包。
2. 客户把更新器复制到 U 盘 `U-Claw/` 根目录。
3. 客户关闭当前 U-Claw。
4. 客户双击更新器。
5. 更新器替换程序层，保留 `data/`。
6. 客户重新打开 `U-Claw Launcher.exe`。

## 后续目标交互

等当前主窗口问题解决、合并同事 `dev_1.0`、发货稳定后，再做页面内提示。

目标流程：

1. U-Claw 正常启动。
2. 后台轻量检查版本，不阻塞启动。
3. 有新版本时弹窗：

```txt
发现新版本 vX.Y.Z

更新需要关闭当前 U-Claw。
点击“立即更新”后，U-Claw 会自动退出，并启动更新程序。
你的会话、配置、数据不会被覆盖。
```

4. 按钮：

```txt
立即更新
稍后
```

5. 用户点击“立即更新”后：
   - 下载或定位独立更新器。
   - 写入更新 manifest。
   - 启动 `U-Claw-Updater-vX.Y.Z.exe`。
   - U-Claw 主程序主动退出。
6. 更新器等待主程序、gateway、node 子进程完全退出。
7. 更新器替换 `app/`、launcher、启动脚本。
8. 更新器提示完成，或自动重新打开 U-Claw。

## 更新器包形态

推荐文件名：

```txt
U-Claw-Updater-vX.Y.Z.exe
```

放置位置：

```txt
<USB>/U-Claw/U-Claw-Updater-vX.Y.Z.exe
```

更新器内部应自带：

- 目标版本程序层 payload。
- 版本 manifest。
- 文件 hash 清单。
- 签名信息。
- 更新执行逻辑。

更新器不能依赖：

- `<USB>/U-Claw/app` 内的 Node runtime。
- `<USB>/U-Claw/app` 内的 `hard-update-client.js`。
- 当前正在运行的 Electron app。

## 允许替换的路径

更新器只允许替换：

```txt
app/
U-Claw Launcher.exe
U-Claw Launcher.app
Mac-Start-App.command
Windows-Start-App.bat
Windows-Sync-Data.ps1
UCLAW-PACKAGE-NOTES.txt
```

后续若根目录清理完成，脚本可移动到：

```txt
app/scripts/Mac-Start-App.command
app/scripts/Windows-Start-App.bat
app/scripts/Windows-Sync-Data.ps1
```

根目录最终只保留用户入口：

```txt
U-Claw Launcher.exe
U-Claw Launcher.app
app/
data/
```

## 禁止替换的路径

更新器绝对禁止覆盖或删除：

```txt
data/
.openclaw/
openclaw.json
auth_profile_store/
auth-profile-store/
```

如需数据迁移，只能做显式、可回滚、带备份的迁移脚本。

## 可复用现有代码

可以复用：

- `scripts/hard-update-client.js` 的检查、下载、验签、manifest 解析逻辑。
- `scripts/lib/hard-update-utils.js` 的 hash、zip、路径安全校验逻辑。
- `scripts/updater/main.go` 的程序层替换和禁止覆盖 `data/` 的安全模型。
- `hard-update-control-plane-server.js` 的版本检查协议。
- R2 发布脚本中的发布、签名、生产 manifest 机制。

需要改造：

- `scripts/updater/main.go` 从“事务应用器”升级为“独立自解压更新器”。
- payload 直接打进 updater exe，或 updater exe 同目录携带 payload 包。
- updater 自己完成解压、校验、替换、回滚、日志输出。
- 主程序后续只做提示、拉起 updater、主动退出。

需要废弃或停用：

- 启动脚本默认执行 `startup-update`。
- 启动时下载大包。
- 启动时卡住等待硬更新。
- 更新失败导致 U-Claw 启动失败。

## 日志与回滚

更新器日志建议写：

```txt
<USB>/U-Claw/data/logs/U-Claw-Updater.log
```

每次更新前备份程序层：

```txt
<USB>/U-Claw/app/.update-backup/<transaction-id>/
```

更新失败时：

1. 写失败状态。
2. 尝试恢复备份。
3. 保留日志。
4. 不删除 `data/`。
5. 提示客户联系支持。

## 后续验收标准

Windows：

- U-Claw 正常启动。
- 点击更新后主程序主动退出。
- updater 能等待锁释放。
- 替换程序层成功。
- `data/` 未丢失。
- 更新后能重新打开。
- 旧版本备份可回滚。

Mac：

- 启动不被更新检查阻塞。
- 不出现启动硬更新下载。
- 程序层和 `data/` 边界清晰。

通用：

- hash 校验失败不替换。
- 签名校验失败不替换。
- payload 内出现 `data/`、`.openclaw/`、`.env`、`.key` 等敏感/禁止路径时拒绝。
- 断电/中断后可再次运行 updater 恢复或重试。

## 当前结论

方案可行。

短期先人工发独立更新器给客户，客户复制到 U 盘运行。

中期再接入页面内“发现新版本 -> 立即更新 -> 自动退出 -> 拉起 updater”的提示式更新体验。
