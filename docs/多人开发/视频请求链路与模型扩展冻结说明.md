# Bavi-box 视频请求链路与模型扩展冻结说明

> 状态：已验证，默认链路冻结  
> 最后验证：2026-08-24  
> 适用范围：桌面 dev、客户版、主播版、便携版、U 盘版  
> 新增或更换视频模型前，必须先读本文档。

## 1. 唯一正确链路

```txt
Bavi-box / OpenClaw
  -> 本机 video adapter
  -> New API（计费、任务日志、渠道路由）
  -> 服务器 video adapter
  -> 火山引擎即梦
```

不得简化为以下任一链路：

```txt
Bavi-box -> New API
Bavi-box -> 公网 video adapter
Bavi-box -> 火山引擎
```

原因：本机 adapter 负责 xAI/OpenClaw 请求兼容；New API 负责计费和路由；服务器 adapter 负责 New API/OpenAI 协议到即梦签名接口的转换。绕过任一层，都会丢失兼容、计费或即梦调用。

## 2. 当前正确地址和请求

### 2.1 OpenClaw -> 本机 adapter

配置 base URL：

```txt
http://127.0.0.1:18808/xai/v1
```

请求：

```http
POST http://127.0.0.1:18808/xai/v1/videos/generations
GET  http://127.0.0.1:18808/xai/v1/videos/{request_id}
```

`18808` 是默认端口。若被占用，桌面端会在 `18808-18818` 中选可用端口，并把实际地址写入运行配置。不得因端口变化改成公网地址。

### 2.2 本机 adapter -> New API

配置 base URL：

```txt
https://api.gmnlee.com/v1
```

请求：

```http
POST https://api.gmnlee.com/v1/videos
GET  https://api.gmnlee.com/v1/videos/{task_id}
```

本机 adapter 完成以下映射：

```txt
/xai/v1/videos/generations -> /v1/videos
request_id <-> task_id/id
durationSeconds -> seconds
aspectRatio -> aspect_ratio
resolution -> size
New API 状态 -> xAI/OpenClaw 状态
视频 URL -> video.url
```

### 2.3 New API -> 服务器 adapter

New API 视频渠道当前 upstream base URL：

```txt
https://video-adapter.560777.xyz/openai/v1
```

请求：

```http
POST https://video-adapter.560777.xyz/openai/v1/videos
GET  https://video-adapter.560777.xyz/openai/v1/videos/{task_id}
```

该地址只属于 New API 服务端渠道配置。不得写入桌面端 `providers.xai.baseUrl`。若服务器 adapter 域名变更，只更新 New API 渠道和本文档，桌面端仍指向本机 adapter。

### 2.4 服务器 adapter -> 火山即梦

```txt
base URL: https://visual.volcengineapi.com
720p 提交: JimengT2VV30SubmitTask
720p 查询: JimengT2VV30GetResult
```

`UCLAW_VIDEO_PROVIDER=volcengine` 只配在服务器 adapter。桌面端或本机 adapter 不得设置该值，否则会绕过 New API 计费。

## 3. 正确 `openclaw.json`

### 3.1 客户版空模板

```json
{
  "models": {
    "providers": {
      "custom": {
        "baseUrl": "https://api.gmnlee.com/v1",
        "apiKey": ""
      },
      "litellm": {
        "baseUrl": "https://api.gmnlee.com/v1",
        "apiKey": ""
      },
      "xai": {
        "baseUrl": "http://127.0.0.1:18808/xai/v1",
        "apiKey": "uclaw-video-adapter"
      }
    }
  },
  "agents": {
    "defaults": {
      "videoGenerationModel": {
        "primary": "xai/jimeng-video-3-720p",
        "timeoutMs": 600000
      }
    }
  }
}
```

真实模板文件：

```txt
u-claw-app-dev/resources/default-openclaw.json
```

### 3.2 主播版/内部测试版

使用同一链路，只在 `custom.apiKey` 和 `litellm.apiKey` 中写入真实 New API key。

```txt
custom.apiKey   = 真实 New API key
litellm.apiKey  = 真实 New API key
xai.apiKey      = uclaw-video-adapter
xai.baseUrl     = http://127.0.0.1:18808/xai/v1
```

必须由同步脚本自动继承，不得手填 key：

```bash
cd <repo>/u-claw-app-dev
npm run sync:config -- --streamer --dest /absolute/path/openclaw.json
```

同步脚本：

```txt
u-claw-app-dev/scripts/sync-openclaw-config.js
```

## 4. key 的职责

```txt
真实 New API key：
  - 存在 custom/litellm 或 UCLAW_NEW_API_KEY。
  - 本机 adapter 启动时从这些配置取得。
  - 只用于访问 https://api.gmnlee.com/v1。

uclaw-video-adapter：
  - 是 OpenClaw -> 本机 adapter 的本地占位 token。
  - 不是 New API key。
  - 本机 adapter 收到该 token 时，会改用启动时读取的真实 New API key。
```

任何真实 key 都不得出现在 Git 可跟踪文件、默认模板、文档或日志中。

## 5. SSRF 拦截的正确处理

OpenClaw xAI 视频 provider 默认拦截 loopback/private network。本项目通过：

```txt
u-claw-app-dev/scripts/patch-openclaw.js
patchXaiVideoLoopbackAccess()
```

只允许 xAI 视频 provider 访问：

```txt
http://127.0.0.1:<port>
```

禁止：

```txt
全局开启 allowPrivateNetwork
允许 localhost、局域网 IP、0.0.0.0/8、10.0.0.0/8、192.168.0.0/16 等更宽范围
关闭其他 provider、工具或媒体下载的 SSRF 防护
手工直改 node_modules/openclaw/dist 后不回写 patch-openclaw.js
```

`npm run dev` 和打包前的 `npm run patch-openclaw` 都必须能重复打补丁。OpenClaw 升级后如果 bundle 结构变化，补丁应明确失败，不得静默跳过。

## 6. 原视频下载失败的降级规则

即梦任务成功且返回原始视频 URL 后，OpenClaw 会尝试把视频下载到本地媒体目录。当当前设备因代理、DNS、防火墙或网络路由无法连接原视频地址时：

```txt
不得把任务误报为“视频生成失败”。
必须保留 task ID、原始视频 URL 和底层下载错误。
必须提示“原视频已生成，失败发生在当前设备下载阶段”。
必须把原始 URL 作为 URL-only video attachment 返回，让用户可复制到浏览器打开或下载。
```

正式补丁位置：

```txt
u-claw-app-dev/scripts/patch-openclaw.js
patchXaiVideoDownloadFallback()
```

降级逻辑只使用 provider 返回的 `videoUrl`，不按 `*.aigc-cloud.com` 或任何 CDN 域名写死规则。CDN 换域名不需要修改该补丁。

## 7. 启动命令

```bash
cd <repo>/u-claw-app-dev
npm run dev:video
```

`dev:video` 是保留的视频调试入口，实际转到 `npm run dev`。由桌面端启动本机 adapter，不得在命令中注入公网 adapter 地址或 `UCLAW_VIDEO_PROVIDER=volcengine`。

## 8. 新增视频模型的强制流程

新增模型只改“模型和映射”，不改“链路和地址”。

1. 确认 New API 已有对应模型和视频渠道，请求仍经过 New API 计费。
2. 确认服务器 adapter 已支持该模型的即梦 `req_key`、提交 action、查询 action 和参数。
3. 在 `u-claw-app-dev/src/video-adapter.js` 的 `DEFAULT_MODEL_PROFILES` 中增加或校正 profile。
4. 在 `u-claw-app-dev/resources/default-openclaw.json` 的 `models.providers.xai.models` 中增加 model id。
5. 如需更改默认模型，同步更新 `UCLAW_VIDEO_MODEL`、`videoGenerationModel.primary` 和同步脚本生成值。
6. 保持以下配置不变：

   ```txt
   providers.xai.baseUrl = http://127.0.0.1:18808/xai/v1
   providers.xai.apiKey = uclaw-video-adapter
   newApiBaseUrl = https://api.gmnlee.com/v1
   ```

7. 先用 mock 验证创建、轮询和状态映射；再仅发起一次真实任务，避免重试造成重复计费。
8. 同时验证客户空模板和主播版 `--streamer` 生成结果。

```txt
[ ] 主播版自动继承 New API key，xai 仍使用本地 adapter token
[ ] Git diff 中没有真实 key
```

## 10. 常见错误的定位

| 现象 | 先查 | 正确结论 |
|---|---|---|
| New API 没有日志 | `providers.xai.baseUrl` | 必须指向本机 adapter，由 adapter 再请求 New API |
| 报 SSRF/private IP | `patchXaiVideoLoopbackAccess()` | 只放行 xAI -> `127.0.0.1:<port>` |
| New API 有日志但即梦无任务 | New API 视频渠道 upstream | 必须指向服务器 adapter `/openai/v1` |
| 有任务但无最终视频 | 轮询 ID、状态和 URL 映射 | 检查 `task_id/id <-> request_id` 和 `video.url` |
| 任务成功但本地视频下载超时 | 返回 URL 的主机连通性、代理、DNS | 保留 task ID 和原始 URL；不得改视频请求链路或写死 CDN 域名 |
| 主播版无权限 | `custom/litellm.apiKey` | 用 `sync:config -- --streamer`，不手填 |
| 客户包泄露 key | `default-openclaw.json` | `custom/litellm.apiKey` 必须为空 |
