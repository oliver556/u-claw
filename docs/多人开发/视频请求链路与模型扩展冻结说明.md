# U-Claw 视频请求链路与模型扩展冻结说明

> 状态：已验证，默认链路冻结  
> 最后验证：2026-08-24  
> 适用范围：桌面 dev、客户版、主播版、便携版、U 盘版  
> 新增或更换视频模型前，必须先读本文档。

## 1. 唯一正确链路

```txt
U-Claw / OpenClaw
  -> 公网 video adapter
  -> New API（计费、任务日志、渠道路由）
  -> 火山引擎即梦
```

不得简化为以下任一链路：

```txt
U-Claw -> New API
U-Claw -> 火山引擎
```

原因：公网 adapter 统一处理 xAI/OpenClaw 请求兼容、上游协议差异、鉴权、限流和日志脱敏；New API 负责计费、任务日志和渠道路由。绕过 adapter 会丢失兼容、风控或即梦调用。

## 2. 当前正确地址和请求

### 2.1 OpenClaw -> 公网 adapter

配置 base URL：

```txt
https://video-adapter.gmnlee.com/xai/v1
```

请求：

```http
POST https://video-adapter.gmnlee.com/xai/v1/videos/generations
GET  https://video-adapter.gmnlee.com/xai/v1/videos/{request_id}
```

当前生产先保留旧公网 adapter。服务器和 `yiyong.me` 路由配置完成后，再统一切到 `https://yiyong.me/uclaw/video/xai/v1`。公网 adapter 首选部署在香港网络优化机。客户端不得写死香港机或阿里云机器 IP/域名。

### 2.2 公网 adapter -> New API

配置 base URL：

```txt
https://api.gmnlee.com/v1
```

请求：

```http
POST https://api.gmnlee.com/v1/videos
GET  https://api.gmnlee.com/v1/videos/{task_id}
```

公网 adapter 完成以下映射：

```txt
/xai/v1/videos/generations -> /v1/videos
request_id <-> task_id/id
durationSeconds -> seconds
aspectRatio -> aspect_ratio
resolution -> size
New API 状态 -> xAI/OpenClaw 状态
视频 URL -> video.url
```

### 2.3 上游视频服务

公网 adapter 或 New API 渠道按后台配置访问上游，不写入客户端：

```txt
火山引擎即梦 / 后续其他视频上游
```

### 2.4 火山即梦

```txt
base URL: https://visual.volcengineapi.com
720p 提交: JimengT2VV30SubmitTask
720p 查询: JimengT2VV30GetResult
```

`UCLAW_VIDEO_PROVIDER=volcengine` 只配在公网 adapter 服务端。桌面端不得设置该值，否则会绕过 New API 计费。

## 3. 正确 `openclaw.json`

### 3.1 客户版空模板

```json
{
  "models": {
    "providers": {
      "custom": {
        "baseUrl": "https://api.gmnlee.com/v1",
        "apiKey": ""
      },
      "litellm": {
        "baseUrl": "https://api.gmnlee.com/v1",
        "apiKey": ""
      },
      "xai": {
        "baseUrl": "https://video-adapter.gmnlee.com/xai/v1",
        "apiKey": "uclaw-video-adapter"
      }
    }
  },
  "agents": {
    "defaults": {
      "videoGenerationModel": {
        "primary": "xai/jimeng-video-3-720p",
        "timeoutMs": 600000
      }
    }
  }
}
```

真实模板文件：

```txt
u-claw-app-dev/resources/default-openclaw.json
```

### 3.2 主播版/内部测试版

使用同一链路。正式新盘 key 由激活链路写入 `custom.apiKey` 和 `litellm.apiKey`；激活链路完成前，streamer stage 可临时继承桌面 key 作内部验证/母盘过渡。

```txt
custom.apiKey   = 真实 New API key
litellm.apiKey  = 真实 New API key
xai.apiKey      = uclaw-video-adapter
xai.baseUrl     = https://video-adapter.gmnlee.com/xai/v1
```

过渡期如需生成 streamer stage，必须由同步脚本自动继承，不得手填 key：

```bash
cd <repo>/u-claw-app-dev
npm run sync:config -- --streamer --dest /absolute/path/openclaw.json
```

同步脚本：

```txt
u-claw-app-dev/scripts/sync-openclaw-config.js
```

## 4. key 的职责

```txt
真实 New API key：
  - 存在 custom/litellm 或 UCLAW_NEW_API_KEY。
  - 只用于访问 https://api.gmnlee.com/v1。

uclaw-video-adapter：
  - 是 OpenClaw -> 公网 adapter 的过渡 token。
  - 不是 New API key。
  - 正式公网 adapter 后续必须升级为 license/device 短期 token 或请求签名。
```

任何真实 key 都不得出现在 Git 可跟踪文件、默认模板、文档或日志中。

## 5. SSRF 拦截的正确处理

生产链路不需要放行 loopback/private network。

本机 adapter 只允许保留为 dev/debug fallback。若启用，仍必须只放行：

```txt
http://127.0.0.1:<port>
```

`npm run dev` 和打包前的 `npm run patch-openclaw` 都必须能重复打补丁。OpenClaw 升级后如果 bundle 结构变化，补丁应明确失败，不得静默跳过。

## 6. 原视频下载失败的降级规则

即梦任务成功且返回原始视频 URL 后，OpenClaw 会尝试把视频下载到本地媒体目录。当当前设备因代理、DNS、防火墙或网络路由无法连接原视频地址时：

```txt
不得把任务误报为“视频生成失败”。
必须保留 task ID、原始视频 URL 和底层下载错误。
必须提示“原视频已生成，失败发生在当前设备下载阶段”。
必须把原始 URL 作为 URL-only video attachment 返回，让用户可复制到浏览器打开或下载。
```

正式补丁位置：

```txt
u-claw-app-dev/scripts/patch-openclaw.js
patchXaiVideoDownloadFallback()
```

降级逻辑只使用 provider 返回的 `videoUrl`，不按 `*.aigc-cloud.com` 或任何 CDN 域名写死规则。CDN 换域名不需要修改该补丁。

## 7. 启动命令

```bash
cd <repo>/u-claw-app-dev
npm run dev:video
```

`dev:video` 是保留的视频调试入口，实际转到 `npm run dev`。生产包默认走公网 adapter；本机 adapter 只用于 dev/debug fallback。桌面端不得设置 `UCLAW_VIDEO_PROVIDER=volcengine`。

## 8. 新增视频模型的强制流程

新增模型只改“模型和映射”，不改“链路和地址”。

1. 确认 New API 已有对应模型和视频渠道，请求仍经过 New API 计费。
2. 确认服务器 adapter 已支持该模型的即梦 `req_key`、提交 action、查询 action 和参数。
3. 在 `u-claw-app-dev/src/video-adapter.js` 的 `DEFAULT_MODEL_PROFILES` 中增加或校正 profile。
4. 在 `u-claw-app-dev/resources/default-openclaw.json` 的 `models.providers.xai.models` 中增加 model id。
5. 如需更改默认模型，同步更新 `UCLAW_VIDEO_MODEL`、`videoGenerationModel.primary` 和同步脚本生成值。
6. 保持以下配置不变：

   ```txt
   providers.xai.baseUrl = https://video-adapter.gmnlee.com/xai/v1
   providers.xai.apiKey = uclaw-video-adapter
   newApiBaseUrl = https://api.gmnlee.com/v1
   ```

7. 先用 mock 验证创建、轮询和状态映射；再仅发起一次真实任务，避免重试造成重复计费。
8. 同时验证客户空模板和主播版 `--streamer` 生成结果。

## 9. 验收清单

```txt
[ ] npm run dev:video 启动成功
[ ] providers.xai.baseUrl 指向公网 adapter
[ ] OpenClaw 创建请求到达公网 adapter
[ ] New API 出现请求、计费和任务日志
[ ] 即梦任务创建成功
[ ] 最终视频 URL 返回并在 U-Claw 显示
[ ] 模拟 CDN 下载失败时，任务仍返回 task ID、原始 URL 和明确的本机下载失败提示
[ ] 没有 Blocked hostname or private/internal/special-use IP address
[ ] 其他 provider、工具和私网地址仍被 SSRF 防护拦截
[ ] 客户版模板中真实 key 为空
[ ] 主播版自动继承 New API key，xai 仍使用本地 adapter token
[ ] Git diff 中没有真实 key
```

## 10. 常见错误的定位

| 现象 | 先查 | 正确结论 |
|---|---|---|
| New API 没有日志 | `providers.xai.baseUrl` | 必须指向公网 adapter，由 adapter 再请求 New API |
| 报 SSRF/private IP | `providers.xai.baseUrl` | 生产不应指向 `127.0.0.1`；本机 adapter 仅 dev/debug |
| New API 有日志但即梦无任务 | 公网 adapter / New API 视频渠道 upstream | 检查服务端上游配置 |
| 有任务但无最终视频 | 轮询 ID、状态和 URL 映射 | 检查 `task_id/id <-> request_id` 和 `video.url` |
| 任务成功但本地视频下载超时 | 返回 URL 的主机连通性、代理、DNS | 保留 task ID 和原始 URL；不得改视频请求链路或写死 CDN 域名 |
| 主播版无权限 | `custom/litellm.apiKey` | 正式链路看激活写入；过渡 stage 用 `sync:config -- --streamer`，不手填 |
| 客户包泄露 key | `default-openclaw.json` | `custom/litellm.apiKey` 必须为空 |
