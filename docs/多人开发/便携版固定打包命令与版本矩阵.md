# U-Claw 便携版固定打包命令与版本矩阵

> 状态：正式打包入口  
> 适用：客户便携版、主播/内部便携版、U 盘部署

## 1. 只允许使用的总命令

客户版：

```bash
cd <repo>/u-claw-app-dev
npm run package:portable:customer -- --usb /Volumes/UCLAW-01
```

主播/内部版：

```bash
cd <repo>/u-claw-app-dev
npm run package:portable:streamer -- --usb /Volumes/UCLAW-01
```

只生成 `release/portable-<edition>/U-Claw`，不写 U 盘：

```bash
npm run package:portable:customer
npm run package:portable:streamer
```

总命令自动完成：

```txt
OpenClaw 补丁
UI/lib 同步
Mac arm64 app 构建
Mac x64 app 构建
Windows x64 app 构建
Mac arm64/x64 tar.gz 生成
Windows zip 生成
SHA-256 manifest 生成
按版本生成 openclaw.json
生成完整 U-Claw 目录
部署前备份 U 盘旧文件
原子复制和 SHA-256 校验
```

`--skip-build` 只允许在刚刚完成构建、仅调试组装脚本时使用。正式交付不得使用，避免重用旧产物。

## 2. 版本矩阵

| 项目 | 客户版 | 主播/内部版 |
|---|---|---|
| `custom.baseUrl` | `https://api.gmnlee.com/v1` | 同左 |
| `litellm.baseUrl` | `https://api.gmnlee.com/v1` | 同左 |
| `custom.apiKey` | 空 | 激活链路写入；stage 过渡期可从桌面配置自动继承 |
| `litellm.apiKey` | 空 | 激活链路写入；stage 过渡期可从桌面配置自动继承 |
| `xai.baseUrl` | `https://video-adapter.gmnlee.com/xai/v1` | 同左 |
| `xai.apiKey` | `uclaw-video-adapter` | 同左 |
| 视频链路 | U-Claw -> 公网 video adapter -> New API -> 即梦/上游 | 同左 |

两个版本不允许各自更改视频地址、adapter token、模型链路或 SSRF 规则。当前生产先保留旧公网 adapter；服务器和 `yiyong.me` 路由配置完成后，再统一切到 `https://yiyong.me/uclaw/video/xai/v1`。streamer key 正式来源是激活链路；激活链路完成前，stage 继承桌面 key 只作为内部验证/母盘过渡。

## 3. 固定产物

```txt
U-Claw/
  Mac-Start-App.command
  Windows-Start-App.bat
  UCLAW-PACKAGE-NOTES.txt
  app/
    desktop-archive/
      u-claw-app-mac-arm64.tar.gz
      u-claw-app-mac-arm64.tar.gz.sha256
      u-claw-app-mac-x64.tar.gz
      u-claw-app-mac-x64.tar.gz.sha256
      u-claw-app-win-x64.zip
      u-claw-app-win-x64.zip.sha256
  data/
    .openclaw/
      openclaw.json
```

Windows 不再从 U 盘直接运行 NSIS portable EXE。正式便携产物是 `win-unpacked` 的 zip，首次解压到电脑缓存后直接运行真实 `U-Claw.exe`。

## 4. 电脑缓存策略

### Mac

```txt
App 缓存：~/Library/Caches/U-Claw/u-claw-app-mac-arm64
App 缓存：~/Library/Caches/U-Claw/u-claw-app-mac-x64
Data 缓存：~/Library/Caches/U-Claw/usb-portable/data
```

Mac 启动脚本必须按宿主机架构选择归档：

```txt
arm64  -> u-claw-app-mac-arm64.tar.gz
x86_64 -> u-claw-app-mac-x64.tar.gz
```

两套 App 缓存必须隔离，不能让 Intel Mac 复用 Apple Silicon 缓存，也不能让 Apple Silicon 复用 Intel 缓存。

### Windows

```txt
App 缓存：%LOCALAPPDATA%\U-Claw\usb-portable\app-win-x64
Data 缓存：%LOCALAPPDATA%\U-Claw\usb-portable\data
```

两端流程统一：

```txt
启动脚本从 U 盘读取小型 SHA-256 manifest
manifest 未变 -> 直接复用电脑 App 缓存
manifest 变化 -> 仅该版本首次解压 App
U 盘 data -> 电脑 Data 缓存
App 只读写电脑 Data 缓存
App 退出后，电脑 Data 缓存 -> U 盘 data
```

因此：

```txt
每个新包第一次启动会慢，因为必须安装电脑 App 缓存。
同一包后续启动不应重复解压。
运行中不高频读写 U 盘。
```

## 5. 慢启动定位

| 日志 | 含义 | 是否正常 |
|---|---|---|
| `Installing updated app cache from archive...` | 新包首次解压 | 每个新 SHA 只出现一次 |
| `Reusing app cache` | 直接运行电脑缓存 | 正常快速路径 |
| 同一 SHA 每次都解压 | manifest/stamp 缺失或不一致 | 错误，禁止交付 |
| 启动后长时间读写 U 盘 | Data 路径未指向电脑缓存 | 错误，禁止交付 |

## 6. 交付验收

```txt
[ ] 总命令退出码为 0
[ ] stage 的版本类型正确
[ ] 客户版 New API key 为空
[ ] 主播版 New API key 与桌面配置相同
[ ] xai.baseUrl 为公网 adapter
[ ] xai.apiKey 为 uclaw-video-adapter
[ ] Mac arm64 archive SHA-256 与 manifest 一致
[ ] Mac x64 archive SHA-256 与 manifest 一致
[ ] Windows archive SHA-256 与 manifest 一致
[ ] U 盘部署后 SHA-256 仍一致
[ ] 新 SHA 首次启动解压一次
[ ] 第二次启动显示 Reusing app cache
[ ] App 运行时 OPENCLAW_HOME/STATE/CONFIG 指向电脑 Data 缓存
[ ] App 退出后数据同步回 U 盘
[ ] Apple Silicon Mac 真机验证通过
[ ] Intel Mac 真机验证通过
[ ] Windows 真机验证通过
```
