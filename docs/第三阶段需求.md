## 1. 阶段目标

第三阶段将通用 U-Claw 客户端变为可正式制作、销售和运营的产品盘，完成：

1. 用户不可见、无需配置的默认模型服务。
2. 独立于模型 Token 的 U 盘启动授权。
3. 每个产品盘唯一设备身份和后端映射。
4. New API 用户与专属 Token 自动创建。
5. 单设备额度、限速、模型权限和封禁管理。

第一版产品化顺序调整为：发货前生成用户名与激活码并准备独立 New API 设备账户，余额由运营人员人工设置；用户首次使用时在线绑定当前 U 盘并签发许可证。不再要求制盘时完成最终 USB 绑定和许可证签发。

安全目标定位为“防君子”，不建设硬件级 DRM。

第三阶段是产品化附加层，不替代客户端改造主线。客户端改造的核心交付仍然是：

```text
OpenClaw 原有能力
-> U-Claw Adapter
-> Electron 主进程与受控 IPC
-> 自建 React UI
-> 用户真实操作成功
```

- 不重写 OpenClaw Agent 引擎，不用授权、New API 或制盘功能代替 OpenClaw 能力接入。
- 第一、第二阶段已实现的 UI 和契约，仍需以真实 OpenClaw 运行时验收；只有 mock 或 localhost 证据不等于真实能力已接通。
- 第三阶段只在上述主链外增加隐藏内置模型、启动授权、制盘开户和运营控制。

## 2. 进入条件

开始第三阶段前，必须满足：

1. 第二阶段全部功能包已完成本地代码与自动化会合，国产模型和纯自定义模型配置契约已稳定。
2. Windows 正式发行包、runtime 数字签名、更新和回滚链路已有本地自动化证据；真实 Windows 与物理 U 盘验收统一留到 `P3-T08`。
3. 选定自有 New API 部署及企业商家上游，确认用户、Token、额度、限速、模型权限和禁用管理接口。
4. 自有后端数据库、TLS、备份、审计日志和管理员权限边界可用。
5. 制盘工具运行环境已确定，能访问 U 盘、U-Claw 后端和 New API 管理接口。

### 2.1 精简执行原则

为避免过度设计和重复审核，后续缺陷修复、`P3-T08` 验收准备和未来开发 Task 按以下规则执行：

1. 每个 Task 只保留一份简短设计和一次最终代码审查，不因普通修复反复重写设计或交付报告。
2. 以完整 Task 为测试批次：先完成当前 Task 的实现和测试用例，再集中运行 typecheck 和定向测试，不要求每个小步骤先 RED 后 GREEN。
3. 集中测试失败后按根因批量修复，然后重跑受影响的定向测试；不在每次小修复后重复运行全仓 Node、Go 和 Windows 交叉编译门禁。
4. Task 结束审查只阻断 `Critical` 和 `Important`；`Minor` 记录到交付报告，不阻止会合。
5. `P3-T07` 统一执行一次 fresh 全量 Node、Go、契约、集成、秘密扫描和 Windows 交叉编译；除非修复实际改变了受影响路径，否则不重复全量门禁。
6. 真实 New API、Windows、物理 U 盘、真实账号、断网和时钟场景统一留到 `P3-T08`，localhost 阶段不提前穷举真实环境故障。
7. `P3-T01`–`P3-T07` 已完成并集成，不因本规则变更返工、重启审查或重跑历史门禁；`P3-T08` 只执行真实环境验收，发现缺陷时才创建定向修复批次。

## 3. 功能包一：隐藏内置模型服务

需求编号：`MODEL-008`、`MODEL-009`

系统内部存在三类模型来源：

```text
builtin   U-Claw 隐藏内置服务
domestic  原项目国产模型 Provider
custom    OpenAI-compatible 纯自定义服务
```

用户界面只展示 `domestic` 和 `custom` 两类配置。`builtin` 不显示服务地址、用户名、Token、编辑入口或独立选择项。

路由规则：

1. 用户未启用任何外部模型来源时，使用 `builtin`。
2. 用户明确启用国产模型时，只使用当前国产 Provider。
3. 用户明确启用纯自定义模型时，只使用当前自定义服务。
4. 国产与自定义配置同时存在时，以最后一次明确启用的来源为准。
5. 用户关闭或清除当前外部来源后，恢复 `builtin`。
6. 外部服务认证失败、欠费、限流或网络错误时，直接报告当前来源错误，不静默回退到 `builtin`。
7. 外部模型请求不得经过或消耗 U-Claw 内置服务；启动授权校验仍独立执行。

验收重点：

- 新产品盘不填写模型配置即可完成首次对话。
- renderer、设置页、日志和诊断导出均不能显示完整内置 URL 或 Token。
- DeepSeek、Kimi、Qwen、GLM、MiniMax、豆包等原有国产 Provider 不因内置服务接入而被删除或降级。
- 用户自定义 Base URL、API Key 和模型名仍可完整使用，且 Key 不上传 U-Claw 自有服务器。

## 4. 功能包二：U 盘启动授权

需求编号：`LIC-001`、`LIC-002`

启动授权由以下信息组成：

```text
隐藏独立启动密钥
+ 签名授权文件
+ device_id
+ 可用的 U 盘硬件指纹
```

要求：

- 缺少隐藏启动密钥或授权文件时，`U-Claw.exe` 拒绝启动。
- 授权签名私钥只存在于自有服务器或受控签发环境，不能进入 U 盘和客户端源码。
- 客户端只内置验签公钥。
- 启动密钥与 New API Token 完全独立，不得复用、派生或共用撤销逻辑。
- 支持签发、状态查询、撤销、重新制作和必要的离线容错。
- 在线状态查询失败与许可证被撤销必须使用不同错误状态。

验收重点：

- 只复制可见 `U-Claw.exe`，缺少隐藏启动凭据时无法启动。
- 修改授权文件、设备身份或签名后无法通过校验。
- 模型 Token 泄露不等于启动密钥泄露，任一凭据可单独轮换和撤销。

## 5. 功能包三：制盘设备身份与自动开户

需求编号：`LIC-003`、`SVC-001`

每个产品盘制作时生成：

- 随机唯一 `device_id`。
- 独立高强度启动密钥。
- 唯一许可证 `license_id`。
- 随机唯一 New API 用户名。
- New API 返回的用户 ID 和设备专属 Token。

后端设备记录至少包含：

```text
device_id
license_id
startup_secret_hash
startup_secret_salt
usb_fingerprint
new_api_user_id
new_api_username
new_api_token_id
status
created_at
updated_at
```

约束：

- 用户名是公开标识，不是密钥，不包含客户姓名、电话等敏感信息。
- 启动密钥使用每条记录独立盐值加盐哈希保存。
- 后端原则上不保存 New API Token 明文；制盘失败重试时重新签发或使用受控短期密文。
- U 盘保存本设备专属 Token，不保存企业商家的上游 Key。
- 数据库唯一约束拒绝重复 `device_id`、`license_id`、New API 用户名和有效 Token 标识。

## 6. 制盘流程

标准流程：

```text
识别目标 U 盘
-> 校验发行包和可写性
-> 生成 device_id、license_id、启动密钥
-> 后端预登记设备，状态设为 provisioning
-> 调用 New API 创建随机唯一用户
-> 调用 New API 创建设备专属 Token
-> 后端保存设备、许可证和 New API 映射
-> 写入隐藏启动凭据、签名授权文件和内置服务凭据
-> 本地启动校验
-> 发起一次内置模型连通请求
-> 后端状态切换为 active
-> 输出制盘结果
```

失败处理：

- 任一步失败时，设备不得进入 `active`。
- 已创建 New API 用户但写盘失败时，记录用户 ID 并撤销 Token，不留下不可追踪账户。
- 相同制盘任务重试必须幂等，不重复创建多个有效用户或 Token。
- 制盘日志只记录标识和结果，不记录启动密钥、Token、上游 Key 或完整请求头。

## 7. 功能包四：内置服务运营控制

需求编号：`SVC-002`

自有 New API 负责：

- 单设备用户额度。
- 请求频率和并发限制。
- 可用模型范围。
- 用户或 Token 禁用。
- 用量查询和异常审计。
- 上游渠道与企业商家 Key 管理。

要求：

- 运营调整按 `device_id` 或 `new_api_user_id` 定位同一账户。
- 修改额度、限速、模型权限和禁用状态后，无需重新制作 U 盘即可生效。
- 企业商家上游 Key 只存在自有 New API 服务端。
- 单设备 Token 泄露只消耗该设备账户额度，不能访问其他设备账户。
- 启用用户自有国产或自定义模型后，不消耗内置服务额度。

## 8. 启动与请求流程

启动流程：

```text
读取隐藏启动凭据
-> 验证授权文件数字签名
-> 校验 device_id 和可用硬件指纹
-> 判断许可证本地状态与离线容错
-> 必要时查询后端授权状态
-> 通过后启动 Electron/OpenClaw
```

模型请求流程：

```text
读取当前 provider_mode
├─ builtin  -> 使用隐藏设备 Token 请求自有 New API
├─ domestic -> 使用用户选择的国产 Provider 配置
└─ custom   -> 使用用户自定义 Base URL、API Key 和模型名
```

## 9. 格式化与复制边界

- 普通格式化会清空程序、授权、模型凭据和用户数据，属于客户自行执行的数据清除行为。
- 格式化后产品不承诺继续启动；如需恢复，走重新制作或重新授权流程。
- 只复制可见 `U-Claw.exe` 时，因为缺少隐藏启动凭据，不能启动。
- 完整文件复制或磁盘镜像得到同一授权时，服务端仍视为同一设备账户，共享额度、限速、模型权限和封禁状态。
- 本阶段不承诺抵抗完整磁盘镜像、逆向、内存提取、固件改写或硬件级复制。

## 11. 第三阶段验收条件

- 新产品盘完成制盘后，不进行任何模型配置即可启动并完成对话。
- 每个产品盘拥有唯一设备、许可证、New API 用户和 Token 映射。
- 制盘流程可幂等重试，失败不会留下有效但不可追踪的账户或 Token。
- 缺少或篡改启动凭据时拒绝启动。
- 内置服务 URL、用户名和 Token 不出现在用户设置、日志和诊断导出中。
- 用户可继续使用全部原有国产模型和纯自定义服务。
- 外部模型启用后，内置服务无推理请求和额度消耗；外部错误不静默回退。
- 额度、限速、模型权限和禁用可从服务端动态修改并生效。
- U 盘和客户端发行包中不存在企业商家的上游 Key。
- 完整复制同一授权时只共享原账户，不自动创建新账户或新增额度。

## 12. 第三阶段不交付

- 硬件安全芯片或企业级 DRM。
- 对完整磁盘镜像、专业逆向或内存提取的绝对防护。
- 用户可见或可编辑的内置 New API 配置。
- 外部模型失败后自动消耗内置额度的兜底行为。
- 将用户自定义 API Key 上传到 U-Claw 自有服务器。
- macOS、Linux、Windows ARM 产品授权。
- 面向客户开放的 U-Claw 后端管理控制台。
