# U-Claw 第一阶段需求

## 1. 阶段目标

第一阶段交付可长期演进的 Windows U 盘桌面客户端和完整对话主链，解决旧客户端脱节、浏览器感明显、U 盘散文件启动慢和用户数据路径不清晰等基础问题。

完成后，用户可在 Windows 10/11 x64 普通用户权限下双击 `U-Claw.exe`，进入独立客户端并完成对话、附件、工具调用和基础模型选择；更换电脑后继续使用同一 U 盘数据。

## 2. 进入条件

开始第一阶段前，必须满足：

1. 使用当前 `portable/` 和锁定版本 OpenClaw 作为能力基线。
2. `u-claw-app/` 只作为 Electron 生命周期和 Gateway 启动参考，不继续堆叠正式功能。
3. 首发平台限定为 Windows 10/11 x64，不同时维护 macOS、Linux、Windows ARM 产品线。
4. 正式产品代码统一进入 `product/`，不将自研 React UI 混入上游目录。
5. Node.js、OpenClaw、Electron 和生产依赖必须锁定版本并可重现构建。

## 3. 基础能力

需求编号：`MODEL-007`、`DATA-003`、`DATA-005`、`REL-002`、`SEC-001`、`SEC-002`

交付内容：

- Adapter 检测 OpenClaw 版本和模型能力，不向 UI 开放后端不支持的能力。
- 审计配置、会话、记忆、技能、工作文件和业务数据的全部持久化路径。
- 处理个人微信插件可能写入宿主机用户目录的残留问题。
- 锁定 OpenClaw、Node.js、Electron 和原生模块版本，禁止生产构建解析 `latest`。
- 建立 renderer、preload、Electron IPC 和本地服务之间的安全边界。
- 对日志、错误、诊断和 IPC 响应统一执行敏感信息脱敏。

验收重点：

- 本机不存在用户配置、Key、会话、记忆和工作文件的唯一副本。
- renderer 无任意 Node.js 能力，不能读取已保存的完整敏感字段。
- 日志不包含 API Key、Token、请求头和对话正文。
- 构建结果可由锁定版本重现。

## 4. 功能包一：Windows 启动与运行环境

需求编号：`RUN-001`–`RUN-013`

交付内容：

- 提供无终端、无浏览器地址栏的 Windows 独立客户端。
- 启动后立即展示校验、缓存准备、Gateway 启动、就绪和失败状态。
- 校验 U 盘结构、可写性、平台、架构、版本和 runtime 包完整性。
- 同一 U 盘数据目录只允许一个写实例。
- 首次启动将版本化 runtime 原子解压到本机 SSD；二次启动直接复用。
- Electron 统一管理 Gateway 端口、健康检查和子进程生命周期。
- U 盘拔出后停止新写入并安全停止相关进程。
- 支持窗口、托盘、单实例唤醒和重新打开。
- 自动记录首窗、runtime 准备、Gateway 就绪和业务可用耗时。
- 启动前检测 Windows 版本、CPU 架构、磁盘和 runtime 兼容性。

验收重点：

- Win10/11 x64 普通用户无需安装 Node.js 即可启动。
- 连续双击不会产生两个 Gateway 或并发写入。
- 缓存损坏可重建，删除缓存不丢用户数据。
- 端口占用可回退，不把占用误报为初始化失败。
- 正常退出、崩溃恢复和拔盘后无产品所属孤立进程。

## 5. 功能包二：对话与任务主链

需求编号：`CHAT-001`、`CHAT-002`、`CHAT-004`–`CHAT-012`

交付内容：

- 原生会话列表、切换、新建、重命名和删除。
- 历史消息分页加载，保证顺序正确且无重复。
- 消息发送、流式输出、停止生成和明确终态。
- Markdown、代码块、表格和安全链接渲染。
- 附件选择、拖放、发送、进度、失败和重试。
- 工具调用等待、运行、成功、失败、参数摘要和结果轨迹。
- Gateway 断线重连和未发送草稿保留。
- 会话内模型选择和失效模型提示。
- 上下文舱统一展示附件、引用文件、记忆、工具结果和任务产物。

验收重点：

- 切换会话后消息、模型和上下文一致。
- 流式内容不重复拼接，每个 run 只有一个终态。
- 停止生成同时结束服务端任务和前端流。
- 危险 HTML、脚本和 URL 被拦截。
- 断线或 Gateway 重启不丢草稿。

## 6. 功能包三：U 盘数据便携

需求编号：`DATA-004`、`DATA-006`

交付内容：

- Electron、Node.js、OpenClaw 的可重建缓存统一放在本机 SSD。
- 配置、API Key、会话、记忆、技能、工作文件和授权数据保存在 U 盘。
- 所有路径根据当前 EXE 和 U 盘位置动态解析，不依赖固定盘符。
- 同一 U 盘在不同 Windows 电脑间继续使用同一工作状态。

验收重点：

- 删除本机缓存后可自动恢复，用户数据不受影响。
- 两台 Win10/11 电脑之间完成换机连续工作验证。
- 拔出 U 盘后，本机缓存不能作为独立 U-Claw 产品继续运行。

## 7. 功能包四：基础系统维护

需求编号：`OPS-006`、`OPS-008`、`OPS-010`

交付内容：

- 启动时识别并清理本产品拥有的残留进程，不误杀其他 Node.js 或 OpenClaw 实例。
- 保留 OpenClaw Dashboard 作为第一阶段高级控制台，为尚未原生化的管理功能兜底。
- 系统页提供受控入口，打开当前 U 盘真实数据目录。

验收重点：

- 残留进程识别有明确产品归属依据。
- 高级控制台可打开，但不破坏自建前端和 Adapter 边界。
- 打开的数据路径与当前 U 盘实际持久目录一致。

## 8. 功能包五：发行与解压安全

需求编号：`REL-004`、`SEC-003`

交付内容：

- 生成 `U-Claw.exe`、`runtime.pkg`、`version.json` 和 `.uclaw/data/` 发行结构。
- runtime 包包含锁定的 Windows x64 Electron、Node.js、OpenClaw、Adapter 和 React 产物。
- 解压过程防止路径穿越、绝对路径写入和半成品启动。
- 解压到临时目录，校验后原子切换为正式版本缓存。

验收重点：

- 损坏包、平台不符、架构不符或哈希错误时拒绝启动。
- 恶意压缩条目不能写出目标缓存目录。
- 正式产品盘只需复制少量大文件，不直接运行约两万多个 runtime 散文件。

## 9. 功能包六：客户端骨架与亮色主题

需求编号：`UX-001`–`UX-007`

交付内容：

- 建立“随行工作舱”应用骨架。
- 一级导航固定为工作、文件、记忆、能力、连接、系统。
- 常驻展示 U 盘、数据落盘、Gateway 和当前模型状态。
- 两侧栏可独立收起，窄窗口优先保留主工作区。
- 支持 Windows 100%、125%、150% 缩放。
- 统一中文错误码、说明、重试、日志和安全退出操作。
- 按已冻结语义 Token 实现 Ant Design 蓝白亮色主题。

验收重点：

- 客户端不表现为 OpenClaw Dashboard 套壳。
- 主流程无布局重叠、文字截断和水平溢出。
- 键盘焦点、tooltip、状态色和错误操作可用。
- 业务组件不散写固定色值。

当前严格进度：`6/23 = 26.1%`。已完成 `P1-T01`、`P1-T02`、`P1-T03`、`P1-T04`、`P1-T11`、`P1-T14`；仅 `P1-T05`、`P1-T06` 的代码和当前自动化已完成但未达到 100%，仍为待验收，不计入完成数。

## 12. 第一阶段验收条件

- 6 项基础需求和 38 项第一阶段需求全部达到验收状态。
- 正式产品代码集中于 `product/`，上游目录可继续同步。
- 新前端不依赖 OpenClaw Dashboard DOM 或原始 payload。
- 双击后及时显示窗口和准确启动状态。
- 会话、消息、附件、工具、模型和上下文主链可用。
- 首启创建本机版本缓存，二启不再全量解压。
- 配置、Key、会话、记忆和工作数据可验证地保存在 U 盘。
- 换机可继续工作，退出后无孤立进程。
- Win10/11 x64、普通用户权限、无本机 Node.js、Defender 开启环境通过验收。

## 13. 第一阶段不交付

- 会话搜索、固定、分组、活动中心和成果文件页签。
- 全量 Provider、技能、插件、MCP、渠道、文件和诊断原生管理页。
- 暗色主题和正式在线更新闭环。
- U 盘启动授权、设备身份和许可证生命周期。
- New API 自动开户、隐藏内置模型服务和运营控制。
- Tauri 双技术线、macOS、Linux、Windows ARM 和独立本机安装版。

第二阶段负责补齐原项目管理能力；第三阶段负责商业授权和隐藏内置服务。
