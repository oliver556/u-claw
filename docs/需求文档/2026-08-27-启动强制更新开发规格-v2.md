# U-Claw 启动强制更新开发规格 v2

- 日期：2026-08-27
- 文档类型：开发规格 / 生命周期重评版
- 状态：待冻结
- 适用范围：无终端便携版远程强制更新
- 主域名：`https://yiyong.me`
- 默认入口：`https://yiyong.me/uclaw/releases/production.json`

## 0. 2026-08-27 冻结决策

```text
更新入口固定为 https://yiyong.me/uclaw/releases/production.json。
客户端默认只依赖 yiyong.me 发布控制入口，不写死香港机或阿里云机器地址。
Phase 1 / staging 允许阿里云 update check 或本地 staging env 返回 Cloudflare R2 public r2.dev 下载 URL；客户端按返回值下载，不内置 R2 secret。
强制更新采用严格无网阻断：无法确认 production/latest 时，不进入正式 UI，只允许重试或退出。
视频 provider 走公网 adapter，不走本机 127.0.0.1 adapter。
当前生产先保留旧公网 adapter：https://video-adapter.gmnlee.com/xai/v1。
服务器和 yiyong.me 路由配置完成后，再切到 https://yiyong.me/uclaw/video/xai/v1。
video adapter 部署优先香港网络优化机；阿里云 1C1G3M 负责 license/device/token/发布控制，不承载视频主链路。
旧主播盘 key 不做手动修复工具；普通部署和远程更新都不改 key。
新盘 key 由激活链路写入 data，不由硬更新写入。
```

## 1. 结论

U-Claw 启动强制更新必须接入现有无终端便携版生命周期。

现有生命周期：

```text
原生 Launcher
-> app/desktop-archive
-> 本机 app cache
-> Electron App
-> Gateway / Config Server / video adapter
-> runtime data cache
-> USB data sync
```

旧版 `app/current -> staging -> current` 目录模型不再作为开发依据。

启动规则：

```text
能进入正式 UI
= 本次启动已联网确认 requiredVersion
= <USB>/U-Claw/app/version.json 等于 production.requiredVersion
```

无法确认版本时采用严格阻断策略：

```text
无网络 / production 不可用 / 验签失败 / 过期 / 平台缺失
-> 不进入正式 UI
-> 只允许重试或退出
```

客户端启动硬更新默认直连 R2 staging `production.json`，用于 Phase 1 无条件硬更新。

```text

```

启动入口不读取激活凭据，不等待激活接口，不依赖 deviceId/deviceToken。

2026-08-28 Phase 1 已定 update check 控制面入口：

```text
https://updates.yiyong.me/uclaw/update/check
```

该入口由阿里云 121.41.89.103 上的 U-Claw update check 服务承载，经 Caddy 反代到本机 `127.0.0.1:18080`。
该入口仅用于控制面契约和真实查库回归；不是当前启动硬更新默认路径。

2026-08-28 Phase 1 staging 当前版本从 `1.0.0` 开始。

2026-08-29 Phase 1 staging 鉴权已接真实激活库：

```text
客户端 update check 输入：
Authorization: Bearer <device_token>
deviceId: <devices.device_id>

服务端只接受 active token/license/device/inventory。
license.not_before <= now() 且 license.expires_at > now()。
activation_code 不用于 update check。
R2 仍只承载静态下载，不做鉴权。
```

2026-08-28 方案 C 决策：

```text
域名 DNS 暂由阿里云管理，不把 yiyong.me 整站迁到 Cloudflare。
Cloudflare R2 只承载静态更新包。

阿里云 update check API 返回 R2 下载地址。

Phase 1 / staging 可直接返回 R2 public r2.dev URL。
prod 仍由阿里云控制是否返回 prod R2 URL。
```

```text
Cloudflare R2:
- 存放 update package 发布物
- runtime.pkg / manifest.json / sha256 / sbom
- staging bucket: u-claw-updates-staging
- staging public URL: https://pub-8289f643846848528b61bfd5dbf17e43.r2.dev

- prod public URL: https://pub-4f24fbbe718b4c75955440700c70bdeb.r2.dev

Cloudflare Worker:
- 本轮不必创建
- 仅作为未来可选项
- 不作为 Phase 1 硬更新主链路依赖

阿里云:
```

## 5. streamer key 阶段策略

Phase 1 保留现有主播版本地 key 机制：

```text
- 不迁移 streamer key 到阿里云短期 token
- 不改已有 data/.openclaw/openclaw.json key
- 不改已有 auth_profile_store
- 远程更新包不包含 data/
- 远程更新不修复、不迁移、不重写 key
- 旧主播盘已有 key，更新后继续使用原 key
- 旧主播盘缺 key，更新后仍保持缺 key 状态
- 旧主播盘 key 缺失不在本轮提供手动修复工具
- 新盘 key 由激活链路写入 data/.openclaw/openclaw.json 和 auth_profile_store
- 激活链路未完成前，streamer stage 的本地 key 初始化只作为内部验证/母盘过渡手段
```

Phase 2 再做：

```text
启动后凭 license/device 向阿里云换短期 token。
远程更新包完全不含真实 key。
```

本 v2 首版只开发 Phase 1。

## 8. treeDigest

计算规则：

```text
1. 解包 runtime.pkg 到 staging。
2. 遍历所有普通文件。
3. relativePath 使用 `/`。
4. 路径按字典序排序。
5. 每项记录 relativePath + sha256 + size。
6. 对该清单 canonical JSON bytes 做 sha256。
```

拒绝：

```text
绝对路径
..
symlink
junction
reparse point
data/
敏感 key 文件
```

## 10. 恢复规则

```text
checking / downloading / downloaded / verifying / extracting
-> 删除 staging
-> 重新检查 production.json

staged
-> 重新校验 staging
-> 通过则继续 switching
-> 失败则删除 staging，重新下载

waiting-for-app-exit
-> 检查 App/Gateway 是否还在
-> 在则继续请求退出或交给 updater 超时强杀
-> 不在则继续 switching

switching
-> 检查目标文件是否部分替换
-> staging 完整则继续替换
-> staging 不完整但 backup 完整则回滚
-> 两边都不完整则阻断，提示人工修复

switched
-> 校验程序层 hash
-> 通过则写 version.json
-> 失败则用 backup 回滚

cache-invalidated
-> 确认本机 cache stamp 已失效
-> 继续 restarting

restarting
-> 重启 Launcher
-> 新 Launcher 再检查 version
-> 通过后 complete

complete
-> 可删除 staging
-> backup 可保留一段时间

failed
-> 旧程序应仍可运行
-> 但 A 策略下，无法确认 requiredVersion 仍阻断正式 UI
```

## 11. 职责边界

```text
Launcher = 决策 + UI + 下载 + 校验 + staging
App = 受控退出 + 停服务 + final data sync
Updater = 替换 + 恢复 + cache 失效 + 重启 Launcher
```

Launcher 负责：

```text
单实例锁
显示更新进度
获取 production.json
验 production.json 签名
读取 app/version.json
下载 manifest/runtime.pkg
校验 manifest/signature/sha256/size/treeDigest
解包到 staging
拒绝 data/ 和危险路径
写 transaction staged
请求 App 更新关闭
等待 Shutdown complete
启动 updater
自身退出
```

App 负责：

```text
普通关闭时弹确认
更新关闭时跳过确认
显示关闭进度
停 Gateway / Config Server / video adapter
停本次拉起的子进程
final sync runtime data -> USB data
写 Shutdown complete
退出
```

Updater 负责：

```text
读取 update-transaction.json
确认 App/Launcher/Gateway 已退出
必要时按 run-state pid 强杀本次拉起进程
备份允许替换项
替换程序层
写 app/version.json
删除本机 app cache stamp
更新 transaction state
启动新 Launcher
退出
```

Updater 不负责：

```text
下载网络文件
生成 manifest
改 data/
改 openclaw.json
改 auth_profile_store
修复 streamer key
启动 Gateway
直接启动 Electron App
```

Updater 使用 Go 开发。

## 12. 更新关闭协议

Launcher 写：

```text
<USB>/U-Claw/app/.runtime/update-shutdown-request.json
```

内容：

```json
{
  "schemaVersion": 1,
  "reason": "update",
  "transactionId": "update-20260827-153000-v1.1.0",
  "requestedAt": "2026-08-27T16:10:00Z"
}
```

App 检测后执行：

```text
requestAppQuit({ confirm: false, reason: "update" })
```

App 完成后写：

```text
<USB>/U-Claw/app/.runtime/shutdown-complete.json
```

内容：

```json
{
  "schemaVersion": 1,
  "reason": "update",
  "transactionId": "update-20260827-153000-v1.1.0",
  "completedAt": "2026-08-27T16:11:00Z"
}
```

Launcher 等待：

```text
shutdown-complete.json
或 main.log 的 Shutdown complete
或 run-state pid 全部退出
```

优雅等待建议 60 秒。仍未退出时交给 updater 按 pid 强杀。

## 14. cache 失效规则

更新成功后删除本机 app cache stamp，不删除数据 cache。

Windows stamp：

```text
%LOCALAPPDATA%\U-Claw\usb-portable\app-win-x64\.u-claw-archive.sha256
```

macOS stamp：

```text
~/Library/Caches/U-Claw/<slot>/app-darwin-<arch>/.u-claw-archive.sha256
```

允许清理：

```text
本机 archive-cache 复制文件
*.copying
app cache lock
app cache tmp
```

禁止清理：

```text
USB data/
本机 data-<root-id>/
OPENCLAW_HOME
OPENCLAW_STATE_DIR
.openclaw/openclaw.json
```
