## 1. 验证目标

确认 U-Claw 能否形成以下产品形态：

```text
无终端便携版
= 便携数据模型
+ 桌面 App 启动模型
+ Electron 主进程托管 OpenClaw Gateway
```

用户体验目标：

- 用户双击正式入口后，不看到 macOS Terminal。
- 用户双击正式入口后，不看到 Windows 控制台。
- 用户双击正式入口后，不看到独立 Gateway 终端。
- 启动复制、解压、等待锁、同步数据时，显示原生 Launcher 进度窗。
- App/Gateway ready 前，不先展示 Electron 空白窗或 Electron loading 窗。
- Gateway ready / App ready 后，直接进入 Dashboard 或 Config 页面。
- U-Claw App 后台启动 OpenClaw Gateway。
- 用户数据、配置、日志、记忆和备份全部留在 U 盘 `data/`。
- 本机 Data 工作缓存用于运行期高速读写，但不得成为用户数据唯一副本。
- 关闭 U-Claw 时，Gateway 和附属子进程被受控停止。
- 关闭 U-Claw 前先确认；确认后显示关闭进度。
- 正常退出执行 flush / fsync / checkpoint 和最终同步。
- 关闭后立刻再打开，不产生双进程、双弹窗，不卡 loading。
- 启动失败和运行错误可在 U 盘日志中排查。

这里的“无终端”按最终产品口径确认：

```text
macOS 正式入口：U-Claw Launcher.app
Windows 正式入口：U-Claw Launcher.exe
```

`Mac-Start-App.command` 和 `Windows-Start-App.bat` 只作为开发、诊断和过渡验证入口。它们不能作为最终“无终端便携版”验收依据。

## 2. 非目标

本验证不开发强制更新。

本验证不实现 Bootstrap 更新器。

本验证不修改 OpenClaw runtime。

本验证只确认无终端便携打包链路是否成立，以及当前缺口在哪里。

禁止在本轮执行：

```text
启动强制更新 P0/P1/P2
production.json / manifest.json / runtime.pkg 更新器
签名验签实现
staging/current 原子更新切换
强制更新 UI
用户跳过/继续旧版/选择版本
```

## 6. 必须验证的核心事实

### 6.1 无外部 Gateway 终端

验证点：

```text
启动 U-Claw 后，不出现专门运行 openclaw gateway run 的独立终端窗口。
```

允许出现：

- 用户主动从命令行启动时的命令行窗口。
- 调试环境中的开发终端。

正式便携发行不应出现：

```text
Starting OpenClaw Gateway on port ...
DO NOT close this window while using U-Claw
```

### 6.2 Electron 主进程托管 Gateway

验证点：

```text
Gateway 由 Electron 主进程 spawn。
```

预期命令形态：

```text
node openclaw.mjs gateway run --allow-unconfigured --force --port <port>
```

预期行为：

- Gateway 端口默认从 `18789` 开始。
- 端口占用时尝试后续端口。
- Gateway ready 后，主窗口加载本地 Dashboard。
- Gateway 异常退出时有日志。

### 6.3 便携数据目录强制生效

启动时必须设置或推导：

```text
UCLAW_PORTABLE_DATA_DIR=<USB>/data
UCLAW_PORTABLE_WORK_DATA_DIR=<HOST_CACHE>/data
OPENCLAW_HOME=<HOST_CACHE>/data
OPENCLAW_STATE_DIR=<HOST_CACHE>/data/.openclaw
OPENCLAW_CONFIG_PATH=<HOST_CACHE>/data/.openclaw/openclaw.json
OPENCLAW_DISABLE_BONJOUR=1
```

验证点：

- 启动时从 `<USB>/data` 初始化本机 Data 工作缓存。
- 运行期 `openclaw.json`、记忆、备份和日志可写入本机 Data 工作缓存。
- 关键变化通过 portable sync / journal / checkpoint 增量落盘到 `<USB>/data`。
- 不写入宿主机默认 `userData` 目录作为主数据目录。
- 本机 Data 工作缓存不得成为用户数据唯一副本。
- 不能把退出同步回 U 盘作为唯一保存机制。

### 6.4 退出时停止 Gateway

验证点：

```text
关闭 U-Claw App 后，Gateway 子进程退出。
```

预期流程：

```text
App before-quit/window-all-closed
-> stopGateway()
-> SIGTERM
-> 超时后 SIGKILL
```

关闭体验必须包含：

- 关闭确认弹窗。
- 确认后显示停止进度。
- 停止失败写入日志。
- 停止完成后进程和端口释放。

### 6.5 日志落盘

无终端后，stdout/stderr 必须落盘。

目标日志：

```text
data/logs/main.log
data/logs/gateway.log
data/logs/config-server.log
data/diagnostics/desktop-logs/uclaw-gateway.jsonl
```

验证点：

- Gateway stdout/stderr 没有丢失。
- 启动失败可从 U 盘日志定位。
- App 退出原因可记录。
- 日志脱敏。
- 日志轮转。

### 6.6 不依赖旧根 portable/

正式无终端便携版不得依赖旧根目录 `portable/` 的脚本模型。

验证点：

- 不再用 `portable/Windows-Start.bat` 作为正式 Gateway 宿主。
- 不再要求用户保持终端窗口打开。
- 旧 `portable/` 可保留为历史资产或开发参考，但不作为正式发布输入。

## 7. Windows 验证步骤

### 7.1 准备

构造测试目录：

```text
X:\U-Claw\
├─ U-Claw Launcher.exe
├─ Windows-Start-App.bat
├─ app\
│  └─ desktop-archive\
│     └─ u-claw-app-win-x64.zip
└─ data\
```

或最终结构：

```text
X:\U-Claw\
├─ U-Claw Launcher.exe
├─ app\current\
└─ data\
```

### 7.2 启动验证

执行：

```text
双击 U-Claw Launcher.exe
```

检查：

- 是否出现 Windows 控制台窗口。
- 是否先出现 Electron 空白窗。
- 是否在复制/解压/同步时看到原生进度窗。
- 是否出现独立 Gateway 终端。
- U-Claw App 是否启动。
- `127.0.0.1:<port>` 是否可访问。
- `data/.openclaw/openclaw.json` 是否存在。
- `data/logs/` 是否有日志。
- 旧盘更新后 `data/` 文件数量没有减少。
- 旧盘更新后 `data/.openclaw/openclaw.json` 未被新包覆盖。

### 7.3 进程验证

检查进程树：

```text
U-Claw.exe
└─ node.exe
   └─ openclaw.mjs gateway run
```

或等价形态。

重点确认：

- `node.exe` 是 U-Claw 内置 runtime。
- Gateway 不是由独立用户终端长期承载。

### 7.4 退出验证

操作：

```text
关闭 U-Claw App
```

检查：

- `node.exe` Gateway 子进程是否退出。
- 端口 `18789-18799` 是否释放。
- 日志是否记录退出。
- 立刻再次双击是否正常。
- 是否没有两个进度窗、两套 Gateway、两个 U-Claw App。

### 7.5 数据漂移验证

检查宿主机用户目录。

不应将主数据写入：

```text
%APPDATA%
%LOCALAPPDATA%
用户目录下 OpenClaw / U-Claw 默认 userData
```

允许写入：

- 系统临时目录中的短期缓存。
- 明确可重建的本机加速缓存。

但用户配置和业务数据必须持续回写到 U 盘 `data/`。

正常退出必须执行 flush / fsync / checkpoint 和最终同步。异常拔 U 盘时，允许丢最后一次未完成写入，但不得破坏既有 `data/`。

## 9. 当前代码已知基础

当前 `u-claw-app-dev/src/main.js` 已具备以下基础：

- `getPortableDataPath()` 支持 `UCLAW_PORTABLE_DATA_DIR`。
- 打包模式可检测 `.app` 旁边的 `portable/` 目录。
- `userDataPath = portablePath || app.getPath('userData')`。
- `startGateway()` 使用独立 Node runtime 拉起 OpenClaw Gateway。
- Gateway env 设置 `OPENCLAW_HOME`、`OPENCLAW_STATE_DIR`、`OPENCLAW_CONFIG_PATH`。
- `stopGateway()` 对 Gateway 发 `SIGTERM`，超时后 `SIGKILL`。
- `window-all-closed` 和 `before-quit` 调用停止逻辑。

当前过渡启动器 `u-claw-app-dev/scripts/Windows-Start-App.bat` 已设置：

```text
UCLAW_PORTABLE_DATA_DIR
OPENCLAW_HOME
OPENCLAW_STATE_DIR
OPENCLAW_CONFIG_PATH
OPENCLAW_DISABLE_BONJOUR
```

并启动：

```text
%LOCALAPPDATA%\U-Claw\usb-portable\app-win-x64\U-Claw.exe
```
