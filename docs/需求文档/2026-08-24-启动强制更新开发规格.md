## 1. 目标

实现启动前强制更新。

规则：

```text
用户能进入正式 UI
= 本次启动已成功联网确认版本
= 本地版本等于服务端 requiredVersion
```

非最新版必须自动下载、验签、安装、替换、重启。

用户不能跳过、稍后、继续旧版或选择版本。

## 2. 总体架构

更新由独立 Bootstrap 执行。

正式 Bavi-box App 不负责版本门禁。

启动链路：

```text
用户双击 Bavi-box 启动器
-> Bootstrap 进程启动
-> 读取本地 app/version.json
-> 下载 production.json
-> 验证 production.json
-> local.version == requiredVersion：启动正式 App
-> local.version != requiredVersion：下载 manifest + runtime.pkg
-> 验证 manifest + runtime.pkg
-> 安装到 staging
-> 停止正式 App / Gateway / 附属进程
-> 原子切换 current
-> 写入 app/version.json
-> 重新启动 Bootstrap
-> 再次版本门禁通过
-> 启动正式 App
```

## 3. 本地目录结构

U 盘根目录建议：

```text
Bavi-box/
├─ Bavi-box.exe / Bavi-box.command / Bootstrap
├─ app/
│  ├─ current/                 # 当前正式程序
│  ├─ staging/                 # 更新暂存目录
│  ├─ previous/                # 可选：上一稳定内容，仅用于事务恢复，不作为用户可选降级
│  ├─ version.json             # 当前已安装版本
│  └─ update-transaction.json  # 未完成事务记录
├─ data/
│  ├─ .openclaw/
│  ├─ logs/
│  ├─ memory/
│  └─ backups/
└─ bootstrap/
   ├─ updater 可执行文件
   └─ release-public-keys.json
```

正式更新只允许替换：

```text
app/current/
app/version.json
app/update-transaction.json
app/previous/      # 如果实现保留
```

禁止写入或覆盖：

```text
data/
data/.openclaw/
data/logs/
data/memory/
data/backups/
license/device 绑定材料
用户模型配置
聊天记录
记忆
```

## 4. 服务器目录结构

OSS / CDN 目录：

```text
releases/
├─ production.json
└─ packages/
   └─ v1.1.0/
      ├─ win-x64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      ├─ mac-arm64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      └─ mac-x64/
         ├─ manifest.json
         ├─ runtime.pkg
         ├─ runtime.pkg.sha256
         └─ sbom.json
```

上传顺序必须固定：

```text
1. runtime.pkg
2. runtime.pkg.sha256
3. sbom.json
4. manifest.json
5. production.json
```

`production.json` 必须最后替换。

## 5. 版本规则

Bavi-box 采用全产品单版本。

唯一版本字段：

```text
version
requiredVersion
```

示例：

```text
v1.1.0
```

禁止：

- 复用版本号。
- 降级 requiredVersion。
- Windows / macOS / 服务端版本不一致。
- 同一版本替换不同内容。

修复旧版本内容也必须发布新版本。

示例：

```text
v1.1.0 有严重 bug
-> 用 v1.0.0 内容重新构建 v1.1.1
-> production.requiredVersion = 1.1.1
```

## 6. production.json 规格

`production.json` 是全局强制版本指针。

字段：

```json
{
  "schemaVersion": 1,
  "requiredVersion": "1.1.0",
  "releaseId": "v1.1.0",
  "issuedAt": "2026-08-24T10:00:00Z",
  "expiresAt": "2026-08-31T10:00:00Z",
  "platforms": {
    "win32-x64": {
      "manifestUrl": "https://oss.example.com/releases/packages/v1.1.0/win-x64/manifest.json",
      "manifestSha256": "<sha256>"
    },
    "darwin-arm64": {
      "manifestUrl": "https://oss.example.com/releases/packages/v1.1.0/mac-arm64/manifest.json",
      "manifestSha256": "<sha256>"
    },
    "darwin-x64": {
      "manifestUrl": "https://oss.example.com/releases/packages/v1.1.0/mac-x64/manifest.json",
      "manifestSha256": "<sha256>"
    }
  },
  "signature": {
    "alg": "Ed25519",
    "keyId": "uclaw-release-2026-01",
    "value": "<base64url-signature>"
  }
}
```

校验规则：

- `schemaVersion` 必须支持。
- `requiredVersion` 必须合法。
- 当前平台必须存在于 `platforms`。
- `issuedAt` 不能在客户端当前时间之后过多。
- `expiresAt` 必须未过期。
- `signature` 必须通过。
- 签名失败、过期、平台缺失，一律阻断正式 UI。

## 7. manifest.json 规格

`manifest.json` 是平台包清单。

字段：

```json
{
  "schemaVersion": 1,
  "version": "1.1.0",
  "releaseId": "v1.1.0",
  "platform": "win32",
  "arch": "x64",
  "package": {
    "url": "https://oss.example.com/releases/packages/v1.1.0/win-x64/runtime.pkg",
    "size": 123456789,
    "sha256": "<sha256>",
    "format": "zip"
  },
  "runtime": {
    "entrypoint": "Bavi-box.exe",
    "treeDigest": "<sha256-tree-digest>",
    "openclawVersion": "2026.7.1-2",
    "nodeVersion": "24.15.0",
    "electronVersion": "35.0.0"
  },
  "publishedAt": "2026-08-24T10:00:00Z",
  "signature": {
    "alg": "Ed25519",
    "keyId": "uclaw-release-2026-01",
    "value": "<base64url-signature>"
  }
}
```

校验规则：

- `version` 必须等于 `production.requiredVersion`。
- `releaseId` 必须等于 `v${version}`。
- `platform` / `arch` 必须匹配当前机器。
- `package.size` 必须等于实际下载字节数。
- `package.sha256` 必须等于实际包哈希。
- `signature` 必须通过。
- `runtime.entrypoint` 必须存在于解包目录。
- `runtime.treeDigest` 必须匹配解包后的文件树摘要。

## 8. 签名规则

签名算法：

```text
Ed25519
```

签名对象：

```text
去掉 signature 字段后的 JSON canonical bytes
```

Canonical JSON 规则：

- UTF-8。
- object key 按字典序排序。
- 不保留无意义空白。
- string 使用标准 JSON escaping。
- number 禁止 NaN、Infinity。
- 时间统一 RFC3339 UTC。

客户端内置发布公钥。

公钥文件：

```text
bootstrap/release-public-keys.json
```

示例：

```json
{
  "keys": [
    {
      "keyId": "uclaw-release-2026-01",
      "alg": "Ed25519",
      "publicKey": "<base64url-public-key>",
      "status": "active"
    }
  ]
}
```

发布私钥禁止进入：

- OSS。
- U 盘。
- 客户端。
- Bootstrap。
- Git 仓库。

## 9. runtime.pkg 格式

首版建议：

```text
zip
```

要求：

- 包内路径必须相对。
- 禁止绝对路径。
- 禁止 `..` 路径穿越。
- 禁止 symlink / junction / reparse point。
- 禁止覆盖 `data/`。
- 解包后根目录必须能直接成为 `app/current/`。

包内示例：

```text
Bavi-box.exe
resources/
assets/
node_modules/
package.json
version.json
```

macOS 包内示例：

```text
Bavi-box.app/
version.json
```

`runtime.pkg` 只作为运输格式。

热启动不读取完整 `runtime.pkg`。

## 10. 本地 app/version.json

当前已安装版本文件：

```json
{
  "schemaVersion": 1,
  "version": "1.0.0",
  "releaseId": "v1.0.0",
  "platform": "win32",
  "arch": "x64",
  "installedAt": "2026-08-20T10:00:00Z",
  "manifestSha256": "<sha256>",
  "treeDigest": "<sha256-tree-digest>"
}
```

读取失败或缺失：

```text
视为 unknown version
必须走 production.json 检查
不能直接进入正式 UI
```

## 11. 更新事务

事务文件：

```text
app/update-transaction.json
```

字段：

```json
{
  "schemaVersion": 1,
  "id": "update-20260824-100000-v1.1.0",
  "targetVersion": "1.1.0",
  "state": "downloading",
  "manifestSha256": "<sha256>",
  "packageSha256": "<sha256>",
  "startedAt": "2026-08-24T10:00:00Z",
  "updatedAt": "2026-08-24T10:01:00Z"
}
```

状态：

```text
downloading
downloaded
verified
extracting
staged
stopping-app
switching
switched
restarting
complete
failed
```

事务规则：

- 每次状态变化先写事务。
- 关键文件写入后必须 fsync 或平台等效刷新。
- 切换前不得删除当前可运行版本。
- 切换成功后再写 `app/version.json`。
- 完成后删除或标记事务为 `complete`。

## 12. 事务恢复

Bootstrap 启动时必须先检查事务。

恢复规则：

```text
downloading/downloaded/verified/extracting
-> 清理 staging
-> 重新检查 production.json

staged
-> 重新校验 staging
-> 校验通过则继续 switching
-> 校验失败则清理 staging

switching/switched/restarting
-> 检查 current 和 version.json
-> current 完整且版本正确则 complete
-> current 不完整则阻断并重新下载目标版本

failed
-> 允许重试或退出
```

不得进入半更新状态。

不得破坏 `data/`。

## 13. Windows 替换策略

Windows 正在运行的 `.exe` 不能可靠覆盖自身。

因此：

- Bootstrap 必须独立于 `app/current/`。
- 正式 App 退出后，Bootstrap 才切换 `app/current/`。
- 正式 App 不自己覆盖自己。
- 如果 Gateway 残留，Bootstrap 必须等待或强杀由 Bavi-box 启动的进程。

建议流程：

```text
Bootstrap 检查更新
-> 需要更新
-> 下载并 staged
-> 如果正式 App 正在运行，请求其退出
-> 等待退出等待界面完成
-> 超时后按受控 pid 强杀
-> 重命名 app/current -> app/previous
-> 重命名 app/staging -> app/current
-> 启动新版本
```

## 14. macOS 替换策略

macOS 同样由 Bootstrap 切换。

规则：

- 不在运行中的 `.app` 内覆盖自身。
- 若从 DMG 运行，应阻断并提示把 Bavi-box 放到可写 U 盘目录。
- 正式便携版必须在可写目录运行。
- `.app` 数据不得写入宿主机用户目录。

建议：

```text
Bootstrap 位于 U 盘固定目录
app/current/Bavi-box.app 是可替换内容
```

## 15. 网络要求

更新请求要求：

- HTTPS。
- 禁止重定向到非 HTTPS。
- 禁止携带 License token、API key、用户配置。
- 固定超时。
- 限制 `production.json` 最大 1 MiB。
- 限制 `manifest.json` 最大 1 MiB。
- 下载 `runtime.pkg` 时限制最大字节数。

失败处理：

```text
无法确认最新版
-> 阻断正式 UI
-> 显示重试 / 退出
```

## 17. 日志

日志写入 U 盘：

```text
data/logs/bootstrap.log
data/logs/update.log
data/logs/main.log
data/logs/gateway.log
```

必须记录：

- 本地版本。
- 服务端 requiredVersion。
- production.json URL。
- manifest URL。
- 下载字节数。
- sha256 校验结果。
- 签名校验结果。
- 事务状态变化。
- App/Gateway 停止结果。
- 失败错误码。

必须脱敏：

- Authorization。
- Bearer token。
- API key。
- License secret。
- 用户模型 key。
- 本地绝对路径可按需截断。

## 19. 验收测试

必须覆盖：

1. 本地最新版：直接进入 License 门禁。
2. 本地旧版：自动更新到 requiredVersion。
3. 无网络：阻断正式 UI，仅允许重试/退出。
4. `production.json` 签名错误：阻断。
5. `manifest.json` 签名错误：阻断。
6. `runtime.pkg` SHA-256 错误：阻断，不覆盖 current。
7. 下载中断：下次能清理 staging 并重试。
8. 解包中断：下次能恢复，不破坏 current。
9. 切换中断：下次能识别 current/staging 状态。
10. 更新前后 `data/` 完整保留。
11. Gateway 正在运行时，更新能触发受控退出。
12. Windows 正在运行 EXE 不被直接覆盖。
13. macOS 不从只读 DMG 执行更新。
14. 平台不匹配包被拒绝。
15. 版本号复用内容不同被拒绝。

## 20. 发布验收

发布前必须验证：

```text
runtime.pkg sha256 与 manifest 一致
manifest 签名可验证
production.json 签名可验证
production.requiredVersion 与各 manifest.version 一致
OSS 路径可访问
production.json 最后上传
```

发布后抽检：

```text
旧版 U 盘启动
-> 自动更新
-> 重启后显示新 version
-> data/ 未变
-> Gateway 正常启动
```

## 21. 非目标

首版不做：

- 用户选择版本。
- 灰度发布。
- Beta 渠道。
- 用户主动检查更新入口。
- App 内跳过更新。
- 本地业务回滚按钮。
- 只更新 OpenClaw runtime。
- 覆盖用户数据。
