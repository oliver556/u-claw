# U-Claw 全产品单版本策略确认

- 日期：2026-08-24
- 文档类型：版本策略决策确认
- 状态：已确认
- 影响范围：客户端、服务端版本策略、更新 manifest、OSS 发布目录、U 盘本地版本文件、发布流程

## 1. 结论

U-Claw 采用全产品单版本策略。

对外和产品内只认一个版本号：

```text
U-Claw v1.1.0
```

客户端、服务端版本策略、各平台更新包、manifest 和本地版本文件必须同时归属同一个版本号。

不允许出现用户或运营需要理解的多套版本：

```text
客户端版本
服务端策略版本
runtime 版本
平台包版本
manifest 版本
```

这些都必须收口到同一个 U-Claw 产品版本。

## 2. 版本统一范围

当发布 `v1.1.0` 时，下列对象都必须是 `v1.1.0`：

- Windows 客户端更新包。
- macOS arm64 客户端更新包。
- macOS x64 客户端更新包。
- 服务端强制版本策略。
- OSS 发布目录。
- 各平台 `manifest.json`。
- U 盘本地 `app/version.json`。
- 产品界面展示版本。
- 运维和客服口径。

示例：

```text
客户端当前版本：v1.0.0
服务端要求版本：v1.1.0
结果：客户端必须更新到 v1.1.0
```

## 3. OSS 目录

推荐目录结构：

```text
releases/
├─ production.json
└─ packages/
   └─ v1.1.0/
      ├─ win-x64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      ├─ mac-arm64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      └─ mac-x64/
         ├─ manifest.json
         ├─ runtime.pkg
         ├─ runtime.pkg.sha256
         └─ sbom.json
```

`v1.1.0` 是唯一发布目录标识。

## 4. production.json

`production.json` 是当前全局强制版本指针。

示例：

```json
{
  "schemaVersion": 1,
  "requiredVersion": "1.1.0",
  "releaseId": "v1.1.0",
  "manifestBaseUrl": "https://oss.example.com/releases/packages/v1.1.0",
  "issuedAt": "2026-08-24T10:00:00Z",
  "expiresAt": "2026-08-31T10:00:00Z",
  "signature": {
    "keyId": "uclaw-release-2026-01",
    "value": "<signature>"
  }
}
```

客户端启动时读取该文件。

若本地版本不是 `requiredVersion`，正式 UI 不启动，必须更新。

## 5. manifest.json

每个平台和架构都有自己的 `manifest.json`。

但它们必须共享同一个 `version`。

示例：

```json
{
  "schemaVersion": 1,
  "version": "1.1.0",
  "releaseId": "v1.1.0",
  "platform": "win32",
  "arch": "x64",
  "packageUrl": "https://oss.example.com/releases/packages/v1.1.0/win-x64/runtime.pkg",
  "packageSize": 123456789,
  "packageSha256": "<sha256>",
  "treeDigest": "<digest>",
  "openclawVersion": "2026.7.1-2",
  "nodeVersion": "24.15.0",
  "publishedAt": "2026-08-24T10:00:00Z",
  "signature": {
    "keyId": "uclaw-release-2026-01",
    "value": "<signature>"
  }
}
```

`openclawVersion` 和 `nodeVersion` 只是审计字段，不作为产品对外版本。

## 6. 本地 version.json

U 盘本地必须保存当前已安装程序版本。

示例：

```json
{
  "version": "1.0.0",
  "releaseId": "v1.0.0",
  "platform": "win32",
  "arch": "x64",
  "installedAt": "2026-08-20T10:00:00Z"
}
```

启动比较规则：

```text
local.version == production.requiredVersion
→ 允许继续启动后续 License / Gateway 链路

local.version != production.requiredVersion
→ 必须下载安装 production.requiredVersion
```

## 7. 禁止规则

### 7.1 禁止复用版本号

同一个版本号发布后，不允许替换不同内容。

错误示例：

```text
v1.1.0 发布后发现 bug
重新上传另一个 v1.1.0 runtime.pkg
```

正确做法：

```text
发布 v1.1.1
```

### 7.2 禁止降级版本号

服务端不得把 `requiredVersion` 从高版本改回低版本。

错误示例：

```text
requiredVersion: 1.1.0
改回
requiredVersion: 1.0.0
```

正确做法：

```text
用上一稳定内容重新构建 v1.1.1
然后 requiredVersion 指向 v1.1.1
```

### 7.3 禁止平台版本不一致

同一次发布不能出现：

```text
Windows: v1.1.0
macOS: v1.0.9
服务端: v1.1.0
```

如果某个平台没有准备好，则整个 `v1.1.0` 不应成为正式版本。

## 8. 与 releaseSequence 的关系

产品策略不要求对外暴露 `releaseSequence`。

如果实现层需要内部单调序号，可作为隐藏字段存在。

但产品、运维、客服、客户端 UI、OSS 目录和服务端强制策略统一只使用：

```text
version
```

内部序号不得制造第二套用户可感知版本。

## 9. 发布顺序

上传顺序固定：

```text
1. 上传各平台 runtime.pkg
2. 上传 runtime.pkg.sha256 和 sbom.json
3. 上传各平台 manifest.json
4. 最后替换 production.json
```

`production.json` 一旦替换，用户下次启动就会被强制更新。

因此它必须最后发布。
