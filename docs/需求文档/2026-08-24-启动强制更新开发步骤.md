# U-Claw 启动强制更新开发步骤

- 日期：2026-08-24
- 文档类型：开发步骤 / 执行约束
- 状态：待开发
- 主规格：`docs/需求文档/2026-08-24-启动强制更新开发规格.md`
- 目标：把强制更新拆成可执行小步，防止开发时自行扩展、绕路或多做无关能力。

## 1. 总原则

本文件只定义开发顺序。

字段、包格式、签名、目录和验收以主规格为准：

```text
docs/需求文档/2026-08-24-启动强制更新开发规格.md
```

开发目录只允许：

```text
u-claw-app-dev/
docs/
```

禁止修改：

```text
u-claw-app/
product/
```

用户数据主库固定为：

```text
<U盘>/U-Claw/data/
```

宿主机只允许放可重建缓存。

禁止把聊天、配置、license、记忆、设备绑定材料作为唯一副本放到宿主机缓存。

## 2. 非目标

首轮开发禁止做：

```text
灰度发布
Beta 渠道
用户选择版本
用户跳过更新
稍后更新
继续旧版
App 内检查更新按钮
页面内更新入口
只更新 OpenClaw runtime
覆盖 data/
业务回滚按钮
多版本历史管理 UI
```

出现这些需求，先写新需求文档，不直接开发。

## 3. 开发批次

开发按以下批次推进。

每批完成后必须验证，再进入下一批。

```text
P0 文档口径统一
P1 本地目录与版本文件
P2 发布包生成
P3 签名与校验基础库
P4 Bootstrap 最小检查
P5 下载与 staging
P6 事务恢复
P7 current 原子切换
P8 启动正式 App
P9 App/Gateway 受控退出配合
P10 最小更新 UI
P11 日志与错误码
P12 Windows 真机验证
P13 macOS 真机验证
P14 发布验收
```

## 4. P0 文档口径统一

目标：

```text
统一“数据在 U 盘”口径。
统一“更新以启动强制更新开发规格为主”口径。
```

必须修改：

```text
docs/多人开发/便携版固定打包命令与版本矩阵.md
```

移除旧口径：

```text
宿主机缓存承载用户数据主库。
退出阶段批量同步作为唯一保存机制。
```

改为：

```text
U 盘 data/ 是权威便携主库。
本机 Data 工作缓存用于运行期高速读写。
运行中通过 portable sync / journal / checkpoint 增量落盘到 U 盘 data/。
正常退出执行 flush / fsync / checkpoint 和最终同步。
不能把退出同步回 U 盘作为唯一保存机制。
异常拔盘时不得破坏既有 data/。
```

验证：

```bash
rg -n "App 只读写电脑 Data 缓存|退出后.*同步回 U 盘|用户数据唯一主库|OPENCLAW_HOME/STATE/CONFIG 指向 U 盘 data|权威便携主库|Data 工作缓存|portable sync|journal|checkpoint" docs
```

通过标准：

```text
无文档再把本机缓存写成用户数据唯一主库。
```

## 5. P1 本地目录与版本文件

目标：

```text
建立更新所需本地结构，不实现联网更新。
```

只允许在 `u-claw-app-dev` 内开发。

需要形成的便携结构：

```text
U-Claw/
├─ app/
│  ├─ current/
│  ├─ staging/
│  ├─ previous/
│  ├─ version.json
│  └─ update-transaction.json
├─ data/
└─ bootstrap/
```

开发内容：

```text
1. 增加生成 app/version.json 的构建步骤。
2. version.json 使用主规格字段。
3. 确认 app/current/ 是正式 App 可替换目录。
4. 不改 data/ 写入位置。
```

验证：

```bash
cd u-claw-app-dev
npm run package:portable:customer
find release -name version.json -o -name update-transaction.json
```

通过标准：

```text
产物中有 app/version.json。
version 等于当前产品版本。
data/ 不被生成脚本覆盖。
```

## 6. P2 发布包生成

目标：

```text
从正式打包产物生成 runtime.pkg、runtime.pkg.sha256、manifest.json、sbom.json。
```

开发内容：

```text
1. 新增 release package 脚本。
2. 输入必须来自 u-claw-app-dev 正式打包产物。
3. runtime.pkg 首版使用 zip。
4. 包内路径必须相对。
5. 包内禁止 data/。
6. 输出 OSS 目录结构。
```

输出结构：

```text
releases/packages/v1.1.0/win-x64/
releases/packages/v1.1.0/mac-arm64/
releases/packages/v1.1.0/mac-x64/
```

验证：

```bash
find releases/packages -maxdepth 4 -type f | sort
shasum -a 256 releases/packages/v1.1.0/*/runtime.pkg
```

通过标准：

```text
runtime.pkg 解包后可直接成为 app/current/。
runtime.pkg 内无 data/。
sha256 文件与实际包一致。
```

## 7. P3 签名与校验基础库

目标：

```text
先实现可测试的签名、哈希、canonical JSON、treeDigest。
不接启动链路。
```

开发内容：

```text
1. canonical JSON 序列化。
2. Ed25519 验签。
3. sha256 文件校验。
4. runtime.pkg zip 安全检查。
5. treeDigest 计算。
6. release-public-keys.json 读取。
```

禁止：

```text
禁止把发布私钥放入 repo。
禁止跳过签名只靠 HTTPS。
```

验证：

```bash
npm test -- --runInBand
```

如果项目没有测试框架，先加最小脚本测试。

通过标准：

```text
签名正确通过。
签名篡改失败。
sha256 篡改失败。
zip 路径穿越失败。
treeDigest 篡改失败。
```

## 8. P4 Bootstrap 最小检查

目标：

```text
Bootstrap 能读取本地 version.json、下载 production.json、判断是否允许启动。
```

开发内容：

```text
1. 增加独立 Bootstrap 入口。
2. 支持读取 app/version.json。
3. 支持 HTTPS 下载 production.json。
4. 校验 production.json 签名、过期时间、平台字段。
5. local.version == requiredVersion 时启动正式 App。
6. 不一致时先阻断，不下载。
```

验证场景：

```text
本地最新版 -> 允许继续
本地旧版 -> 阻断并提示需要更新
无网络 -> 阻断
production 签名错 -> 阻断
production 过期 -> 阻断
```

通过标准：

```text
正式 App 只有在版本一致且 production.json 验证通过后启动。
```

## 9. P5 下载与 staging

目标：

```text
旧版本能下载 manifest 和 runtime.pkg，并解包到 staging。
仍不切换 current。
```

开发内容：

```text
1. 从 production.platforms 选择当前平台 manifestUrl。
2. 下载 manifest.json。
3. 校验 manifestSha256。
4. 校验 manifest 签名。
5. 校验 manifest.version == production.requiredVersion。
6. 下载 runtime.pkg。
7. 校验 size 和 sha256。
8. 安全解包到 app/staging/。
9. 校验 runtime.entrypoint 和 treeDigest。
```

验证场景：

```text
manifest 签名错 -> 失败
manifest version 不一致 -> 失败
runtime.pkg sha256 错 -> 失败
runtime.pkg size 错 -> 失败
zip 路径穿越 -> 失败
treeDigest 错 -> 失败
```

通过标准：

```text
staging 完整时可通过校验。
失败不影响 app/current/。
```

## 10. P6 事务恢复

目标：

```text
每一步写 update-transaction.json。
启动时能恢复未完成事务。
```

开发内容：

```text
1. 实现事务状态写入。
2. 状态变化先写事务。
3. 关键文件写入后 fsync 或平台等效刷新。
4. Bootstrap 启动时先读事务。
5. 按主规格恢复 downloading/downloaded/verified/extracting/staged/switching 等状态。
```

验证：

```text
人工制造事务文件到每个状态。
重启 Bootstrap。
检查恢复行为。
```

通过标准：

```text
不会进入半更新状态。
不会删除 data/。
不会破坏 current。
```

## 11. P7 current 原子切换

目标：

```text
staging 校验通过后，切换 app/current/。
```

开发内容：

```text
1. 切换前确认正式 App 未运行。
2. current -> previous。
3. staging -> current。
4. 写入 app/version.json。
5. 标记事务 complete。
6. 不提供用户降级入口。
```

Windows 规则：

```text
Bootstrap 必须独立于 app/current/。
不能覆盖正在运行的 U-Claw.exe。
```

macOS 规则：

```text
不能覆盖运行中的 .app。
只读 DMG 场景必须阻断。
```

验证：

```text
切换成功后 current 是新版本。
version.json 是新版本。
previous 只用于事务恢复，不暴露 UI。
```

## 12. P8 启动正式 App

目标：

```text
Bootstrap 门禁通过后启动 app/current/ 中正式 App。
```

开发内容：

```text
1. Windows 启动 app/current/U-Claw.exe。
2. macOS 启动 app/current/U-Claw.app。
3. 传入 U 盘 data 权威主库环境变量。
4. 传入本机 Data 工作缓存环境变量。
5. OPENCLAW_HOME 指向本机 Data 工作缓存。
6. OPENCLAW_STATE_DIR 指向本机 Data 工作缓存的 .openclaw。
7. OPENCLAW_CONFIG_PATH 指向本机 Data 工作缓存的 openclaw.json。
8. OPENCLAW_DISABLE_BONJOUR=1。
```

验证：

```text
正式 App 启动。
Gateway 由 Electron 主进程 spawn。
OpenClaw 读写本机 Data 工作缓存。
关键数据通过 portable sync / journal / checkpoint 增量落盘到 U 盘 data/。
```

## 13. P9 App/Gateway 受控退出配合

目标：

```text
更新前能让正式 App、Gateway、Config Server、附属进程受控退出。
```

开发内容：

```text
1. 正式 App 暴露受控退出方式。
2. Bootstrap 更新前请求 App 退出。
3. App 显示退出等待状态。
4. App 停 Gateway。
5. App 停 Config Server。
6. App 停 video adapter / 附属子进程。
7. flush 日志和关键状态。
8. 超时后 Bootstrap 只强杀 U-Claw 启动的 pid。
```

验证：

```text
更新时 Gateway 不残留。
18789-18799 端口释放。
日志记录退出原因。
```

## 18. P14 发布验收

目标：

```text
发布物可安全放到 OSS / CDN。
```

发布前检查：

```text
runtime.pkg sha256 与 manifest 一致
manifest 签名可验证
production.json 签名可验证
production.requiredVersion 与各 manifest.version 一致
platform / arch 覆盖 win32-x64、darwin-arm64、darwin-x64
OSS 路径可访问
production.json 最后上传
```

发布后抽检：

```text
旧版 U 盘启动
-> 自动更新
-> 重启后显示新 version
-> data/ 未变
-> Gateway 正常启动
```

## 19. 停止条件

遇到以下情况，必须停止继续叠功能：

```text
App 打不开
Gateway 起不来
文本对话失效
U 盘 data 路径漂移
Windows 或 macOS 任一平台启动失效
打包产物依赖宿主机 Node/Python/npm
更新失败后破坏 current
更新过程覆盖 data/
签名或 sha256 可被绕过
用户可跳过更新进入正式 UI
```

停止后只允许：

```text
定位问题
修复当前批次
补验收记录
```

不得继续开发下一批。
