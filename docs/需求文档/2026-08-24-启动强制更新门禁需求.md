# U-Claw 启动强制更新门禁需求

- 日期：2026-08-24
- 文档类型：未开发需求 / P0 产品策略
- 状态：已确认方向，待开发
- 影响范围：Bootstrap、更新服务、OSS 发布物、启动链路、License 门禁、Gateway 启动、正式 UI

## 1. 背景

U-Claw 处于持续高频迭代期。

用户不会稳定主动更新。如果允许旧版本长期运行，会带来：

- 客户端和服务端协议不一致。
- 激活、支付、模型配置和渠道逻辑不一致。
- SkillHub、Gateway、OpenClaw patch 行为不一致。
- 客服排查成本上升。
- 老版本 bug 长期存在。

因此，U-Claw 必须采用启动强制更新。

用户只有在本机程序已经是服务端要求的最新版本时，才能进入正式产品。

## 2. 核心结论

启动强制更新必须发生在正式 App 之前。

规则：

```text
能进入正式 UI
= 已完成本次启动版本检查
= 本地版本等于服务端 requiredVersion
```

如果本地不是最新版，客户端必须自动下载、验证、安装并替换当前程序版本。

用户不能：

- 跳过更新。
- 稍后更新。
- 忽略版本。
- 继续使用旧版本。
- 选择旧版本启动。

## 3. 启动顺序

目标启动链路：

```text
用户双击 U-Claw
-> Bootstrap 启动
-> 检查本地路径和基础运行环境
-> 联网读取 production.json
-> 校验 production.json 签名和有效期
-> 读取本地 app/version.json
-> 对比 local.version 与 production.requiredVersion
-> 版本一致：继续 License 门禁
-> 版本不一致：自动更新
-> 更新完成后重启 U-Claw
-> 再次检查版本
-> License 门禁通过
-> 启动正式 shell
-> 启动 OpenClaw Gateway
-> 进入正式 UI
```

正式 UI 不承担版本检查和更新入口职责。

## 4. 服务不可用策略

强制更新策略下，无法确认最新版时，不允许进入正式 UI。

包括：

- 没有网络。
- DNS 失败。
- TLS 失败。
- OSS/CDN 不可访问。
- `production.json` 下载失败。
- `production.json` 过期。
- `production.json` 验签失败。
- 服务端返回格式错误。

客户端显示最小阻断状态：

```text
无法连接更新服务，请检查网络后重试
```

允许操作：

- 重试。
- 退出。

不允许操作：

- 跳过。
- 继续旧版。
- 离线进入正式 UI。

## 5. 版本判断

U-Claw 采用全产品单版本策略。

服务端：

```json
{
  "requiredVersion": "1.1.0"
}
```

本地：

```json
{
  "version": "1.0.0"
}
```

判断规则：

```text
local.version == production.requiredVersion
→ 允许继续启动

local.version != production.requiredVersion
→ 必须自动更新
```

版本号禁止复用。

如果 `v1.1.0` 发布后发现问题，不能重新上传另一个 `v1.1.0`。

必须发布：

```text
v1.1.1
```

## 6. 更新发布物

OSS / CDN 上至少提供：

```text
releases/
├─ production.json
└─ packages/
   └─ v1.1.0/
      ├─ win-x64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      ├─ mac-arm64/
      │  ├─ manifest.json
      │  ├─ runtime.pkg
      │  ├─ runtime.pkg.sha256
      │  └─ sbom.json
      └─ mac-x64/
         ├─ manifest.json
         ├─ runtime.pkg
         ├─ runtime.pkg.sha256
         └─ sbom.json
```

`production.json` 是全局强制版本指针。

`manifest.json` 是平台包签名清单。

`runtime.pkg` 是程序更新包。

`runtime.pkg.sha256` 用于人工和运维核验。

`sbom.json` 用于依赖审计和问题追溯。

## 7. 校验要求

客户端必须校验：

- `production.json` 签名。
- `production.json` 有效期。
- `manifest.json` 签名。
- `manifest.json` 的 `version` 是否等于 `production.requiredVersion`。
- `platform` 是否匹配当前系统。
- `arch` 是否匹配当前架构。
- `runtime.pkg` 下载大小。
- `runtime.pkg` SHA-256。
- 包内文件树摘要。

不能只依赖 HTTPS。

HTTPS 只保护传输链路。

签名和哈希保护发布物本身。

## 8. 安装替换要求

更新不能边下载边覆盖当前程序。

必须使用 staging：

```text
下载 runtime.pkg 到 staging
-> 校验完整性
-> 解包到 staging runtime
-> 写入待切换事务
-> 请求当前 App 停机
-> 停 Gateway / Config Server / 附属子进程
-> 原子切换 current
-> 写入 app/version.json
-> 重启 U-Claw
```

中途断电或异常退出时，下次 Bootstrap 必须能处理未完成事务：

```text
发现未完成事务
-> 判断 staging 是否完整
-> 完整则继续完成切换
-> 不完整则清理 staging
-> 重新读取 production.json
```

## 9. 数据保护

更新只允许替换程序内容。

允许更新：

```text
app/
runtime/
resources/
assets/
manifest/version 文件
```

禁止覆盖：

```text
data/
data/.openclaw/
data/logs/
data/memory/
data/backups/
用户模型配置
聊天记录
记忆
激活材料
设备绑定材料
license 文件
```

更新不是换盘。

更新不得重新消耗激活码。

更新不得重置用户配置。

## 10. 更新界面

启动阶段必须提供最小状态反馈。

建议状态：

```text
正在检查版本
发现新版本 v1.1.0
正在下载更新
正在验证更新
正在安装更新
正在重启 U-Claw
无法连接更新服务
更新失败，请重试
```

允许按钮：

```text
重试
退出
```

禁止按钮：

```text
跳过
稍后更新
继续旧版
降级
选择版本
```

## 11. 回滚策略

客户端没有本地业务回滚入口。

如果新版本有严重问题，不能让服务端指回旧版本。

错误做法：

```text
requiredVersion: 1.1.0
改回
requiredVersion: 1.0.0
```

正确做法：

```text
用上一稳定内容重新构建 v1.1.1
requiredVersion = 1.1.1
```

客户端始终向前更新。

服务端可保留上一稳定内容，用于快速构建更高版本的修复包。

## 12. 与 License 门禁关系

版本门禁必须早于 License 门禁。

顺序：

```text
版本门禁
-> License 门禁
-> Gateway 启动
-> 正式 UI
```

原因：

- License 离线宽限不能绕过强制更新。
- 旧版本不能因为本地 License 有效而继续使用。
- 正式 UI 的前置事实必须是“当前版本已确认最新”。

## 13. 与无终端便携版关系

本需求适用于无终端便携版。

无终端便携版中：

- Bootstrap 负责版本门禁和安装替换。
- Electron 主进程负责正式 App 和 Gateway 生命周期。
- 用户数据强制留在 U 盘 `data/`。
- 更新过程不能把数据写到宿主机用户目录。

## 14. 验收标准

### 14.1 最新版本启动

本地 `version` 等于服务端 `requiredVersion`。

结果：

```text
继续 License 门禁
继续 Gateway 启动
进入正式 UI
```

### 14.2 旧版本启动

本地 `version` 低于服务端 `requiredVersion`。

结果：

```text
正式 UI 不启动
自动下载更新
验签和校验通过
安装替换
重启后进入最新版
```

### 14.3 更新服务不可用

无法获取或验证 `production.json`。

结果：

```text
正式 UI 不启动
显示阻断状态
仅允许重试或退出
```

### 14.4 发布物被篡改

篡改 `manifest.json` 或 `runtime.pkg`。

结果：

```text
更新失败
当前程序不被覆盖
正式 UI 不启动
记录脱敏错误日志
```

### 14.5 更新中断

下载、解包或切换中断。

结果：

```text
下次启动能识别未完成事务
不会进入半更新状态
不会破坏 data/
```

### 14.6 用户数据保护

更新前后对比：

```text
data/.openclaw/
data/memory/
data/logs/
license/device 绑定材料
用户模型配置
```

必须保留。
