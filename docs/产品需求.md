## 1. 产品定位

U-Claw 是一个随 U 盘携带的 AI 工作空间。用户将 U 盘插入受支持的电脑，双击 `U-Claw.exe` 即可继续使用同一套配置、记忆、聊天记录和工作数据。

产品不是“将网页启动脚本拷贝到 U 盘”，而是可双击启动、不显示终端和浏览器地址栏的独立桌面客户端。

## 2. 目标用户场景

1. 用户首次将 U 盘插入一台新电脑。
2. 用户双击 U 盘根目录中的 `U-Claw.exe`。
3. 程序在本机准备可删除的运行环境缓存，同时立即显示启动界面。
4. 运行环境就绪后，客户端启动 OpenClaw 并进入主界面。
5. 用户退出并再次启动时，程序复用本机缓存，不再重复解压完整运行环境。
6. 用户换到另一台受支持的电脑时，首次准备流程重新执行，但工作数据仍来自同一个 U 盘。

## 3. 已确认的产品范围

### 3.1 首发平台

- Windows 10 64 位 x64。
- Windows 11 64 位 x64。
- 普通用户权限可启动，不要求管理员权限。
- 首发版不要求同一个包同时支持 macOS、Windows ARM 或 Linux。

### 3.2 客户端体验

- U 盘根目录中只展示一个主启动入口：`U-Claw.exe`。
- 双击后应尽快显示可见界面，不能长时无反馈。
- 使用 Electron 提供桌面窗口，由自建 React + Vite 前端提供主界面。
- 用户不需要手动打开 Chrome、Edge 或终端。
- 程序应明确展示首次准备、启动网关、就绪和失败状态。
- 出现错误时应有用户可理解的提示，并保留可诊断日志。

### 3.3 运行环境

- Node.js、OpenClaw、Electron 和所需 `node_modules` 随发行包提供。
- 客户不需要预先安装 Node.js、OpenClaw、npm 或开发工具。
- Node.js 基线使用 OpenClaw 明确支持的 `v24.15.0`。
- 运行环境以版本化大包存放于 U 盘隐藏目录，不以两万多个散文件直接运行。
- 首次在某台电脑上启动时，运行环境解压到本机 SSD 缓存。
- 本机缓存只包含可重建的程序文件，删除后不得导致用户数据丢失。

### 3.4 数据归属

以下数据必须始终保存在 U 盘：

- OpenClaw 配置。
- 模型 API Key 及服务商配置。
- 聊天记录。
- AI 记忆。
- 用户工作文件和业务数据。
- 用户安装或启用的个性化技能与配置。
- 授权文件及与 U 盘绑定的必要元数据。

本机可保留：

- 按版本和包哈希区分的运行环境缓存。
- 不含 API Key、聊天、记忆和业务内容的启动诊断信息。

### 3.5 U 盘可移植性

- 更换电脑后，用户应继续使用 U 盘中同一套数据。
- 程序不得依赖固定盘符。
- 运行期间不得将数据目录默认切换到 `%APPDATA%` 或其他本机用户目录。
- U 盘移除或失联时，客户端应阻止继续写入，并安全停止相关进程。
- 拔出 U 盘后，本机缓存不得作为一套可独立使用的 U-Claw 产品继续运行。

## 4. 启动性能目标

当前已确认的问题是：U 盘直接运行约 916 MB、2.4 万个散文件时，窗口出现约 2 分钟，完整进入可能超过 5 分钟。该体验不可交付。

第一阶段验收时必须记录：

- 双击到首个可见窗口的时间。
- 新电脑首次准备运行环境的时间。
- 同一电脑第二次启动到主界面可用的时间。
- OpenClaw gateway 启动耗时。
- Windows Defender 开启时的实际表现。

精确秒数指标尚未经真实 Windows 10/11 设备基准测试确认，不在本文档中虚构。

## 5. U 盘文件展示要求

普通用户看到的根目录：

```text
U 盘根目录
├── U-Claw.exe
└── .uclaw/       隐藏目录
```

`.uclaw/` 用于收纳运行包、数据、授权和版本信息。隐藏属性只负责界面整洁，不作为真正的防复制手段。

## 6. 第三阶段授权与内置模型服务

第三阶段在第一、二阶段客户端能力完成后实施，目标是正式产品盘制作、启动授权和默认开箱即用的模型服务。

- 每个产品盘制作时生成随机唯一 `device_id` 和独立启动凭据，并登记到自有后端数据库。
- 发货前为激活码人工预配置 New API 用户、API Key、默认模型和允许模型；New API Key 只在验证服务器加密保存。
- 用户首次启动只输入激活码；服务端绑定当前 U 盘后下发长期设备访问令牌，不下发 New API Key。
- `U-Claw.exe` 启动依赖隐藏独立密钥和签名授权文件；启动密钥不得与模型服务 Token 复用。
- 内置 New API 是未配置外部模型时的隐藏默认服务。客户端只访问验证服务器的模型代理；New API URL、用户名和 Key 不向用户展示或开放编辑。
- 企业商家的上游 Key 只保存在自有 New API 服务端，不进入 U 盘。
- 验证服务器逐请求校验设备令牌、License 和设备状态，再用对应 New API Key 代理请求；自有 New API 按账户管理余额、额度、限速和模型权限。

第一版权威流程见 [激活码、长期设备令牌与模型代理设计](./superpowers/specs/2026-08-13-激活码长期设备令牌与模型代理设计.md)。短期模型 Token、`expiresAt` 和客户端刷新不属于第一版。

原项目的国产模型和 OpenAI-compatible 纯自定义模型配置继续保留。用户启用任一外部模型源后，推理请求不再经过内置服务；外部服务失败时不得静默回退。用户清除或关闭外部配置后，恢复使用隐藏内置服务。

安全边界定位为“防君子”：只复制可见 `U-Claw.exe` 且缺少隐藏启动凭据时不能启动；不承诺抵抗完整磁盘镜像、逆向或硬件级复制。完整复制得到同一授权时，共享同一 New API 账户、额度、限速和封禁状态。普通格式化会清空程序、授权和用户数据，产品不承诺格式化后继续运行。

## 7. U 盘与文件系统

- 开发和 Mac/Windows 跨平台制作阶段可使用 exFAT。
- 正式 Windows 客户产品盘优先使用 NTFS。
- NTFS 的主要优势是日志恢复、频繁数据写入稳定性和 Windows 原生支持，不是保证启动速度更快。
- U 盘性能重点看 4K 随机读写，不只看 USB 3.1 标识和顺序读写峰值。
- macOS 默认不能可靠写入 NTFS。旧版 Tuxera NTFS 不得用于制作正式盘。

## 8. 非功能要求

- 运行包必须有版本号和完整性哈希。
- 本机缓存损坏时能重建，不破坏 U 盘数据。
- 并发双击不得启动多个 gateway 或同时修改数据。
- 程序退出时必须停止子进程并刷新待写数据。
- 日志默认不得记录 API Key 和对话正文。
- 更新运行包时必须保留 `.uclaw/data/`。

## 9. 第一阶段验收条件

- 新的 Windows 10/11 x64 电脑无需安装 Node.js 即可启动。
- 双击后及时显示窗口和当前启动状态。
- 首次运行完成本机 runtime 缓存。
- 第二次启动复用缓存，不再全量解压。
- 配置、API Key、聊天、记忆和工作数据均可验证地保存在 U 盘。
- 换一台电脑后，可使用同一个 U 盘继续工作。
- 删除本机 runtime 缓存后，再启动可自动重建，用户数据不受影响。
- 程序退出后，不留下孤立 OpenClaw 或 Node.js 进程。

## 10. 待确认项

- 首次启动和二次启动的具体秒数指标。
- 本机 runtime 缓存的最终路径和自动清理策略。
- API Key 是否需要额外加密，以及密钥如何在换机时保持可用。
- U 盘硬件标识的选取和兼容范围。
- 授权许可证的签发、续期、撤销和离线容错规则。
- runtime 更新包的发布、回滚和数据迁移流程。
- 程序运行中 U 盘被强制拔出时的最终交互。
