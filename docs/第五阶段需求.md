# U-Claw 第五阶段需求：助手库

> 文档状态：已确认助手库与上线版能力精简方向，待设计与实施
>
> 记录日期：2026-08-13
> 前置条件：第四阶段 Agent 管理、会话、Skill 与记忆真实接线可用

## 1. 阶段目标

建设类似 NextChat Mask 的“助手库”，将 OpenClaw Agent 的本地文件配置封装成可视化模板。

用户不需要手工创建 Workspace，也不需要自己编辑 `AGENTS.md`、`SOUL.md`、`IDENTITY.md` 等文件。选择一个助手后即可开始对话。

助手库作为 U-Claw 对外主要卖点之一：

```text
选择助手
-> 一键添加
-> 自动创建 OpenClaw Agent 和 Workspace
-> 写入身份、行为、记忆与推荐 Skill 配置
-> 创建绑定该 Agent 的会话
-> 立即使用
```

## 2. 产品定义

- **Agent**：长期存在的助手实例，拥有独立身份、Workspace、记忆、默认模型和会话。
- **助手模板**：用于生成 Agent 的可安装预设，不是正在运行的 Agent。
- **Skill**：助手可调用的专项能力，不代替 Agent 身份。
- **记忆**：归属具体 Agent，跨会话保存。

助手模板与 Skill 可组合，但必须分开安装、更新和权限确认。

## 3. 功能需求

### `ASSISTANT-001` 助手库

- 按分类、关键词和场景浏览助手模板。
- 展示名称、头像、简介、适用场景、默认模型、推荐 Skill 和权限摘要。
- 首版至少包含通用、编程、文案、翻译、数据分析等内置助手。

### `ASSISTANT-002` 一键添加助手

- 从模板一键创建真实 OpenClaw Agent。
- 自动生成独立 Workspace，并写入模板声明的 Agent 文件。
- 创建前展示将写入的文件、Skill 依赖和权限。
- 任何一步失败时不留下半成品 Agent。

### `ASSISTANT-003` 助手使用闭环

- 新建会话时可选择已添加助手。
- 会话明确绑定 Agent，整段会话持续使用该 Agent 的身份、Workspace、记忆和默认模型。
- 对话页明确显示当前助手，不与“下一条消息使用的 Skill”混淆。
- 刷新、重启、换机后，会话与 Agent 绑定保持一致。

### `ASSISTANT-004` 我的助手

- 查看、启用、停用、复制和删除已添加助手。
- 以表单编辑名称、头像、说明、默认模型、身份和行为规则。
- 提供高级文件编辑入口，但不强迫普通用户直接编辑 Markdown。
- 删除前说明会话、记忆和 Workspace 的保留策略。

### `ASSISTANT-005` 记忆与 Skill 组合

- 按 Agent 查看和管理 `MEMORY.md` 及 `memory/**/*.md`。
- 为助手配置默认启用的已安装 Skill。
- 模板依赖的 Skill 未安装时，引导用户确认安装；禁止静默获取高风险能力。
- Skill 被禁用或卸载后，助手显示可恢复诊断，不伪报能力可用。

### `ASSISTANT-006` 模板来源与安全

- 内置模板随 U-Claw 发行版提供，断网也可添加。
- 模板不携带 API Key、Token、用户记忆或其他秘密。
- 外部助手目录属于后续扩展；接入时必须有来源、版本、完整性校验、风险提示和更新回滚。

## 4. 验收标准

1. 新用户不编辑本地文件，从助手库选择模板后可直接对话。
2. 新助手必须对应真实 OpenClaw Agent，不是仅在前端插入一段提示词。
3. 会话、Agent、Workspace、记忆和 Skill 关系可从后端或权威文件读回。
4. 重启客户端和更换电脑后，U 盘中的助手及其数据保持可用。
5. 助手模板、Agent 和 Skill 在 UI 中概念分明，用户不需要理解 OpenClaw 目录结构。

## 5. 非本阶段范围

- 不自建新 Agent 运行引擎，继续使用 OpenClaw Agent。
- 不把 Skill 目录直接复制成助手库。
- 首版不建设付费助手市场、创作者分成或账号同步。

首版“能力”页只向普通用户展示 Skill，从页面导航隐藏以下入口：

- Plugin 和 MCP 可作为内部基础设施继续运行，普通用户不直接管理。

### 6.2 SkillHub 与本地 Skill 管理

首版不在 U-Claw 中复制腾讯 SkillHub 的搜索、分类和目录界面。

```text
发现更多 Skill
-> 调用系统默认浏览器
-> 打开 https://skillhub.cloud.tencent.com/skills
```

U-Claw 内部只负责本地已安装 Skill 管理：

- 已安装列表。
- 启用和禁用。
- 更新和卸载。
- 权限与风险提示。
- 依赖缺失和 OpenClaw 实际可用状态。

当前代码接入的 `api.skillhub.cn` 与本阶段指定的腾讯 SkillHub 不是同一产品入口，不得把前者的“SkillHub 在线”状态当作已接入腾讯 SkillHub。

腾讯 SkillHub 到 U-Claw 的安装交接方式暂未确认。后续只从以下可验证方式中选择，不让普通用户手工输入终端命令：

- 网站通过受控协议链接唤起 U-Claw 安装。
- 用户将 SkillHub 详情页链接粘贴到 U-Claw 安装。
- 用户下载后，由 U-Claw 导入受支持的 Skill 包。

### 6.3 Plugin 内部化

Plugin 管理界面首版隐藏，但 Plugin 能力继续保留。

需要 Plugin 的用户功能必须被 U-Claw 封装成业务流程。以个人微信为例：

```text
连接 -> 个人微信
-> 用户填写必要信息或扫码
-> U-Claw 内部检查、安装、启用和更新所需 Plugin
-> 完成登录与状态验证
-> 用户只看到可发送、可接收或可恢复的业务状态
```

用户不需要理解 Plugin 名称、版本、安装路径、CLI 或配置文件。Plugin 问题在普通界面中转换为业务化错误，底层信息仅供诊断日志和高级控制台使用。

### 6.3.1 个人微信产品边界

个人微信使用腾讯 `@tencent-weixin/openclaw-weixin` 通道插件。用户使用普通手机微信扫码授权，不需要：

- 申请微信公众号。
- 申请企业微信。
- 创建开放平台 AppID 或 AppSecret。
- 搭建机器人服务器。
- 使用 CLI 或手工安装 Plugin。

该能力是“通过微信与 U-Claw Agent 对话”，不是接管用户个人微信账号。产品不得宣称能读取全部私人聊天、代替用户向任意联系人发消息，或自动操作微信桌面客户端。

### 6.3.2 发行包与版本管理

1. 正式 runtime 必须随包内置并锁定经验证的 `@tencent-weixin/openclaw-weixin` 版本。
2. 构建清单记录 Plugin 包名、版本、完整性哈希和支持的 OpenClaw 版本范围。
3. 启动时校验 Plugin 存在、版本、文件完整性和 OpenClaw 兼容性。
4. Plugin 缺失或损坏时，优先从已签名的本地 runtime 修复；首版不要求用户联网下载。
5. Plugin 升级必须跟随 U-Claw runtime 发行和回滚，不允许普通用户单独升级到未验证版本。

### 6.3.3 扫码登录流程

```text
用户进入“连接 -> 个人微信”
-> U-Claw 检查 Plugin 与 Gateway 状态
-> 点击“扫码连接”
-> Electron 请求腾讯 iLink Bot 二维码
-> UI 显示二维码与到期时间
-> 普通手机微信扫码
-> 用户在手机端确认授权
-> U-Claw 轮询获取 bot account 和 token
-> 凭据原子写入 U 盘受控目录
-> 内部启用 Plugin 并启动微信通道
-> 从 Gateway 读回 connected 状态
-> UI 显示“已连接”
```

二维码流程必须支持：生成、等待扫码、等待手机确认、到期、刷新、取消、网络中断和登录失败。旧二维码刷新后必须失效，禁止多个并发登录流程写入不同凭据。

### 6.3.4 账号与凭据存储

- bot token、account ID 与登录状态只写入 U 盘受控数据目录，不进入 renderer 持久状态、日志、诊断导出或宿主机用户目录。
- 凭据文件使用最小访问权限和原子写入，禁止符号链接、路径穿越和非受控文件覆盖。
- UI 只显示用户可识别的账号摘要，不返回完整 token。
- 同一 U 盘换机后应可读取既有账号状态；若腾讯端要求重新授权，显示“需重新扫码”，不伪报已连接。

### 6.3.5 消息收发与 Agent 路由

1. 微信入站消息必须经 Plugin 到 OpenClaw Gateway，再进入真实 Agent，不使用 UI mock 回复。
2. 支持至少文本收发；图片、语音、文件、视频和引用消息按插件实际能力验收。
3. 每条入站消息必须有稳定的 account/channel/peer 会话边界，避免不同微信用户混用上下文。
4. 回复失败、鉴权失效、限流、网络中断和 Gateway 重启必须分类展示，不得只显示“未连接”。
5. 需要确认的工具调用仍遵守 U-Claw 审批和风险策略，不因消息来自微信而自动放开高风险权限。

### 6.3.6 重连、退出与清理

- Gateway 或通道短暂中断后，用户可点击“重新连接”；已有凭据有效时不重复扫码。
- 凭据无效时明确进入“需重新扫码”状态。
- “退出登录”必须先停止通道，再清理 U 盘账号索引和凭据，最后读回确认已清空。
- 退出 Electron、拔出 U 盘和卸载后，宿主机不得留下可识别账号、token、二维码或消息内容。

### 6.3.7 用户界面状态

普通界面只显示业务状态：

- 检查中。
- 未连接。
- 等待扫码。
- 已扫码，等待手机确认。
- 二维码已过期。
- 已连接。
- 连接中断，可重连。
- 授权失效，需重新扫码。
- 组件损坏，需修复或更新 U-Claw。

普通界面不显示 npm 包名、Plugin ID、CLI 命令、token、Gateway RPC 或本地文件路径。

### 6.4 MCP 首版隐藏

- 普通用户不看到 MCP Server、stdio、SSE、tool/resource/prompt 等技术配置。
- 已配置或内置功能依赖的 MCP 仍可由 U-Claw 内部管理和运行。
- 后续只在明确的高级或开发者模式中重新开放 MCP 管理。

### 6.5 本地软件操作边界

隐藏 Plugin 和 MCP 不得导致本地操作能力被删除：

- 本地软件提供 CLI 或 API 时，优先使用 OpenClaw 内置工具或 Skill，并继续使用执行审批和风险控制。
- 需要专用扩展时，可由 U-Claw 内部管理 Plugin 或 MCP，不将技术细节暴露给普通用户。
- 只有图形界面的 Windows 软件需要独立的 UI Automation 能力和真机验收，不得因为 Plugin 或 MCP 存在就宣称已完成。

## 7. 自动化模板库边界

当前 U-Claw 只具备 Agent 管理、Cron 定时任务和运行历史，没有可一键安装的自动化模板库。

自动化模板库与助手库分开：

- 助手库创建长期 Agent。
- 自动化模板库创建定时或触发式任务，例如每日报告、定时整理文件。

为保证快速上线，自动化模板库本阶段只记录产品边界，不纳入首版阻断范围。现有 Cron 和 Agent 管理能力继续保留。
