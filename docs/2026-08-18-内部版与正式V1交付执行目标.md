# Bavi-box 内部员工版与正式 V1 交付执行目标

> 用途：作为后续 Codex 执行入口。本文是汇总执行目标，不替代五阶段需求、联调矩阵、授权方案和更新设计；原文档仍是具体契约的权威来源。
>
> 基线日期：2026-08-18
>
> 版本策略：先完成“内部员工可用版”，再完成“正式 V1”。两版共用同一套产品代码、Launcher、Electron、Gateway、Adapter 和 U 盘数据架构。

## 1. 目标与口径

### 1.1 内部员工可用版

员工可在自己的 Windows 电脑上，把产品安装到 U 盘后使用：

- 启动 Bavi-box。
- 完成内部授权或内部激活。
- 使用真实工作会话和模型对话。
- 使用能力模块中的本地 Skill。
- 使用个人微信连接；若真实微信尚未收口，必须明确关闭该入口，不得伪报可用。
- 打开系统设置，使用外观和更新。
- 公司统一管理模型额度；不提供充值页面和支付能力。

内部版不是正式发行版。允许使用公司内部服务、内部 feed、内部账号和受控测试策略，但不得把上游 Provider/New API Key 写入 EXE、U 盘、renderer、日志或员工可读配置。

### 1.2 正式 V1

正式 V1 只交付《首个版本功能隐藏记录》保留的用户表面：

- 工作与会话。
- 能力。
- 连接中的个人微信。
- 系统中的发布更新、外观。
- U 盘、Gateway、任务活动中心和窗口控件。
- 启动授权、U 盘绑定、模型代理和真实模型对话。

以下项目暂不作为 V1 用户入口，但底层代码和协议保留：文件、记忆、自动化、Telegram、QQ Bot、飞书、企业微信、Discord、诊断、设备与运行、语音与通知、产品授权、备份与存储、全局搜索和顶栏模型状态。

余额充值、支付、自动充值不属于 V1；但正式 V1 激活前必须由运营人员准备可用的模型账户和余额策略。

## 2. 不可改变的安全规则

1. 激活码不是 API Key。一个正式激活码只能绑定一个 U 盘。
2. 设备令牌按 U 盘独立签发、撤销和审计，不允许所有设备共用一个设备令牌。
3. Provider Key/New API Key 只保存在服务端或公司内部模型代理，不进入客户端、U 盘、日志、诊断导出或普通配置。
4. 内部版可以让多个设备映射到一个公司内部模型账户，但必须仍为每个设备签发独立内部激活码和设备令牌。
5. 任何 Mock、fixture、localhost、交叉编译或单元测试证据都不能标记为正式 V1 已验收。
6. 隐藏功能不等于删除功能。隐藏功能的底层 shared、Desktop、IPC、Adapter 和测试必须继续保留。

## 3. 执行顺序

```text
A. 内部员工版
  -> Windows/U 盘安装闭环
  -> 内部授权策略
  -> 真实模型对话
  -> 能力模块
  -> 个人微信
  -> 系统外观与内部更新
  -> 5~10 台员工试用

B. 正式 V1
  -> 正式域名、TLS、激活服务和模型代理
  -> 正式 Windows/U 盘验收
  -> 个人微信正式验收
  -> 正式更新 feed、签名、回滚
  -> V1 隐藏表面回归
  -> 发布门禁签字
```

不得在 A 阶段把内部试用包标记为正式发行版；不得在 B 阶段用内部服务证据替代正式服务证据。

## 4. 阶段 A：内部员工可用版

### A-01 发行包和 Windows 安装

目标：员工可从物理 U 盘在 Win10/11 x64 普通用户环境启动。

交付内容：

- 生成 `Bavi-box.exe`、锁定 `runtime.pkg`、`version.json` 和 `.uclaw/data/`。
- runtime 缓存放本机 SSD；配置、会话、记忆、Skill、工作文件和授权材料放 U 盘。
- 双击启动显示状态；Gateway 端口冲突可回退；退出后无孤立产品进程。
- 换盘符后路径仍能正确解析。

验证：

- 在两台 Win10/11 x64 电脑上，以普通用户、无本机 Node.js、Defender 开启运行。
- 从 U 盘启动、退出、重启、换盘符、删除本机缓存后再次启动。
- 检查 U 盘数据仍存在，本机仅有可重建缓存。
- 检查重复启动、异常退出和拔盘后的进程、写锁和日志。

完成门槛：两台电脑均能启动；换盘符和缓存重建通过；无产品孤立进程和敏感数据残留。

### A-02 内部授权与模型代理

目标：不把公司上游 Key 发给员工，员工可完成内部激活并对话。

交付内容：

- 每个内部 U 盘一枚独立内部激活码。
- 每个内部 U 盘独立设备令牌。
- 公司内部模型代理保存唯一上游 Key。
- 内部设备可映射到公司内部 New API 账户或内部额度池。
- 激活失败、撤销、服务不可用和模型不可用有不同状态。

验证：

- 两个 U 盘分别激活，确认激活码不能互相复用。
- 任意撤销一个设备，确认另一个设备不受影响。
- 服务端日志不包含完整激活码、设备令牌、New API Key 或完整 prompt。
- 激活成功后重新执行完整 Launcher gate，再进入工作台。

完成门槛：两个独立设备可使用同一内部额度池；设备可单独撤销；客户端不持有上游 Key。

### A-03 工作与会话

目标：员工可完成真实工作会话。

验证：

- 新建、切换、重命名、删除会话。
- 历史消息分页、刷新和重启后仍存在。
- 发送、流式输出、停止生成、错误终态正常。
- Markdown、代码块、表格、链接安全渲染。
- 附件选择、拖放、发送、失败和重试。
- 工具调用、单次 Exec/Plugin 审批和结果轨迹可读。
- Gateway 重启后草稿和会话状态正确。

完成门槛：至少完成一次真实模型对话；消息不重复；停止生成能结束服务端任务；重启不丢数据。

### A-04 能力模块

目标：员工可以使用已安装 Skill，不要求第一版助手库。

验证：

- 查看本地已安装 Skill。
- 安装一个受控 Skill。
- 启用、禁用、更新和卸载。
- 依赖缺失、安装失败和回滚状态准确。
- 换机后 U 盘 Skill 状态保持。
- Skill 调用结果能回到工作会话。

完成门槛：至少一个 Skill 完成安装、调用、禁用、恢复全流程；不把 Plugin/MCP 技术字段暴露给普通员工。

### A-05 个人微信连接

目标：内部版若保留连接入口，必须是真实可用；不能用 Mock 冒充。

验证：

- 真实腾讯 Plugin、Windows 微信和手机微信扫码。
- 二维码生成、刷新、超时、取消、手机确认。
- 入站消息到 Agent，Agent 回复回原 peer。
- Gateway/Electron 重启、断网恢复、授权失效重扫。
- 退出登录后停止通道并清除凭据。

完成门槛：真实账号完成文本双向收发，并通过重启、断网、退出登录测试。

若 A-05 未完成：内部版必须隐藏连接入口并在发布说明中写明“个人微信未开放”，不得显示假连接状态。

### A-06 系统设置和内部更新

目标：员工可使用外观和受控更新。

验证：

- 系统默认进入发布更新。
- 外观页可正常打开；V1 固定亮色时不得承诺暗色主题。
- 内部 feed 或离线签名包可检查、下载、验签和安装。
- 更新失败能回滚；会话、Skill、授权和 U 盘数据不丢。

完成门槛：至少完成一次内部版本升级和一次失败回滚。

### A-07 内部试用验收

范围：5~10 台公司 Windows 电脑、至少 2 个物理 U 盘、至少 2 名员工。

必须记录：

- 设备环境、版本、U 盘标识摘要。
- 启动、激活、对话、Skill、连接、更新结果。
- 脱敏错误、崩溃、拔盘和恢复结果。
- 不记录激活码、设备令牌、API Key、完整 prompt 或完整聊天内容。

## 5. 阶段 B：正式 V1

### B-01 正式授权服务

完成：

- 正式域名 DNS、TLS、health/ready。
- 正式 PostgreSQL、密钥注入、备份和恢复。
- 激活码库存、首次绑定、同盘幂等、异盘拒绝。
- 许可证签发、撤销、重制、离线宽限。
- New API Key 加密保存和轮换 canary。

正式门槛：真实 Electron + 正式 Windows + 物理 U 盘完成激活闭环；状态不再是 `not-release-ready`。

### B-02 正式模型对话

完成：

- 激活后真实设备令牌访问模型代理。
- 模型代理真实转发到 New API。
- 成功对话、超时、限流、无权限、撤销、余额不足均有正确状态。
- 真实会话写入 U 盘并可换机恢复。

正式门槛：至少一个正式发行 U 盘完成真实模型成功对话，并留存脱敏 HTTP 状态、请求 ID、版本和结果摘要。

### B-03 正式个人微信

完成 `WX-03`–`WX-12`：

- 真实二维码状态机。
- 凭据原子写盘和 renderer 脱敏。
- Plugin/Gateway 权威 connected 状态。
- 入站、出站和 peer 隔离。
- 二启、断线、授权失效和 Gateway 重启恢复。
- 退出登录、拔盘、换机、卸载残留审计。
- 文本、图片、语音、文件、视频、引用消息按实际能力检测并明确降级。

正式门槛：Win10/11 x64、Defender、普通用户、无本机 Node.js、物理 U 盘、普通手机微信全部通过。

### B-04 正式更新

完成：

- 正式 HTTPS feed 和公钥。
- `runtime.pkg` Ed25519 验签、SHA-256 校验、防降级。
- 原子切换、失败恢复、断电回滚。
- 更新后授权、会话、Skill、数据完整。
- 在线和离线更新使用同一安全内核。

正式门槛：正式签名包成功升级一次；篡改、旧版本、错误公钥、安装中断全部拒绝或回滚。

### B-05 V1 可见界面

完成：

- 主导航只显示工作、能力、连接、系统。
- 连接只显示个人微信。
- 系统只显示发布更新、外观并默认进入发布更新。
- 隐藏文件、记忆、自动化、其他渠道、高级系统页、全局搜索和模型状态。
- 桌面 `1440x900`、移动 `390x844` 无空白、重叠、截断和不可用热区。
- 更新《首个版本功能隐藏记录》，追加实施状态、验收日期、提交 SHA 和验收人。

正式门槛：自动化、Playwright 和人工视觉验收全部通过。

### B-06 正式数据和安全

完成：

- U 盘是配置、会话、记忆、Skill、工作文件和授权数据的唯一持久源。
- 本机只保存可重建 runtime 缓存。
- renderer 不可读取 Node、路径、完整 Key 或 Token。
- 日志、错误、导出不包含 Key、Token、Authorization、完整 prompt 或聊天正文。
- 正常退出、崩溃、拔盘、换机不产生产品孤立进程和宿主机业务残留。

正式门槛：安全测试、静态检查、日志抽查、宿主机残留审计和两台 Windows 换机证据完整。

### B-07 正式余额策略

不实现充值和支付页面，但必须：

- 激活前完成正式 New API 账户准备。
- 明确余额、额度、模型权限和限速策略。
- 余额不足不能伪报网络错误。
- 运营可单独禁用账户或设备。

正式门槛：激活成功后模型可用；余额不足时 UI 显示明确业务状态。

## 8. Codex 执行规则

1. 执行前先读取本文和对应权威文档，建立当前状态快照。
2. 先执行 A 阶段，不把 A 阶段结果标记为正式 V1。
3. 每完成一个 A/B 子项，补自动化证据、人工验收记录和脱敏结果。
4. 缺真实 Windows、物理 U 盘、真实账号、正式 feed 或正式服务时，只能标记“待外部环境”，不能标记“已完成”。
5. 修改功能状态时同步更新对应阶段文档、联调矩阵和验收记录。
6. 不删除隐藏功能底层代码，不把 Key、Token、完整 prompt 或聊天正文写入报告。
7. 每个子项完成后运行定向测试，再运行全量门禁：frontend typecheck、unit、integration、E2E、Go test/race/vet、Windows amd64 交叉构建。
8. 最终发布前必须生成两份独立报告：内部员工版试用报告、正式 V1 发布验收报告。
