## 1. 统计规则

第一阶段只使用以下公式报告进度：

```text
第一阶段完成度 = 状态为“已完成”的 Task 数 / 23 个第一阶段 Task
```

- 每个功能编号只归属一个交付 Task。
- Task 内全部功能达到矩阵验收标准并有证据后，Task 才能标记为“已完成”。
- Task 内任一功能仍为“开发中”或“待验收”，整个 Task 不计入完成数。
- “待验收”表示代码和当前自动化已完成，但完整验收仍缺指定 CI、真实 Windows、物理 U 盘或真实发布 artifact 证据。
- “开发中”可以包含已经实现但尚未合入、尚未完成真实环境验收或仍缺少同 Task 其他功能的情况。
- `P1-T23` 是第一阶段最终 Windows 会合验收；未完成时不得宣布第一阶段完成或发布正式版。
- 旧实施计划中的 Task 1–9 只作为代码批次历史，不再作为阶段进度统计单位。

## 5. 状态更新规则

每次实现或验收后，必须同时更新：

1. 本文对应 `P1-Txx` 状态和统计快照。
2. `docs/客户端改造需求.md` 中每个功能的状态和总统计。
3. `docs/第一阶段需求.md` 中对应功能复选框。
4. `docs/验收记录/` 中的测试命令、环境和证据。

禁止只更新 Task，不更新功能；也禁止功能只完成一部分就将所属 Task 标记为完成。
